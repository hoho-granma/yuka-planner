# 학원 후기 API 선행 검증

확인일: 2026-10-09. 현재 개발자센터 검색 API 약관은 검색 데이터를 AI에 입력하는 행위를 금지한다. 따라서 네이버 검색 요약을 저장하고 AI로 주제·감정을 분석하는 구조는 구현하지 않는다. 검색 표시와 별도 이용 권한을 확보한 후기 분석을 분리해야 한다.

## 권한과 사용 조건

| 항목 | 확인 결과 | 구현 판단 |
| --- | --- | --- |
| 기존 검색 API | 2026-07-30까지 신청한 기존 이용자만 2027-06-30까지 개발자센터 서비스 이용 가능 | 기존 신청 여부 확인 필요 |
| 신규 신청 | NAVER API HUB 이용 절차와 약관 적용 | HUB 권한·엔드포인트·조건 별도 확인 필요 |
| 검색 표시 | 출처·원문 링크를 포함하고 검색결과를 독립적으로 가공 없이 표시 | 검색 순서 변경·분석 문구 혼합을 기본 허용으로 보지 않음 |
| AI 분석 | 검색 데이터의 AI 입력·학습·개선·평가·노출 활용 금지 | 요약문도 AI 분석에 보내지 않음 |
| 저장 | 원칙적 저장 금지, 서비스 연속성 목적의 제한적 임시 보관 예외 | 후기 DB 구축 권한으로 해석하지 않음 |
| 로컬 인증 설정 | 환경변수·functions 환경 파일에서 NAVER 이름의 인증 설정 미발견 | 실제 호출 및 앱 권한 미검증. 원격 Secret Manager 존재 여부는 미확인 |

캐시 예외는 기기에서 24시간 또는 새 질의까지 중 짧은 기간, 서버 이력 조회 최대 21일이며 개인화 서버 캐시는 기기와 같은 기간이다. 분석용 영구 저장을 허용하는 조항이 아니다. 링크·최소 관리 정보도 검색 응답에서 추출해 영구 저장할 권한을 자동으로 가정하지 않는다.

근거: [현재 약관 검색 API 특약 2.1~2.4 및 부칙](https://developers.naver.com/products/terms/).

## 문서상 제공 필드와 실제 샘플 검증 상태

| API | 개별 결과 필드 | 제한 |
| --- | --- | --- |
| blog.json | title, link, description, bloggername, bloggerlink, postdate | 문서상 필드이며 실제 응답 검증은 미완료 |
| cafearticle.json | title, link, description, cafename, cafeurl | 게시일 필드 없음. 검색 생성일을 게시일로 표시하지 않음 |
| local.json | title, link, category, description, telephone, address, roadAddress, mapx, mapy | telephone은 값을 반환하지 않음. 리뷰 본문·평점 필드 없음 |

문서의 검색 API 일일 한도는 25,000회이며 신규 HUB 요금·한도로 일반화하지 않는다. 검색 total은 해당 학원의 확인된 후기 수가 아니다. 검색 결과는 광고·모집·다른 지점 글을 포함할 수 있다.

근거: [블로그 문서](https://developers.naver.com/docs/serviceapi/search/blog/blog.md), [공개 카페글 문서](https://developers.naver.com/docs/serviceapi/search/cafearticle/cafearticle.md), [지역 검색 문서](https://developers.naver.com/docs/serviceapi/search/local/local.md).

## 기존 구조와 개선 설계

현재 `js/education-reference-view.js`는 학원 상세의 검색 링크와 수동 조사 의견을 표시한다. `functions/education-directory/index.js`는 로그인·가입 확인 후 교육청 목록을 제공한다. 네이버 검색 연동은 확인되지 않았다. 기존 수동 의견의 이용 권한이 검증되었다고 간주하지 않으며 이번 조사로 기존 의견을 삭제하거나 변경하지 않는다.

검색 화면은 네이버 검색결과임을 표시하는 별도 영역으로 구성하고 원문 링크로 연결한다. 검색 실패, 정상 응답의 빈 결과, 일부 출처 실패, 권한 미설정을 구분한다. 빈 결과는 ‘검색 결과를 확인하지 못함’으로 표시한다. 검색 결과 개수와 학원·지점이 확인된 후기 표본 수는 별개다.

분석은 작성자 동의·계약 등으로 저장과 분석 권한을 확보한 독립 데이터에만 적용한다. 검색 API 결과의 필터링·중복 제거·학원별 재구성이 가공 제한에 해당하는지 제공자 확인 전에는 활성화하지 않는다. 독립 데이터에서는 이름·지점·주소·과목·동명 학원 여부를 검증하고 불확실한 연결을 검토 대기 상태로 둔다.

분석 레코드는 출처 레코드, 허용된 근거 문구, 주제, 감정, 신뢰도, 모델 버전, 분석 시각을 연결한다. 근거가 없는 판단은 판단 불가로 처리하고, 적은 표본에 비율·순위를 부여하지 않는다. 엇갈리는 의견을 함께 표시한다. 사용자 제보는 자동 확정 대신 연결 검토로 이어지며, 학원 상세에서 상담·방문 일정 등록으로 연결한다.

## 구현 재개 조건

1. 기존 개발자센터 신청 또는 신규 HUB 계약 중 사용할 경로와 서버 인증 설정을 확인한다. 인증키는 채팅·브라우저 코드에 노출하지 않는다.
2. 해당 경로의 약관·BI·호출 한도·비용·캐시 조건을 확인한다. AI 분석은 별도 허용 데이터가 확보되어야 한다.
3. 실제 학원·지점·지역·과목으로 블로그와 공개 카페 검색을 소량 호출한다. HTTP 상태, 실제 필드명, 결과 수, 게시일 유무를 검사한다. 원문 페이지는 자동 수집하지 않는다.
4. 동명 학원·다른 지점·중복 URL·빈 응답·403·429·시간 초과 사례를 검증한다. 테스트 데이터 보관도 권한 범위 안에서 처리한다.
5. 검증 이후 검색 표시를 먼저 구현하고, 권한을 확보한 독립 후기의 매칭·분석·표본 표시·연결 수정 기능을 순서대로 추가한다.

## 인증 설정 후 실제 호출 검증

사용자가 Firebase Secret 설정 완료를 알린 후 NAVER API HUB를 실제 호출했다. Client ID의 활성 버전 1을 확인했고 두 인증값을 메모리에서 읽어 요청에 사용했다. 인증값과 응답 본문은 출력·파일 저장·AI 전달하지 않았다.

| 호출 | 검색어 | 상태 | 반환 결과 | 실제 필드 |
| --- | --- | --- | --- | --- |
| /search/v1/blog | 분당 정법수학학원 초등 후기 | HTTP 200 | 3개 | title, link, description, bloggername, bloggerlink, postdate |
| /search/v1/cafearticle | 분당 정법수학학원 초등 후기 | HTTP 200 | 3개 | title, link, description, cafename, cafeurl |

공통 응답은 display, items, lastBuildDate, start, total이다. 검사한 링크는 모두 HTTP 또는 HTTPS이며 블로그 3개에는 postdate가 있고 카페 3개에는 없다. 이는 검색 접근과 응답 구조 검증이다. 해당 지점의 실제 후기 여부·내용·광고 여부·학원 매칭은 검증하지 않았으므로 ‘확인된 후기 3개’로 집계하지 않는다.

현재 HUB 약관도 검색 데이터의 AI 입력을 금지한다. 근거: [2026-09-20 시행 HUB 약관 개정 공지](https://www.ncloud.com/support/notice/all/2243). 기존 개발자센터 제한뿐 아니라 이번에 발급한 HUB 인증에도 관련 제한이 적용된다.

재검증 도구: `python3 tools/verify_naver_search.py`. 블로그·카페 각 1회 호출하며 상태·필드·결과 수만 출력한다. API 본문과 인증값은 저장하지 않는다.

인증과 실제 응답 구조 검증은 완료했다. 검색 표시 기능·독립 후기 분석 기능은 미구현이며 애플리케이션 코드·Firestore 규칙·배포에는 변경이 없다.
