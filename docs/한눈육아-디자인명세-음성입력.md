## 1. 두 갈래(기기 지원 여부로 자동 선택)
| 갈래 | 조건(코드 판정) | 화면 |
|---|---|---|
| ① 마이크 버튼 | 브라우저 음성 인식 API가 있고(`SpeechRecognition` 또는 `webkitSpeechRecognition`), 실제로 시작이 됨 | 붙여넣기 입력칸 옆 마이크 버튼 |
| ② 받아쓰기 안내 | API가 없거나, 시작이 실패함(권한 거부·홈 화면 웹앱 미지원 등) | 마이크 버튼 없이 안내 한 줄 |
- 판정은 버튼을 처음 누를 때 한 번 더 확인한다(API는 있어도 iOS 홈 화면 웹앱에서 시작이 막힐 수 있음). 실패하면 그 기기에서는 ②로 바꾸고 다시 묻지 않는다(기기 저장).
- iOS 홈 화면 웹앱에서 ①이 되는지는 **추가확인 필요**(hn_test 실기기). 확인 전에도 ②가 있으니 기능이 막히지 않는다.

## 2. 화면 요소(2-1 '붙여넣기로 추가' 화면 안)
| 요소(한국어 이름) | 마크업(제안) | 모양(재사용) | 내용·동작 | 갈래 |
|---|---|---|---|---|
| 진입점 | 일정 추가 시트 안 '붙여넣기로 추가'와 나란히(결정 1) | 기존 `.us-chip` | **"말로 추가"** 칩 1개 추가 → 같은 화면을 열고 ①이면 바로 듣기 시작, ②면 안내를 먼저 보여 줌 | ①② |
| 입력칸 | 2-1 `textarea.us-paste` | 그대로 | 받아쓴 글자가 들어옴. **사용자가 고칠 수 있음** | ①② |
| 마이크 버튼 | `button.us-mic`(입력칸 오른쪽 위) | 기존 `.us-chip` 원형(지름 40) + 마이크 SVG 아이콘(하단 탭 아이콘과 같은 선 굵기 1.8) | 누르면 듣기 시작/멈춤 | ① |
| 듣는 중 표시 | `.us-mic[aria-pressed="true"]` + 아래 `.us-note` | 버튼 면 #4a45c8 + 흰 아이콘(확정 인디고, 정보 수정 시트 저장 버튼과 같은 색) | 문구 "듣고 있어요… 말을 마치면 버튼을 다시 눌러 주세요" | ① |
| 예시 문구 | `.us-note` | 기존 | "예) 다음 주 화요일 세 시에 하린 치과 예약" | ①② |
| 받아쓰기 안내 | `.us-note` 한 줄 | 기존 | **"키보드의 마이크(받아쓰기)를 눌러 말한 뒤, 여기에 입력돼요."** | ② |
| 해석하기 | 2-1 버튼(문구만 "해석하기") | 그대로 | 말이 끝나도 자동 해석하지 않음. 인식된 글자를 보여 주고 사용자가 누르면 해석 → 2-1 후보 확인 화면(결정 2) | ①② |
- ②에서는 입력칸에 바로 포커스를 줘서 키보드가 올라오게 한다(받아쓰기 마이크가 키보드에 있음).
- 아이콘만 있는 버튼이 아니게 `aria-label="말로 입력"`.

## 3. 음성에서 더 조심할 것(2-1 9규칙에 더해)
| 상황 | 처리 | 표시 |
|---|---|---|
| "세 시"처럼 오전/오후 없음 | 2-1과 같음: 3:00으로 두고 '확인 필요' | 같음 |
| 숫자가 한글로 받아써짐("시월 십사일") | 숫자로 읽어 해석. 읽지 못하면 빈칸 | '확인 필요' |
| 이름이 비슷하게 받아써짐("하린이"·"하린") | 등록된 아이 이름과 **정확히 같거나 뒤에 조사(이·가·는)만 붙은 경우**만 채움 | 아니면 빈칸 + '확인 필요'(아이 2명 이상일 때) |
| 인식 결과가 비었음 | 후보를 만들지 않음 | "잘 듣지 못했어요. 다시 말하거나 직접 입력해 주세요." |
- 음성 원문(받아쓴 글자)은 2-1과 같이 **저장하지 않는다**. 녹음 파일은 만들지도 보내지도 않는다(브라우저 인식 결과 글자만 사용).
