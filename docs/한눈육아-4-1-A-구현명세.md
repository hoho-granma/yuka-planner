## ② '지금 꼭 할 것' 카드 (최대 2줄)
- **위치**: 홈 본문 맨 위, 임신 배너(있을 때) 아래·**아이 칩 아래**. 그 아래가 이전 홈 첫 영역(가족 카드 또는 n월 챙길 것).
- **데이터 출처**: `Curation.curate(events, state, policy, today).now` 의 앞 2개(정렬은 엔진 그대로: 레벨 L1→L4, 같은 레벨은 기존 동점 규칙). `state`·`events` 는 `curatedHomeHtml()`(app.js 1432~)이 만드는 것과 **같은 값**을 쓴다(함수로 빼서 공용). 'ACT' 단위만 나오므로 해당돼요/아니에요 줄은 없다. 완료·'아니에요' 처리된 항목은 엔진이 이미 제외.
- **'외 N개 ›'**: 카드 제목 줄 오른쪽. N = (`cur.now.length` − 2) + `cur.moreCounts.now`. N=0이면 링크 없음. 누르면 체크리스트 탭(`switchTab("checklist")`). ※ 접힘 머리의 '이번 달 개수'와 달리 **'꼭 할 것'의 나머지 수**라서 D16(개수 요약 보류)과 충돌하지 않는지 hn_pm 확인.
- **줄 모양(한 줄)**: `[분류색 점] 제목(한 줄, 넘치면 …)   오른쪽 날짜글자`. 분류색은 `cat-line`의 `CATEGORY_META[category].color`(기존 분류색 그대로).
- **오른쪽 날짜 글자(색만으로 구분하지 않음)**
| 레벨 | 글자 | 모양 |
|---|---|---|
| L1·L2 | `D-N`(예: D-9) | **와인 #8a1c3d(`--nd-wine`) 800** — D17 규칙 그대로(글자와 색을 같이) |
| L3 | `지금 가능` | #62656b |
| L4 | `M월 D일까지`(`dmd` 규칙: 6개월 넘으면 연도) | #62656b |
| 지난 기록 확인(`review`) 단위 | 제목은 단위 제목 그대로, 오른쪽 비움 | — |
  - 지난 날짜(`daysToEnd<0`)는 날짜를 보이지 않는다(기존 규칙).
- **누르면**: 줄 전체가 버튼. 그 항목의 **상세 시트**(`openDetail`, 홈 슬롯의 '일정 넣기' 행동과 같은 길). 'review' 단위는 체크리스트 탭. 줄 안에 완료·신청·일정 넣기 버튼은 두지 않는다(2줄을 가볍게 유지; 행동은 상세 시트의 단계에서).
  - 클릭 처리는 기존 `CuratedHome.dispatch` 에 `data-hs-act="open"` 한 종류를 더해 처리하는 방식을 제안(앱의 `curatedHomeClick` 은 새 홈이 꺼져 있어도 이전 홈 위에서 동작하도록 연결 필요 — hn_dev 판단).
- **모양(새 색 없음)**: 카드 = 이전 홈 `.home-sec` 모양 재사용(흰 면·1px 선·r16, 제목 `h3` '지금 꼭 할 것'). 링크 '외 N개 ›' = 기존 `.home-viewall`(인디고 #4a45c8). 줄 높이 44px 이상, 구분선 1px `--line`. 새 CSS 블록은 `.home-must` 하나(style.css 또는 home-slots.css), **새 변수·새 hex 없이 `--nd-*`만**.
- **항목이 없을 때**: **카드를 통째로 숨긴다**(빈 문구 없음). 그러면 이전 홈과 화면이 똑같아져 정보가 늘지 않는다. (★, 사용자 질문 Q1 참고)
- **실패·정책 없음**: `curate` 가 던지거나 정책을 못 읽으면 카드만 조용히 생략(이전 홈 그대로, 오류 문구 없음).

## ③ 아이 칩 (아이 2명 이상일 때만)
- **조건**: `homeChildren.length >= 2` 이고 계정 모드(`accountHome`). 1명이면 안 보인다(지금과 같음).
- **위치**: 홈 본문 맨 위(임신 배너 아래, '지금 꼭 할 것' 카드 위). 지금은 `childHead(ctx)` 가 'n월 챙길 것' 섹션 안에 있다 → **칩만 위로 올리고**, 그 섹션 안에는 아이 나이 한 줄(`home-child-line`)만 남긴다(칩이 두 번 나오지 않게).
- **모양**: 이전 홈 `.home-child-chips`·`.home-child-chip` 그대로(가로 스크롤, 36px, 선택=`active`). 동작 `data-home-child` → `switchChild` 그대로. 새 CSS 없음.
- **36+ 홈**: `Over36View.renderHome` 이 이미 맨 위에 칩(`a36-chips`)이 있어 **변경 없음**.
- 아이 전환 시트(`showChildSwitchSheet`)·프로필 시트 전환 경로는 그대로 둔다.

## ④ 적용 범위
| 홈 | 적용 | 꼭 할 것 카드 위치 | 비고 |
|---|---|---|---|
| 36개월 미만 이전 홈(`HNHome.render`) | **적용** | 맨 위(임신 배너·아이 칩 아래), 챙길 것 먼저·가족 먼저 순서와 무관하게 항상 첫 카드 | 칩은 ③ |
| 36개월 이상 홈(`acct36RenderHome`→`Over36View.renderHome`) | **적용** | 아이 칩 → 나이 한 줄(`home-child-line`) → **꼭 할 것** → 가족 카드 → 자동 일정 → 할 일 | `renderHome` 반환 문자열에 `st.mustHtml` 한 칸을 끼우는 방식 제안 |
- 36+ 주의: 홈에 이미 '자동 일정' 줄(`acct36AutoItems(3)`)이 있다. 같은 항목이 두 곳에 나오지 않도록 **꼭 할 것 카드에서 자동 일정 줄에 이미 있는 항목은 건너뛰고 다음 순위로 채운다**(id 가 단위 key 의 `items[0].id` 와 같은지 hn_dev가 확인 — 다르면 건너뛰기 없이 그대로 둬도 됨, 중복은 낮은 우선순위).
- 임신 중 홈: 적용(임신 배너 아래).

## 정책 값(끌 수 있는 한 곳)
- `data/policy/curation.json` 의 `slots` 에 `"homeMust": 2` 한 값을 둔다(제안). **0이면 카드를 그리지 않는다**(= 이전 홈 완전 그대로). 플래그 없이 기본 적용, 문제가 생기면 정책 값만 0으로 바꿔 배포. 엔진 수치(`now`·`soon`·`know`·`expandMax`)는 건드리지 않는다. `normalizePolicy` 가 알 수 없는 키를 지우는지 hn_dev가 확인.

## 테스트 제안(hn_test)
1. 36개월 미만 계정(은찬·구로구·2026-06-20): 맨 위에 꼭 할 것 ≤2줄, 아래 이전 홈 영역이 이전과 DOM 동일.
2. 꼭 할 것 0건: 카드 없음(이전 홈과 동일). 3건 이상: '외 N개 ›' → 체크리스트 탭.
3. L1·L2 줄에 `D-N`이 와인 #8a1c3d·800(computed), 글자 있음.
4. 아이 2명: 칩이 맨 위에 1번만(챙길 것 섹션 안에 중복 없음), 전환 동작. 1명: 칩 없음.
5. 36+ 홈: 꼭 할 것 카드가 가족 카드 위, 자동 일정과 같은 항목 중복 없음.
6. `slots.homeMust = 0` 이면 카드 없음. 새 홈 미리보기 ON/OFF 모두 정상.
