# 지원금 검증 기준 (v1, 2026-09-30 확정)

대상: `data/subsidies/` 아래 모든 지원금 데이터 (전국·시도·시군구·자치구). 서울·경기·부산 등 지역에 관계없이 같은 기준을 쓴다.
적용 결과 서울은 2026-09-30에 반영 완료. 경기·부산은 이 문서 §7 절차대로 적용한다.

## 1. 판정 등급 (2단계만 쓴다)

| status | verified | 앱 노출 |
|---|---|---|
| `확인완료` | `true` | 노출 (`js/schedule.js`가 `status === "확인완료"`만 통과시킴) |
| `확인필요` | `false` | 숨김. 데이터에만 보관, 월간 점검 대상 |

- `일부확인`, `본문확인` 같은 조사 중간 등급은 데이터에 남기지 않는다. 반영 단계에서 위 2단계로 바꾼다. (`일부확인` → `확인필요`, `본문확인` → 아래 §2 통과 시 `확인완료`)
- `종료예정`, `종료`는 등급이 아니라 상태다. 종료·마감 항목은 `pending.json`으로 옮긴다(§5).

## 2. 확인완료 조건 (5개를 모두 만족)

1. **1차 공식 출처 본문을 직접 열람했다.** `officialUrl`이 아래 중 하나이고, 그 페이지를 실제로 열어 확인했다.
   - 중앙·지자체·공공기관 공식 도메인 (`go.kr`, `seoul.kr`, 각 구·시·군 도메인, 구 보건소·육아종합지원센터 등 산하기관 공식 페이지)
   - 법제처·국가법령정보센터의 조례 원문 (`law.go.kr`, `easylaw.go.kr`)
   - **지자체 공식 뉴스·보도자료 게시판** (`news.seoul.go.kr`, `gnews.gg.go.kr`, 각 시·군 뉴스포털). 1차 출처로 인정한다.
   - 정부24·복지로 등 정부 서비스 안내 페이지
2. **대상·금액·신청기간(또는 상시)·시행 지역이 원문에 있다.** 하나라도 원문에 없으면 `확인필요`. 앱에 나가는 문구는 원문에 있는 것만 쓴다.
3. **종료·변경 공지가 없음을 확인했다.** 열람일 기준 종료, 예산 소진, 접수 마감 공지가 없어야 한다.
4. **`lastVerified`에 열람일을 적었다.**
5. **출처끼리 수치가 다르면 채택 근거를 `notes`에 적었다.** 공식 페이지끼리 다를 때는 게시일이 최신인 쪽을 채택하고 그 사실을 남긴다(예: SEOUL-002). 근거를 못 남기면 `확인필요`.

## 3. 확인필요로 내리는 경우

아래에 해당하면 다른 조건이 맞아도 `확인필요`다. 위 §2를 다 만족하는 공식 출처가 함께 있으면 예외.

- 근거가 **언론 보도만** 있다 (같은 내용이 여러 언론에 재게재된 경우도 동일. 구청·시청 홈페이지 원문을 못 열었으면 해당).
- 근거가 **2차 자료만** 있다: 모두의혜택(servedream.com), 육아생활(lifewithbaby.co.kr), 혜택 리포트 카드, 민간 블로그·요약 사이트.
- 근거가 **목록 소개 문구뿐**이다. 상세 페이지를 못 열었다.
- 공식 원문에 **금액·기한·대상 중 하나가 없다.**
- **공식 페이지끼리 수치가 달라** 채택 근거를 못 댄다.
- 조사 중간 등급이 `일부확인`이었다.
- 열람 기록에 "재확인 전", "원문 미열람" 같은 표기가 남아 있다.

보조 근거로 언론·2차 자료를 `sourceName`에 함께 적는 것은 괜찮다. 다만 `officialUrl`과 확인 사실은 1차 출처여야 한다.

## 4. 앱 노출 조건

`status === "확인완료"` **그리고** 아래를 모두 만족.

- 서비스 범위: 임신 ~ 36개월 (`minAgeMonths`/`maxAgeMonths`가 범위 안에 걸침)
- 부모가 신청·수령하는 제도 (시설 이용처 안내, 난임·임신 준비 등 임신 전 제도는 제외)
- 임신 중에만 신청하는 제도는 `prenatalOnly: true` (코드가 읽는다: `js/schedule.js`)

> 경기 데이터의 `appVisible`은 **코드가 읽지 않는다.** 노출을 막으려면 `appVisible`이 아니라 나이 범위·`prenatalOnly`·`pending.json` 이동으로 처리한다. 경기 적용 시 `appVisible: false` 항목은 범위 밖이면 `pending.json`으로 옮기는 걸 권장한다.

## 5. 파일 배치

| 파일 | 넣는 것 |
|---|---|
| `{시도}/city.json`, `{시도}/districts/{구}.json`, `{시도}/{시군}/subsidies.json` | 확인완료 + 확인필요 (앱은 확인필요를 숨김) |
| `{시도}/pending.json` (앱이 읽지 않음) | 범위 밖(임신 전·초등 이상), 전국과 중복, 종료·마감 항목. `excludeReason`을 적는다 |

## 6. 강등·승격 시 기록 방식

- 강등: `status: "확인필요"`, `verified: false`로 바꾸고 `notes` 맨 앞에 사유를 붙인다.
  `[YYYY-MM-DD 검증기준 적용] 언론·2차 자료만 근거라 확인필요로 강등. 월간 점검에서 공식 페이지(구청·조례·정부24) 열람 후 승격.`
- 승격: §2 다섯 조건을 확인하고 `officialUrl`을 공식 URL로 교체, `sourceName`·`lastVerified` 갱신, 강등 사유 문구는 지운다.
- `lastVerified`는 마지막으로 **열람한** 날짜다. 강등해도 바꾸지 않는다.

## 7. 새 지역에 적용하는 절차 (경기·부산 등)

1. 해당 지역 `city.json`, `districts/*.json`(또는 `{시군}/subsidies.json`)에서 `status === "확인완료"` 항목을 전부 뽑는다.
2. 각 항목을 §2로 점검한다. 특히 아래 세 가지를 먼저 찾는다.
   - `sourceName`이 언론·2차 자료뿐인 항목
   - `notes`·`auditNotes`에 "원문 미열람/미확인/재확인 전/2차 자료"가 있는 항목
   - 조사 원본(`_*-raw.json` 등)에 `일부확인`이었는데 `확인완료`로 올라간 항목
3. 걸린 항목은 §6 방식으로 강등한다. 금액·기한을 못 채운 항목도 마찬가지.
4. 범위 밖·전국 중복·종료 항목은 `pending.json`으로 옮기고 `excludeReason`을 적는다.
5. 파일 저장은 기존 서식(`indent=2`, `ensure_ascii=False`)을 유지해 diff가 줄 단위로만 나오게 한다.
6. `node test/todo-engine.test.js`, `node test/hn-logic.test.js`, `node test/sync-v2.logic.test.js`를 돌린다.
7. `www/data/`는 iOS 패키징용 복사본이라 `data/`와 자동 동기화되지 않는다. 데이터를 바꿨으면 패키징 전에 `data/` 내용을 `www/data/`에 다시 복사한다.

## 8. 월간 점검

- 매월 1회 지원제도 갱신 요청 시 **`확인필요` 항목부터** 본다.
- 순서는 항상 **공식 페이지 먼저**: 구청·시청·도청 사업 페이지 → 조례 원문 → 정부24·복지로 → 지자체 공식 뉴스·보도자료. 여기서 못 찾은 것만 언론·2차 자료를 보조로 본다.
- 열람 결과가 §2를 만족하면 승격, 아니면 사유만 `notes`에 갱신하고 `확인필요`로 둔다.
- 신규·종료 여부도 이때 함께 본다. 종료·마감이면 `pending.json`으로 이동.
- 확인완료 항목도 `lastVerified`가 오래된 것부터 재열람한다.
