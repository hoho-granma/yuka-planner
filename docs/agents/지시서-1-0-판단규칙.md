## 0. 목표 (사용자 지시 원문 요지)
- 1-0의 목표는 **우선순위 숫자를 만드는 것이 아니라**, 한눈육아가 나이·지역·시기·조건으로 **부모가 판단할 일을 대신 선별하는 큐레이터 역할이 실제로 되는지 검증**하는 것이다.
- 슬롯 3/2/1, 기준 30/45/60/7일은 **정답으로 고정하지 않는다.** 고정 아이 6명 결과를 보고 "부모가 먼저 봐야 할 항목이 제대로 선별되는가"로 판단하고, 어색하면 숫자·규칙을 조정한다.
- 순서: 단계 0 → v1.12.98 통합 검증 → **1-0**. 0~36개월 회귀 검증 필수. 엔진 재작성 없이 현재 자동화 데이터 위에 레이어만 얹는다.

## 2. hn_data 지시 (①·⑤ 값)
- 파일 구역: `data/`만. js/css/test 금지. `data/todos/vaccination.json`·`_meta.json` 금지(VX-RSV 미커밋).
- `data/policy/curation.json`(신설):
  - `actionType`: 접두사 기본값 + id 예외(06 §5-1). 판단용은 **ACT / CHECK / KNOW 3개**. 하위(BOOK·APPLY·SCHOOL·OBSERVE·MILESTONE·CAUTION·TRY·INFO)는 참고 열로만.
  - 예외 반영: NAT-009~013·PREG-008 → CHECK(D12), VX-RSV·SC-03 → CHECK, SB-06~09 → CHECK(D13).
  - `urgentLongWindowIds`: 창이 길어도 미루면 손해인 항목 **명시 목록**(SB-01·02·04, PG-01·02, HC-03~09). 06 L4의 "priority=1 & MUST" 조항 대신 사용(priority 의미가 섞여 있어 추측 규칙이 됨).
  - `aliases`: 같은 제도 4쌍(SB-06↔NAT-031, SB-07↔NAT-007, SB-08↔NAT-020, SB-09↔NAT-018) — 삭제·id 변경 없이 1건만 보이게 하는 표.
  - `thresholds`: `deadlineSoonDays 30`, `upcomingDays 45`(**근거 없는 신규값 — 조정 1순위**), `shortWindowDays 60`, `reappearDays 7`.
  - `slots`: `now 3`, `soon 2`, `know 1`.
  - 각 값에 `_근거` 한 줄(기존 코드 값 재사용 / 제안값).
- 새 사실(날짜·금액·자격)을 만들지 않는다. 매핑에 확신 없는 id는 `_추가확인` 목록에.
- 완료 보고: 파일 md5, 매핑 건수(ACT/CHECK/KNOW), `_추가확인` 목록 → hn_main(사본 hn_pm).

## 3. hn_dev 지시 (②·③·⑤ 규칙·⑥)
- 파일 구역: `js/`·`test/`·스크립트. `data/` 금지(정책 값 변경은 hn_data에 요청). 화면 렌더 코드(home.js·over36-view.js·app.js 렌더부) 변경 금지.
- `curate(events, state, policy, today) → { now[], soon[], know[], moreCounts, reasons }` 순수 함수.
  - 입력: 기존 `visibleSchedule(true)` 결과. 기존 엔진 status·`todayItems` 정렬·`subsidyStatus`/`subsidyDeadline`/`isUrgent`·소급 판정·VX 묶음 키를 **재사용**. todo-engine.js·schedule.js 판단 로직은 고치지 않는다.
  - 단계: 게이트(G1~G4) → 묶기(VX 같은 창, TO_BORN 3개, SC-01·02, 별칭 4쌍) → 유형(정책 actionType) → 시급성(L1~L7) → 슬롯 → 이유 문장 키.
  - SB-06~09: eligibility UNKNOWN을 숨기지 않고 CHECK 후보로 — **curate 안에서만**. 기존 화면 경로(`schedule.js:152`)는 1-0에서 바꾸지 않는다.
  - 넘침: 아래 슬롯으로 내리지 않고 `moreCounts`. 빔: 채우지 않음.
  - v1에서 뺄 것: 06 §4-2-3 "같은 유형 3칸이면 교체" 규칙, missableOverride·bundleKey(원스톱)·conditionKey·applyChannel·stageConcerns·eligibilityAnswers·seenAt 저장(별도 단계).

## 4. hn_pm 검토 기준 (④) — 6명 각각에 답한다
1. 부모가 오늘 앱을 열었을 때 **가장 먼저 봐야 할 것이 '지금 꼭'에 있는가**(놓치면 손해·마감).
2. '지금 꼭'에 **해당 안 될 수 있는 것**(조건형·고용 조건)이 올라오지 않았는가.
3. 알아둘 것(관찰·주의·생활)이 행동 칸에 **새어 들어오지 않았는가**.
4. 비어야 할 때 비었는가(초등 학기 중 등) — 억지로 채우지 않았는가.
5. 이유 문장만 보고 "왜 지금"이 이해되는가.
6. 시점(10월→11월→1월)을 바꿨을 때 선별이 자연스럽게 이동하는가.
7. 6기준(①지금 필요 ②실제 고민 ③정보→행동→일정 ④가족 ⑤다음 고민 ⑥검색·판단·입력·기억·전달·우선순위 수고 감소).
- 어색한 결과는 **값 조정 → 예외 id → 규칙 변경** 순서로 고친다(가장 작은 변경부터).
