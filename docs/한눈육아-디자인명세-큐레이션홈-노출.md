# 디자인 명세 — 1-1b 큐레이션 홈 사용자 노출(스위치·안내)

- 작성: hn_design, 2026-10-05 / 구현: hn_dev / 게이트: hn_pm / 화면 시안 없음
- 기준: docs/한눈육아-로드맵.md '큐레이션 홈 노출 절차'(사용자 미리보기 → ① 설정의 '새 홈 미리보기'(기기 저장, 기본 OFF) → ② 기본 ON + '이전 홈으로 보기' 유지 1~2주 → ③ 스위치 제거), js/feature-flags.js(`curation` 플래그, 개발용 `hannun_feature_curation`)
- **새 색·새 화면 없음.** 기존 `.us-tchip`(스위치 칩) 또는 프로필 시트의 기존 줄 모양을 재사용한다. 단계 전환(①→②→③)은 사용자 확인 원문으로만 한다(hn_pm 절차 5).
- 지금 앱에는 별도 '설정' 화면이 없다. 설정에 해당하는 곳은 **프로필 시트**(홈 맨 위 프로필 카드를 누르면 뜨는 바텀시트: 가족·계정·거주 지역·구성원 관리·우리 아이·기록 보기)다.

## 0. 저장·적용 방식(공통)
| 항목 | 규칙 |
|---|---|
| 저장 | 기기 저장 `localStorage`(서버·Firestore 변경 없음). 키는 hn_dev 확정(개발용 `hannun_feature_curation`과 구분되는 사용자용 키, 예: `hannun_home_v2`) |
| 의미 | 단계 ①: 키가 없으면 **이전 홈**(OFF), "켜기"를 누르면 새 홈. 단계 ②: 키가 없으면 **새 홈**(ON), "이전 홈으로 보기"를 누르면 이전 홈 |
| 우선순위 | 사용자 키 > 개발용 플래그 > 기본값(단계) |
| 적용 시점 | **누르는 즉시 홈이 바뀐다**(§3). 새로고침·재시작 불필요 |
| 폴백 | 설정 파일을 못 읽거나 새 홈이 실패하면 키와 상관없이 이전 홈이 그려진다(스위치는 켜진 채로 두고, 안내 줄에 한 번 "새 홈을 불러오지 못해 이전 홈을 보여 드려요" — 오류 코드·불안한 말 없음) |

## 1. 단계 ① '새 홈 미리보기' 스위치(기본 OFF)
### 1-1. 위치 후보(사용자 결정)
| 후보 | 위치 | 장점 | 단점 |
|---|---|---|---|
| ★ A | **프로필 시트 안**, '구성원 관리' 줄 아래·'우리 아이' 위의 새 줄(제목 "홈 화면") | 앱 안의 유일한 설정 자리. 기존 줄 모양 재사용. 홈을 어지럽히지 않음 | 프로필 시트를 열어야 발견됨 |
| B | 홈 맨 아래 작은 한 줄 "새 홈 미리보기 켜기" | 눈에 잘 띔(미리보기 참여자를 늘리기 쉬움) | 홈에 영구 요소가 생김. ①에서만 필요하고 ③에서 지워야 함 |
| C | 홈 머리의 버전 칩(v1.12.xxx)을 누르면 뜨는 작은 시트 | 개발자 느낌, 일반 사용자가 못 봄(미리보기를 소수에게만) | 발견이 어려워 사용자 승인 전 테스트용에 가까움 |
- ★ 권장: **A**. 사용자 미리보기(절차 2)는 고정 테스트 계정에서 하니 C도 가능하나, 단계 ①(공개)에는 A가 맞다.

### 1-2. 문구 후보(사용자 결정)
| 후보 | 줄 제목 | 설명(한 줄) | 스위치 글자 |
|---|---|---|---|
| ★ 1 | 새 홈 미리보기 | 지금 꼭 할 것부터 먼저 보여 드려요 | "켜기 / 끄기" |
| 2 | 새로운 홈 화면 | 우리 아이에게 지금 필요한 것부터 모아 보여 드려요 | "사용 중 / 사용 안 함" |
| 3 | 홈 화면 바꿔 보기 | 새 홈과 이전 홈을 오가며 써 볼 수 있어요 | "새 홈 / 이전 홈" |
- ★ 권장: **후보 1**. 로드맵 용어('새 홈 미리보기')와 같고, 설명이 사실(홈이 어떻게 바뀌는지)만 말한다. 홈 이름이 '큐레이션'이라는 내부 용어는 쓰지 않는다.

### 1-3. 줄 모양(프로필 시트 기존 줄 재사용)
| 요소 | 마크업(제안) | 모양 |
|---|---|---|
| 줄 | `.hs-pref`(프로필 시트 '구성원 관리' 줄과 같은 카드: #fff 면, 1px `--line`, r12, 안쪽 12px 14px) | 기존 |
| 제목 | `.hs-pref b` | 12~13px 800 #161618 |
| 설명 | `.hs-pref small` | 11px #62656b, 제목 아래 |
| 스위치 | 기존 `.us-tchip[role="switch"][aria-checked]` | 기존 모양(꺼짐: 흰 칩, 켜짐: 차콜 `--text` 면). 시트가 확정 인디고 범위면(4-2) 켜짐 = 인디고 — 새 색 아님 |
| 접근성 | `aria-label="새 홈 미리보기"` | — |

### 1-4. 켜짐 안내(켠 직후 홈 맨 위에 1회)
| 요소 | 내용 | 모양 |
|---|---|---|
| 안내 띠 `.hs-notice` | **"새 홈을 보고 계세요. 지금 꼭 할 것부터 보여 드려요."** + 오른쪽 작은 링크 **"이전 홈으로"**(§3) + ✕ | 기존 `.us-note`/`.fine-print` 글자(12px 회색), #fff 면 + 1px `--line` + r10(새 색 없음). 사용자가 ✕ 하면 그 기기에서 다시 안 뜸(기기 저장) |
| 표시 시점 | 스위치를 켠 직후 한 번만. 이후 홈에서는 나오지 않음 | — |
- 안내 문구에는 비교·평가("더 좋아졌어요")나 불안("놓치지 않게")을 쓰지 않는다.

## 2. 단계 ② 기본 ON + '이전 홈으로 보기'
### 2-1. 위치 후보(사용자 결정)
| 후보 | 위치 | 장점 | 단점 |
|---|---|---|---|
| ★ A | **홈 맨 아래 작은 링크 한 줄** "이전 홈으로 보기"(탐색 줄·36+ 메모장 아래, 회색 12px, 가운데 정렬) | 1~2주 동안 되돌릴 길이 홈 안에서 보임 | 홈에 임시 요소(③에서 제거) |
| B | 프로필 시트의 같은 '홈 화면' 줄(스위치 문구만 "이전 홈으로 보기") | 홈이 깨끗함 | 되돌리기를 찾기 어렵다는 불만 가능 |
| C | A + B 둘 다 | 가장 안전 | 같은 기능이 두 곳 |
- ★ 권장: **C 중 A를 기본, B도 유지**(②는 임시 단계라 중복 허용). 단계 ① 스위치(1-1 A)가 ②에서는 같은 줄에서 "새 홈 사용 중 / 이전 홈으로 보기"로 바뀐다.

### 2-2. 문구
| 위치 | 문구 |
|---|---|
| 홈 맨 아래 링크 | **이전 홈으로 보기** |
| 프로필 시트 줄(②) | 제목 "홈 화면" · 설명 "새 홈을 쓰고 있어요" · 스위치 "새 홈 사용 / 이전 홈" |
| 이전 홈에서의 되돌림 링크 | **새 홈으로 보기**(이전 홈 맨 아래, 같은 모양) |

### 2-3. 최초 안내(②로 바뀐 날 홈 맨 위 1회)
- "홈이 새로워졌어요. 지금 꼭 할 것부터 보여 드려요. 이전 홈이 편하면 맨 아래에서 바꿀 수 있어요." + ✕(기기 저장). 한 번 닫으면 다시 안 뜸.

## 3. 켜고 끄는 즉시 전환·되돌리기
| 항목 | 규칙 |
|---|---|
| 전환 방식 | 키 저장 → `renderHome()` 다시 호출(새로고침 아님). 탭은 그대로 홈, **스크롤은 맨 위** |
| 소요 | 즉시. 로딩 표시 없음(이미 읽은 데이터 사용) |
| 한 번 더 확인 | 묻지 않는다(되돌리기가 항상 한 번 누름) |
| 되돌리기 | 같은 스위치·링크를 다시 누르면 즉시 원복. 안내 띠(1-4)·최초 안내에도 "이전 홈으로" 링크가 있음 |
| 데이터 영향 | **없음**. 완료·일정·답(해당돼요/아니에요)은 두 홈이 같은 저장소를 읽는다. 스위치는 보이는 방식만 바꿈 |
| 계정 간 | 기기 저장이라 다른 기기·가족 구성원에게 전파되지 않음 |

## 4. 하지 않는 것
- 새 설정 화면 만들기, 홈 위 팝업·배너로 반복해서 권유하기, "베타"·"실험" 같은 불안한 말.
- 서버·Firestore에 스위치 값 쓰기, 가족 구성원에게 보이는 표시.
- 이전 홈 코드 삭제(③ 전까지 폴백 유지).

## 5. 앱과의 차이(모두 '추가')
| 지금 | 바뀐 뒤 |
|---|---|
| 홈은 하나(기존 홈). 큐레이션 홈은 개발용 플래그로만 켬 | ①: 프로필 시트에 '새 홈 미리보기' 줄 추가(기본 OFF). ②: 기본 ON + 홈 맨 아래 '이전 홈으로 보기'. ③: 스위치 제거 |

## 6. 결정 필요(사용자)
1. ①의 스위치 위치: A 프로필 시트(★) / B 홈 맨 아래 / C 버전 칩 시트.
2. ①의 문구: 후보 1 '새 홈 미리보기'(★) / 2 '새로운 홈 화면' / 3 '홈 화면 바꿔 보기'.
3. ②의 '이전 홈으로 보기': 홈 맨 아래 링크 + 프로필 시트 줄 둘 다(★) / 둘 중 하나.
- 단계 전환 시점(① → ② → ③)은 사용자 확인 원문으로만(hn_pm 절차 5).
