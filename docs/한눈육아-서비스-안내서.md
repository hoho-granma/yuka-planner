# 한눈육아 서비스 안내서 — 계획·기능·만든 이유·동작·사용법

> 작성 2026-10-05 (hn_main) · 기준: 최종 디자인 묶음 배포 직후(v1.12.116 안팎) · 근거 문서: 서비스방향설계서, 메뉴별UX지침, 로드맵, 결정목록(D1~D50), 기능목록(v1.12.63 기준 + 이후 변경 반영)
> 이 문서는 **한 번에 읽는 안내서**다. 상세 근거는 각 절 끝의 문서 링크를 본다. 사실이 문서와 코드에서 다르면 코드·결정목록이 맞다.

---

## 1. 한눈육아는 무엇인가

**아이의 성장단계·월령/학년·사는 지역에 맞춰, 부모가 지금 고민할 것을 먼저 찾아주고, 정보에서 행동·일정·가족 공유까지 이어주는 가족 육아 서비스.** (웹앱/PWA, 홈 화면에 설치해 쓴다. https://hoho-granma.github.io/yuka-planner/)

핵심 한 문장: **"우리 아이에게 지금 필요한 것을 먼저 찾아주고, 놓치지 않게 연결해주는 것."**

육아정보 앱, 체크리스트, 가족 캘린더, 지원금 앱, 교육 검색 앱 중 하나가 아니라 이 모두를 아이 한 명의 상황에 맞춰 **연결**하는 것이 차별점이다. "육아를 더 열심히 관리하는 앱"이 아니라 **"육아에서 놓치는 것을 줄여주는 앱"**이다.

## 2. 왜 만들었나 (해결하려는 문제)

- 정보가 부족한 게 아니라 **너무 많고 흩어져 있다.** 접종·검진 시기, 지원금 신청 기간, 어린이집·유치원 신청, 초등 준비까지 부모가 직접 검색하고, 판단하고, 기억하고, 가족에게 전달해야 한다.
- 부모의 실제 질문: 지금 뭘 챙기지 / 곧 뭐가 달라지지 / 우리 지역은 / 받을 수 있는 지원은 / 어디 가지 / 다른 집은 어떻게 하지 / 일정은 어떻게 공유하지.
- 그래서 **부모가 직접 검색·판단·입력·기억해야 하는 일을 줄이고**, 한눈육아가 대신 찾아 정리하게 한다. 새 기능이 좋은지는 "기능이 늘었나"가 아니라 아래 5가지로 판단한다.
  1. 부모가 검색해야 하는 횟수가 줄었는가
  2. 판단 부담이 줄었는가
  3. 직접 입력하는 양이 줄었는가
  4. 기억해야 하는 양이 줄었는가
  5. 가족에게 전달해야 하는 일이 줄었는가

## 3. 성장단계별로 앱이 하는 일

| 단계 | 부모의 고민 | 한눈육아가 먼저 보여주는 것 |
|---|---|---|
| 임신 | 이번 주에 무엇을 검사/준비하지 | 주차별 검사·준비·출산 준비 |
| 0~12개월 | 지금 아기에게 필요한 것 | 예방접종·검진·성장·수면·이유식·지원 |
| 12~36개월 | 이 시기에 뭐가 달라지지 | 발달·생활·건강·어린이집·지원 |
| 3~5세 | 교육은 어떻게 | 기관·교육·건강·활동·지역 정보(유치원 입학 신청 등) |
| 6~7세 | 초등 가기 전에 뭘 준비 | 취학·학교 준비·교육·지역 정보 |
| 초등 | 우리 아이는 어느 정도, 다른 집은 | 학년별 학교생활·학교 검진·늘봄·교육 |

단계는 메뉴로 따로 나뉘지 않고 **내부 로직**이다. 같은 앱이라도 아이가 다르면 홈이 달라진다. 36개월 이상이 되면 앱 모양(테마·하단 탭)이 자동으로 바뀐다(§6).

## 4. 시작하기 (온보딩)

1. 앱을 열면 **첫 화면**: 한눈육아 로고와 메인 카피 "육아하며 시기마다 필요한 것, 한눈에" — 접종·검진·지원금부터 학교 준비까지.
2. **로그인**(기본) 또는 **회원가입**을 누르면 화면 가운데 카드로 폼이 열린다. 폼이 카피를 가리거나 겹치지 않는다. 로그인↔회원가입은 폼 아래 링크로 전환한다.
3. **회원가입 3단계**: ① 이메일·비밀번호·표시 이름 → ② 현재 출생한 아이가 있는지·가입하는 사람의 역할(엄마/아빠 등)·가족코드(초대받았다면) → ③ 아이 정보.
4. **아이 정보 입력**: 이름(별명), 생년월일(또는 출산 예정일), 몇째, 시/도·시/군/구. (동 정보는 다음 단계에서 목록 선택으로 추가 예정)
5. 입력하면 그 아이의 일정과 지금 필요한 것이 만들어진다. 가입 없이 둘러보기·가족코드로 함께하기도 첫 화면에서 가능하다.

## 5. 화면(메뉴)별 기능과 사용법

하단 탭은 아이 나이에 따라 구성이 다르다.
- **36개월 미만**: 홈 · 캘린더 · 체크리스트 · 혜택 · 어디갈까
- **36개월 이상**: 홈 · 캘린더 · 할 일 · 교육 트렌드 · 어디갈까 (혜택·기록 탭은 숨김. 혜택은 홈 위쪽이 대신 보여준다)

### 5-1. 홈 — "그래서 지금 우리 아이에게 중요한 게 뭐지?"
- **맨 위**: 아이 이름 · 나이(만 나이/세는 나이 규칙) · 지역, 아이가 2명 이상이면 **아이 칩**으로 바로 전환.
- **꼭 할 것 2줄**: 지금 놓치면 손해인 것(마감 임박 접종·신청 등)을 한눈에. 없는 날은 카드가 숨는다.
- **이번 달 챙길 것 / 신청 가능한 혜택 / 우리 가족 일정(오늘·이번 주) / 다음 단계 안내**.
- **다음 단계 안내**: 30개월이면 "36개월 이후 달라지는 것", 5세면 초등 준비 등 앞으로 몇 달 안에 고민할 것을 미리 알려준다.
- 사용법: 카드를 누르면 상세 → 신청 링크/예약 일정 만들기/완료로 이어진다.

### 5-2. 캘린더 — "우리 가족에게 앞으로 무슨 일이 있지?"
- **월 보기**(주 보기는 현재 숨김). 날짜를 누르면 아래에 그날의 일정 목록이 나온다.
- **한눈이 만든 자동 일정(AUTO)**: 접종·검진·지원 신청 마감·취학 등 필수·시기성 있는 것만. **가족이 등록한 일정(USER)**: 병원·학원·학교·행사·가족 약속. 두 종류를 한 달력에서 본다.
- **칩 필터**: 전체/구성원/아이 칩을 복수 선택. 아이만 선택하면 "직접 등록한 일정만 보기", "카테고리별 색깔 다르게 하기" 스위치가 나온다.
- **색 규칙**: 일정 점·막대·카드의 색은 **그 일정이 누구에 관한 것인지**(대상 구성원 = 아빠·엄마·아이·가족)의 대표 색이다. 내가 아이 일정을 등록해도 아이 색으로 나온다. 한눈이 만든 자동 일정은 기본이 아이 색, 스위치를 켜면 종류별 색(접종·검진·발달·생활·안전·혜택).
- **선택한 날짜**는 사방 같은 두께의 얇은 테두리, **오늘**은 숫자 굵게+작은 점.
- **일정 추가(+)** — 아래 §5-7에서 설명.

### 5-3. 체크리스트 / 할 일
- **36개월 미만 '체크리스트'**: 월령별 그룹(현재·다음 월령 펼침, 지난 월령 접힘), 완료 체크, 해당 없음 표시, 항목 상세(대상·내용·주의 신호·공식 근거), 신청/예약/예방접종도우미 버튼.
- **36개월 이상 '할 일'**: 시기성 자동 항목(검진·접종·학교·유치원 신청 등)과 **직접 쓰는 할 일 메모**. 메모는 입력 줄의 **[추가] 버튼**(또는 키보드 완료)으로 저장되고 줄 끝 ⋯ 메뉴로 삭제한다. 저장에 실패하면 "저장하지 못했어요"가 뜬다.

### 5-4. 혜택(36개월 미만) — "받을 수 있는 게 뭐지?"
- 지역+아이 나이+조건으로 가능한 지원금·제도를 **신청 가능 / 신청 예정 / 신청 완료**로 정리, 마감 있는 것 먼저.
- 항목마다 대상·금액·기간·공식 페이지, 신청하러 가기, 일정에 넣기.
- 데이터는 서울·경기 우선, 그 외 지역은 "확인필요"로 표시한다(근거는 `docs/지원금-검증기준.md`).

### 5-5. 교육 트렌드(36개월 이상) — 3~5세 이후 교육 고민
- **3~5세**: 올해 정할 것(유치원·어린이집 전환), 받을 수 있는 지원, 기관 찾기 공식 링크(유치원알리미·아이사랑·처음학교로), 만 5세는 초등 준비 한 줄.
- **초등 이상**: 학년·지역 기준 교육 정보 틀. 지역 또래 통계는 표본이 충분할 때만 보여주고(10명 미만 가림, 억지 통계 금지) 지금은 공개 자료 중심이다.

### 5-6. 어디갈까 — "우리 아이 데리고 지금 어디 가지?"
- 기본값: **우리 지역 + 우리 아이 나이**. 임신 중에는 숨는다.
- 분류 칩(공원·키즈카페·체험·교육·도서관·박물관·실내 놀이) + 실내/무료/예약 없이 필터, 거리 칩과 정렬.
- 장소 카드·상세(주소, 공식 홈페이지, 지도, 길찾기, 이동 시간, 권장 나이는 시설 유형 기준 표기) → **[일정 등록하기]**로 바로 캘린더에 저장.

### 5-7. 일정 추가 — 입력을 줄이는 4가지 방법
일정 추가(+)에서 아래 중 하나를 고른다. 어떤 방법이든 **해석 → 일정 후보 → 사용자 확인 → 등록** 순서이고, 한눈육아가 날짜를 임의로 확정하지 않는다(확인 필수).

| 방법 | 어떻게 쓰나 | 동작 |
|---|---|---|
| **사진 찍기** | 가정통신문·병원 안내문 등을 촬영 | 기기 안에서 글자를 읽고(서버 전송 없음, 사진은 읽은 뒤 바로 폐기) 규칙 파서로 일정 후보를 만든다. 못 읽으면 직접 입력·붙여넣기로 안내. 첫 사용 때만 글자 인식 데이터(약 6MB)를 받는다 |
| **사진 불러오기** | 갤러리의 사진 선택 | 위와 같음 |
| **메시지 붙여넣기** | 문자·메신저 글을 붙여넣기 | "다음주 화요일 소아과 3시" 같은 문장에서 날짜·시간·제목 후보를 뽑고 "확인 필요" 표시 |
| **직접 입력** | 제목·분류·날짜·시간/종일·여러 날·장소·메모 | 빠른 입력 칩(병원 예약·예방접종·치과 등)·반복(매주·2주마다)·'누구 일정' 칩 |

- **'누구 일정' 칩**: 이 일정이 누구에 관한 것인지 고른다(기본 = 지금 보는 아이). 색과 필터가 이 값을 따른다.
- AI 보강(규칙으로 못 푼 사진을 AI로 해석)은 자리만 있고 아직 호출하지 않는다(서버·요금 결정 후).

### 5-8. 프로필·가족
- **프로필 시트**: 아이 정보 수정, 사진, 아이 전환(2명 이상), 내 계정(이름·역할·가족코드), 가족 추가(초대), 로그아웃, 기록 보기.
- **가족 구성원**: 아빠·엄마·아이·할머니·할아버지·이모님/돌봄·기타 최대 10칸. 구성원마다 **대표 색**이 있다. 색 순서는 역할 기준으로 고정되어 있다(아빠 1번, 엄마 2번, 아이 3~5번, 가족 6번, 그 외 7~10번). 같은 가족이면 모두 같은 색으로 본다.
- **가족 캘린더**: 가입하면 가족(가구)과 8자리 가족코드가 만들어지고, 초대받은 사람이 코드로 합류하면 같은 일정을 실시간으로 함께 본다. 오프라인에서 저장한 것은 연결되면 자동 반영.

### 5-9. 기록
- 36개월 미만은 하단 탭 '기록', 가족 캘린더 모드에서는 프로필의 [기록 보기]. 완료한 할 일에서 자동 기록이 생기고 직접 기록(제목·날짜·메모·사진)도 쓴다.

## 6. 디자인·테마 (화면이 아이에 맞춰 바뀐다)

- **테마**: 보는 아이가 **36개월 미만이면 웜 브라운**, **36개월 이상이면 딥 포레스트**로 앱 색이 자동으로 바뀐다. 아이 칩으로 전환해도 따라 바뀐다.
- **종류 라벨**(접종·검진·발달·생활·안전·혜택)은 흰 바탕에 색 테두리·점. 안전은 핫핑크라서 마감 임박 와인·위험 빨강·완료 청록과 헷갈리지 않는다.
- 칩 배경이 진하면 글자가 자동으로 흰색이 된다.
- 마감 임박은 와인색 + 'D-N' 글자.

## 7. 어떻게 동작하나 (구조 요약)

- **앱**: 바닐라 JS 웹앱(PWA, 빌드 없음). 서비스워커로 오프라인 앱 셸 캐시, 홈 화면에 설치 가능.
- **데이터**: 정적 JSON(`data/`) — 할 일(11개 파일, 접종·검진·발달·안전·구강·학령기 등), 지원금(전국+시·도 17곳), 어디갈까 장소(약 77곳), 정책(`data/policy/`: 학교 입학 시기, 큐레이션 규칙, 교육 링크, 36개월 이상 자동 일정 허용 목록 등).
- **판단 엔진**: `curate()`가 아이의 월령·지역·완료 상태·마감일로 "지금 꼭 / 곧 / 알아두기"를 가른다. 0~36개월은 기존 엔진, 36개월 이후는 필수·시기성 허용 목록만.
- **저장**: 기기에는 localStorage, 계정·가족은 Firebase(Auth + Firestore: accounts, households, families). 서버 규칙은 `firestore.rules`(배포는 사용자가 직접). 사진 원본은 어디에도 저장하지 않는다.
- **일정 입력**: 사진(OCR) / 붙여넣기 → 공통 규칙 파서(`js/capture/parse-ko.js`) → 일정 후보 → 확인 화면 → 일정 저장(출처 표시, 확인 필수).
- **검증**: 단위 테스트(약 320개), 화면 자동 비교(auto-diff), 데이터 인용 대조 도구. 에이전트 7명(hn_main·pm·dev·design·test·data·research)이 역할을 나눠 일한다(`docs/한눈육아-운영규칙.md`).

## 8. 현재 상태와 앞으로의 계획

진도율(로드맵 기준): **28/31(90%)** → 이번 배포로 4-2·2-3이 완료되면 **30/31(97%)**.

| 단계 | 목표 | 상태 |
|---|---|---|
| 0 설계서 위반·버그 정리 | 놓침·혼란 제거 | 완료 |
| 1 먼저 찾아주는 핵심 경험 | 판단·우선순위 수고 줄이기(큐레이션) | 완료 |
| 2 입력 줄이기 | 붙여넣기·사진·반복·생일 | 붙여넣기·반복·생일 완료, 사진 이번 배포(실기기 확인 대기), 음성 보류 |
| 3 데이터 트랙 | 지원금·어디갈까·월령 정보 정확도 | 3-3(서울·경기 확인필요·신청처) 조사 결과 대기 |
| 4 최종 디자인 | 색·모양 통일, 홈 정리 | 이번 배포로 마무리 |

앞으로(우선순위 순):
1. **동(행정동) 선택 입력** — 서울·경기 행정동 목록·동 중심 좌표 데이터 → 온보딩·프로필 입력 → 어디갈까 동 기준 → 교육 트렌드 동 집계(최소 30명, 부족하면 시·군·구로 확대). 서버 저장에 Firestore 규칙 배포 필요.
2. **사진 AI 보강** — 규칙으로 못 푼 사진을 AI로(중계 서버·요금 결정 필요, 사진 외부 전송 동의 문구 필요).
3. **가족 공유 색 순서 조정 화면** — 앱 안에서 구성원 색 순서를 바꾸고 가족과 공유(규칙 배포 필요).
4. **지원금 데이터 확대** — 서울·경기 '확인필요' 승격, 신청처 링크 확대, 전국 시·군·구.
5. **알림**(푸시·이메일), 카카오·네이버 로그인, 계정 탈퇴, 보안 강화 — 나중.
6. 음성 입력 — 보류. 새 홈 미리보기 삭제 — 후순위.

## 9. 이번 배포 후 직접 확인해 볼 것

1. 온보딩 첫 화면(세로 중앙, 원 2개, 로고)과 로그인·회원가입 가운데 카드(키보드, 겹침 없음, 붉은 그림자 없음)
2. 36개월 미만 웜 브라운 / 이상 딥 포레스트 테마 전환
3. 캘린더(선택 날짜 테두리, 오늘 표시, 주 보기 없음)
4. 구성원 색(역할 기준이라 기존 계정은 색이 바뀜, 웜 브라운에서 비슷한 두 색)
5. 일정 추가 4메뉴·사진 인식·'누구 일정' 칩
6. 할 일 추가·삭제
7. 36개월 이상 아이만 선택 시 캘린더 스위치 2개

## 10. 알아둘 한계

- 사진 인식은 기기 안 OCR이라 손글씨·표는 정확도가 낮을 수 있다. 못 읽으면 직접 입력·붙여넣기로 이어진다.
- 지원금·장소 데이터는 서울·경기 중심이고 나머지는 "확인필요"가 많다. 공식 페이지 확인이 우선이다.
- 가족코드를 아는 사람은 해당 가족의 일정에 접근할 수 있는 구조다(보안 강화는 나중).
- 이 문서의 화면 관련 내용 일부(최종 디자인)는 사용자가 배포 뒤 직접 확인한다.
