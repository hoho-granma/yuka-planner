# 사진 OCR → AI 입력 연결

2026-10-08. 로컬 구현. 사용자 요청으로 검증 후 커밋하며 운영 배포는 하지 않았다.

## 흐름

일정/할일 추가 → 사진 불러오기 → 기기 OCR → 읽은 글자 확인·수정 → 사진 내용 분석해서 채우기 → 후보 선택 → 입력폼 확인 → 저장.

사진 원본은 AI에 보내지 않는다. 기존 OpenRouter/qwen/qwen3.8-flash 텍스트 분석 함수를 재사용하며 버튼을 누를 때만 호출한다. OCR 후 자동 호출·자동 저장·여러 건 일괄 등록은 하지 않는다.

## 구현

- js/app.js: 사진 입력 모드에서 분석 버튼을 표시하고 OCR 완료 전 비활성. OCR 준비 실패 안내. 폼/계정/가족/입력 모드 변경 및 나중에 선택한 사진에 이전 OCR 응답을 적용하지 않는다.
- js/capture/ai-parser.js: 사진/메시지 모드 판정. 서버 전송은 기존 텍스트만 사용한다.
- 후보를 적용해도 사진 입력 모드를 유지하며 원문 글자를 폼에 보존한다. 날짜/시간/대상 확인과 기존 저장 흐름 유지.
- index.html: 변경한 앱/어댑터 캐시 버전 갱신. 다른 세션 변경 보존.

## 제한과 검증

기존 입력폼의 500자 제한을 유지한다. 긴 OCR 결과는 앞 500자만 반영하고 사진을 나누어 올리라는 안내를 제공한다. 전체 사진의 원문 보존·이미지 직접 분석은 이번 범위 밖이다.

`node --test test/photo-ocr-flow.test.js test/photo-ai-input.test.js test/message-ai-client.test.js test/message-input-server.test.js`: 27개 통과. 사진/메시지/직접/음성 모드 구분, OCR 전후 버튼 상태, 원본 이미지 미전송 안내, 기존 인증·후보·서버 오류 검증.

실제 휴대폰 OCR 품질·브라우저 화면·운영 AI 응답·후보 저장은 미검증. 서버 재배포 불필요(기존 텍스트 계약). push·앱 배포는 이번 실행에서 하지 않았다.

검증에서 닫힌 할일 폼의 늦은 OCR 오류 반영 문제를 수정했다. 실제 일정/할일 폼 함수와 후보 적용 이벤트를 모의 실행해 사진 연속 선택·계정 변경·닫힌 폼·준비 실패·500자 초과 안내·분 단위 시간 보존·자동 저장 미호출을 확인했다. dbt-browser recon은 APP_NOT_RUNNING으로 실패하여 실제 브라우저 화면 검증을 수행하지 못했다. 실제 모델 호출과 휴대폰 OCR 품질은 남아 있다.
