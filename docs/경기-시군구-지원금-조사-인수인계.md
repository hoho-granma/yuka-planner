## 3. 이번 작업 순서

### 3-1. 기존 경기 확인완료 점검 (§7)

확인완료 42건 중 아래 8건은 notes나 sourceName에 경고 문구가 있어 먼저 재열람한다.
GG-015, GGM-GWACHEON-02, GGM-GWANGMYEONG-01, GGM-DONGDUCHEON-03, GGM-SIHEUNG-02, GGM-ANYANG-01·02·03.
- 공식 원문을 직접 열람해 §2 다섯 조건을 만족하면 유지(근거 갱신), 못 열었거나 대상·금액·기한이 원문에 없으면 §6 방식으로 확인필요로 강등한다.
- 조사 원본 `_gg-*-raw.json`에서 `일부확인`이었는데 확인완료로 올라간 항목이 있는지도 본다(§7-2 세 번째).
- 알려진 문제: GGM-ANYANG-04(냉동난자, 임신 전 제도)는 이미 pending으로 이동했다. GG-015·GGM-ANYANG-02는 `prenatalOnly: true`로 지정했다.

### 3-2. 확인필요 53건 재열람

공식 페이지를 먼저 본다: 시·군청 사업 페이지 → 조례 원문(law.go.kr) → 정부24·복지로 → 지자체 공식 뉴스·보도자료. 열람 결과가 §2를 만족하면 승격, 아니면 notes에 사유만 갱신한다.

### 3-3. 시·군별 신규 조사 (확인완료 0건 11개 시·군부터)

각 시·군 공식 사이트에서 임신·출산·0~36개월 부모 대상 지원을 찾는다. 서비스 범위는 임신~36개월, 부모가 신청·수령하는 제도만. 시설 이용 안내는 제외.
찾을 것: 출산지원금·축하금, 임신축하금, 산후조리비, 산모·신생아 건강관리 본인부담금, 임산부 교통비, 유축기·용품 대여, 아이돌봄·시간제보육 추가지원, 영유아 건강·예방접종 자체 지원, 육아용품·꾸러미 지원.
전국 공통 제도(부모급여, 첫만남이용권, 아동수당 등)는 제외하고 시·군 자체 추가분만 넣는다.

시·군 하나당 조사 → 검증 → 반영을 끝낸 뒤 다음 시·군으로 넘어간다(한 번에 여러 시·군을 섞지 않는다).

## 4. aside 브라우저 사용 요령

- 열람하지 않은 페이지를 열람했다고 쓰지 않는다. 접속 실패·본문 못 읽음은 notes에 "본문 미열람"으로 적고 확인필요로 둔다.
- 항목마다 원문에서 그대로 복사한 핵심 문장(대상·금액·기간)을 `notes`에 짧게 남기거나 작업 중 메모로 보관해 §2 대조에 쓴다.
- 구청·시청 사이트는 메뉴 껍데기만 나오는 동적 페이지가 많다. 하위 상세 페이지 URL을 직접 열고, 안 열리면 검색 결과 URL이 아니라 사이트 안에서 메뉴를 따라 들어간다.
- 법제처 조례 본문(law.go.kr)이 스크립트 렌더링으로 안 읽히면 생활법령(easylaw.go.kr)이나 시·군청에 게시된 조례 전문, 보도자료로 보완한다. 본문을 못 읽은 채 금액을 적지 않는다.
- 한 브라우저를 쓰므로 시·군을 병렬로 나누지 않고 순서대로 처리한다.

## 5. 데이터 입력 규칙

파일: `data/subsidies/gyeonggi/{시군}/subsidies.json` (구조 `{ "_meta": ..., "subsidies": [...] }`). ID는 기존 규칙 `GGM-{시군영문대문자}-NN`을 따른다(예: GGM-SIHEUNG-02).

필수 필드(서울 데이터 참고): id, name, scope("provincial"), applicableRegions(["경기도:시군명"] 형식은 기존 파일을 보고 맞춘다), target, minAgeMonths, maxAgeMonths, amountText, paymentMethod, deadlineType, deadlineValue, residencyRequirement, additionalConditions, officialUrl, sourceName, lastVerified(열람한 날짜), status, verified, notes.

- `deadlineType`: `ongoing` / `birth_relative_months`(숫자) / `birth_relative_days`(숫자) / `age_window`(값은 반드시 `{"minMonths":0,"maxMonths":24}` 형태 정수 객체) / `unconfirmed`.
- 임신 중에만 신청하는 제도는 `prenatalOnly: true`. 출산 후에도 신청 가능한 임산부 대상 제도는 `postpartumOk: true`, 소득·직종·질환 등 조건이 있으면 `conditionLabel`(짧게, 예: "소득 100% 이하", "서비스 이용자")을 단다. 조건 라벨이 붙은 항목은 앱의 "신청 가능"이 아니라 접이식 섹션으로 간다.
- `status`는 `확인완료`/`확인필요`만. `verified`는 확인완료면 true.
- 범위 밖(임신 전·초등 이상)·전국 중복·종료는 `pending.json`에 `excludeReason`과 함께 둔다.
- 파일 저장은 `json.dumps(..., ensure_ascii=False, indent=2) + "\n"`로 기존 서식을 유지해 diff가 줄 단위로만 나오게 한다.

## 6. 검증·커밋·push

1. 테스트: `node test/hn-logic.test.js`, `node test/todo-engine.test.js`, `node test/sync-v2.logic.test.js`, `node test/data-month-integers.test.js`. 특히 data-month-integers는 age_window 값 형식 오류를 잡는다(이번에 YANGCHEON-002에서 걸렸다).
2. 작업 폴더를 다른 세션과 공유한다. `git stash`, `git checkout`, `git reset`은 쓰지 않는다. 다른 세션의 미커밋 작업(가족 캘린더 v1.12.15 등)은 건드리지 않는다.
3. 커밋은 `git add data/subsidies/gyeonggi ...`처럼 경로를 명시한다. `git add -A`나 `git add .`는 쓰지 않는다. 앱 코드는 이번 작업에서 수정하지 않는다(버전 번호도 올리지 않는다).
4. `www/data/`(iOS 패키징용 복사본)는 git 대상이 아니고 자동 동기화되지 않는다. 이번 작업에서 건드리지 않는다.
5. push는 사용자가 확인한 뒤에만 한다.
6. 작업이 끝나면 `docs/지원금-검증기준.md` §9 형식으로 경기 적용 결과(강등·승격·유지 목록)를 문서에 추가하고, 메모리 `hannun-subsidy-verification-standard.md`를 갱신한다.
