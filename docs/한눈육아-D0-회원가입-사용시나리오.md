# D0 회원가입·로그인 + 가족 캘린더 사용 시나리오 (usecase 기준본)

작성: 2026-10-02 · 요청자 지시를 정리한 기준 문서. 구현·테스트의 진행률은 이 문서의 시나리오(UC)를 기준으로 센다.
관련: [C0 결합계약](한눈육아-C0-AUTO-USER-결합계약.md) · [확장설계 v1](한눈육아-확장설계-v1.md)

## 0. 확정된 전제 (사용자 지시)
- 지금은 회원가입이 없다. **회원가입·로그인·로그아웃을 새로 만든다.** 향후 카카오톡·네이버 로그인 지원 예정(이번 범위 밖, 구조만 열어 둠).
- 캘린더 UI, 하단 메뉴 5개(홈·캘린더·체크리스트·육아 혜택·기록)는 **지금 그대로 유지**한다.
- 엄마·아빠·자녀·이모님 등 **각자 로그인해서 자기 일정을 등록하고 공유**한다.
- 완료 시점까지 push 하지 않는다(커밋은 hn-main이 묶어서 수행).

## 1. 용어
- **계정**: 로그인하는 한 사람. 이름·역할(엄마/아빠/자녀/이모님 등)을 가진다.
- **가족 캘린더 코드**: 8자리. 한 가족(가구)을 가리킨다. 내 정보 화면에 표시되고 다른 가족에게 알려 줄 수 있다.
- **아이**: 가구에 속한 자녀 프로필(출생일·성별·이름). 월령에 맞는 **자동 일정(AUTO)** 을 가진다.
- **내 일정(USER)**: 로그인한 사람이 등록한 일정. 캘린더 기본 보기.

## 2. 시나리오

### UC-1 처음 접속(비회원) — 랜딩
1. 랜딩에 **한눈육아 로고**와 `회원가입` · `로그인` 버튼이 보인다.
2. (기존 사용자 호환) 계정 없이 쓰던 기기는 기존 데이터를 잃지 않는다(§4 마이그레이션).

### UC-2 회원가입 (신규 가족)
입력 항목(한 화면 또는 단계):
1. 로그인 정보(1차: 이메일 + 비밀번호. 카카오·네이버는 후속)
2. 지금 상황 — 라디오: **임산부 / 아이가 있어요**
3. 가입하는 사람 — 라디오: **엄마 / 아빠 / 자녀 / 이모님(기타 돌봄)** + 표시 이름
4. 아이 돌봄 기관 — 라디오: **어린이집 / 유치원 / 초등학교 / 해당 없음**
5. **가족 캘린더 코드** 입력란 — **비워 두면 신규 가족**(새 코드 발급), **입력하면 기존 가족 합류**
6. (아이가 있어요 선택 시) 첫 아이 정보(이름·출생일·성별). (임산부 선택 시) 출산 예정일.
결과: 계정 생성 → 로그인 상태 → 홈. 신규 가족이면 코드가 발급되고 가구가 만들어진다.

### UC-3 회원가입 (기존 가족 합류: 아빠·이모님 등)
1. 가족 구성원이 UC-2의 5번에 **받은 코드를 입력**하고 가입한다.
2. 가입 즉시 그 가구의 구성원으로 추가되고, 캘린더 위 구성원 줄에 **나(아빠)** 가 뜬다. 기존 구성원(엄마·첫째)도 그대로 보인다.
3. 잘못된 코드/존재하지 않는 코드: 가입은 막지 않고 "코드를 찾을 수 없어요" 안내 후 수정하게 한다(신규 가족으로 몰래 만들지 않는다).

### UC-4 로그인 / 로그아웃
1. 로그인: 이메일+비밀번호. 성공하면 마지막으로 보던 가족 캘린더로 들어간다. 다른 기기에서도 같은 계정으로 같은 가족이 보인다.
2. 로그아웃: 내 정보 화면의 `로그아웃`. 로그아웃하면 이 기기에서 가족 데이터 캐시·가구 연결을 지우고 랜딩으로 돌아간다(서버 데이터는 그대로).
3. 비밀번호 분실: 재설정 메일(1차 범위).

### UC-5 첫 로그인 후 + 버튼
`+` 메뉴에 다음이 있다.
- **아이 등록하기** — 아이 정보를 입력하면 가구에 아이가 추가되고, 그 아이의 월령에 맞는 **자동 일정**이 캘린더·체크리스트에 나온다.
- **가족 초대하기** — 가족 캘린더 코드와 복사/공유 안내를 보여 준다(UC-3으로 이어짐).
- (기존) 일정 추가 — 내 일정 입력.

### UC-6 내 정보
- 내 이름·역할, **가족 캘린더 코드**(복사 버튼), 가족 구성원 목록, `로그아웃`.

### UC-7 캘린더 기본 보기
1. 캘린더 위 구성원 줄에 **나(엄마), 첫째(수아)** 처럼 현재 가족이 칩으로 보인다. 아빠가 합류하면 **아빠** 칩이 자동으로 추가된다(새로고침 없이 다음 동기화에 반영).
2. **기본 선택은 로그인한 나** — 내가 등록한 일정이 먼저 보인다. 칩을 눌러 엄마·아빠·아이를 함께 볼 수 있다(기존 복수 선택).
3. 아이를 선택하면 그 아이의 월령별 **자동 일정**이 보이고(기존 토글: 직접 등록한 일정만 보기 / 카테고리별 색깔), 아이 정보가 없으면 자동 일정이 없다.

### UC-8 각자 일정 등록·공유
1. 엄마·아빠·이모님·자녀가 각자 로그인해서 일정을 등록하면 **담당자=본인**이 기본이다.
2. 같은 가구의 다른 구성원 화면에도 보인다(공유). 수정·삭제 권한은 §5.
3. 아이 일정(자동 일정 완료 체크)은 가족 모두가 같은 상태를 본다(기존 완료 동기화).

## 3. 화면·메뉴 (변경 최소)
- 하단 메뉴 5개와 캘린더 UI는 유지. 추가되는 것: 랜딩(로고·회원가입·로그인), 회원가입 화면, 로그인 화면, `+` 메뉴 항목 2개, 내 정보(코드·로그아웃).
- 가족 캘린더 플래그: 계정 기능이 켜지면 가족 캘린더가 기본 구조가 된다(플래그 정책은 설계에서 결정).

## 4. 기존 사용자·데이터 호환 (설계 필수)
- 현재는 **기기 단위** 가구(`hannun_household_*`)·아이 가족코드(6자리)·완료 상태가 로컬+Firestore에 있다. 계정 도입 후에도 **기존 아이 데이터를 잃지 않고** 가입 시 가져오는 흐름이 필요하다("이 기기의 기록을 내 계정으로 가져오기").
- 계정 없이 쓰는 모드(체험)를 유지할지는 설계에서 결정(추천: 유지하고 가입을 권유).

## 5. 열린 결정 (구현 설계 시 확정, 기본 가정 표기)
| # | 질문 | 기본 가정 |
|---|---|---|
| Q1 | 1차 로그인 방식 | 이메일+비밀번호(Firebase Auth). 카카오·네이버는 커스텀 토큰이 필요해 후속 |
| Q2 | 이메일 인증 | 1차 생략(비밀번호 재설정 메일만) |
| Q3 | 자녀 계정 | 역할 선택지에 있으나 일정 등록 권한은 구성원과 동일 |
| Q4 | 구성원 수정/삭제 권한 | 본인 일정은 본인이, 가족 일정은 모든 구성원이 수정 |
| Q5 | 계정 없이 쓰던 기존 기기 | 유지 + 가입 시 데이터 가져오기 |
| Q6 | 가구 코드 변경·재발급 | 1차 없음 |
| Q7 | 탈퇴 | 1차는 로그아웃만, 탈퇴/삭제는 후속 |

## 6. 사용자가 해야 하는 일 (Firebase 콘솔)
- Authentication 사용 설정 + 이메일/비밀번호 제공업체 켜기, 승인된 도메인(hoho-granma.github.io) 확인.
- 새 보안 규칙 배포(계정·구성원 연결 규칙). 테스트 계정 정리.

## 7. 진행률 기준
UC-1~UC-8 단위로 `설계 → 구현 → 검증` 세 단계를 체크해 비율로 센다(진행률 질문 시 이 문서 기준으로만 답한다).
