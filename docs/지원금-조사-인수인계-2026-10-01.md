## 2. 현재 조사 방식 (그대로 이어서 쓰면 된다)

### 2-1. 범위 원칙(사용자 지시)
- **각 시·군·구 대표 공식 사이트의 임신·출산·육아 정책 메뉴만** 본다. 짧게 끝낸다.
- 언론 보도자료, 뉴스, 블로그, 정부24·복지로, 조례(law.go.kr), 다른 기관·사이트는 **열지 않는다**(공식자료 먼저).
- 사이트 안에서 막히면 `본문 미열람`으로 적고 넘어간다. 메뉴 한두 단계 안에서 끝낸다.
- 대상은 임신~36개월 부모가 신청·수령하는 **시·군 자체** 지원. 제외: 전국 공통(부모급여·첫만남이용권·아동수당·국민행복카드), 경기도 단위 사업 접수 안내, 국가 보건소 사업(고위험임산부·미숙아·난청·대사이상 의료비, 영양플러스, 기저귀·조제분유 등), 시설 이용 안내, 임신 전, 초등 이상.

### 2-2. 웹 열람 도구: aside 브라우저
```bash
aside --effort high "프롬프트"          # 브라우저 에이전트가 읽기만 하고 보고
aside session list                       # 상태 확인
aside session stop <id>                  # 중단
```
- `--permission read-only`는 **없는 옵션**(ask/guard/full-access만). 기본값(guard)으로 쓴다.
- 브라우저가 하나라 **병렬로 돌리지 않는다.** 시·군 여러 곳은 순서대로 도는 셸 스크립트(`for i in ...; do aside ... > run$i.log; done`)를 백그라운드로 돌린다.
- 한 곳(시)당 대략 수 분. 로그는 매우 길다(수십~수백 KB). 결과는 로그 끝의 **최종 보고(마지막 `[0m` 이후, `| 사업명` 요약표 앞)**만 읽으면 된다.
- 중단할 때는 체인 스크립트를 먼저 종료(`pkill -f 스크립트명`)하고 실행 중 세션을 `aside session stop`.
- 프롬프트 파일은 세션 임시 폴더에 만들어졌다가 사라지므로 아래 템플릿으로 다시 만든다.

### 2-3. 프롬프트 템플릿 (시·군마다 {시} 와 기존 항목 목록만 바꾼다)
```
경기도 {시} 공식 홈페이지(시청 대표 사이트)에서 임신·출산·육아 지원 정책을 확인해줘. 짧게 끝내는 작업이다. 읽기 전용(로그인·신청·제출 금지).
범위: 오직 {시}청 대표 홈페이지의 임신·출산·육아(보건소 임신·출산 포함) 정책 메뉴만. 해당 메뉴나 '출산·육아 지원 총정리/생애주기별 정책' 페이지 한두 곳에서 지원 목록을 만들고, 목록의 각 항목은 그 사이트의 상세 페이지 한 번씩만 열어 확인해. 언론 보도자료, 뉴스, 블로그, 정부24·복지로, 조례(law.go.kr), 다른 기관·사이트는 열지 마. 사이트 안에서 막히면 '본문 미열람'으로 보고하고 넘어가. 오래 헤매지 말고 메뉴 한두 단계 안에서 끝내.
이미 있는 항목(중복 보고 금지, 내용이 달라졌으면 한 줄만):
- {ID} {사업명} ({status}): {금액 요약}   ← data/subsidies/.../{시}/subsidies.json 에서 뽑아 넣는다
대상: 임신~36개월 부모가 신청·수령하는 {시} 자체 지원(…). 제외: 전국 공통, 경기도 단위 사업 접수 안내, 국가 사업 안내(보건소 국가사업), 시설 이용 안내, 임신 전, 초등 이상.
규칙: 실제로 읽은 페이지만 '열람함', 추측 금지. 원문에 없는 금액·기한은 '원문에 없음'.
신규 항목마다: 사업명 / 대상 / 금액 / 신청기간·기한 / 지급수단 / 거주요건 / 종료·변경 공지 유무 / 열람한 URL / 원문 핵심 문장 / 판정 제안(확인완료 후보·확인필요 후보·제외)과 이유 한 줄.
마지막에 요약표(사업명 | 열람여부 | 판정 제안). 신규가 없으면 '신규 없음'과 확인한 메뉴만.
```
- 기존 항목 재검증이 필요하면 "기존 항목 재검증: 공식 페이지에서 대상·금액·신청기간·지급수단·거주요건이 원문과 일치하는지, 종료·변경 공지가 있는지, 원문 핵심 문장과 현재값과의 차이, 판정(유지/수정 후 유지/강등)" 단락을 추가한다.

### 2-4. 보고·반영 절차(사용자 선호)
1. 열람 결과 → **시·군별 건수 표**(`확인완료 N → M`, `확인필요 N → M`)로 보고. 건별 전후 비교는 사용자가 원치 않음(처음 한 번 요청 시에만).
2. 반영 후보는 "권장안 N건 / 뺄 항목과 이유"로 제안하고 **사용자 OK 뒤에만 파일 수정**.
3. 사용자가 "확인완료만 올릴 거야"라고 한 구간에서는 승격·신규 확인완료만 반영하고, 확인필요 유지·pending 이동 notes는 건드리지 않았다.
4. 반영 → 테스트 4종 → 건수 재집계 → 문서·메모리 갱신 → 커밋은 사용자 확인 후.

### 2-5. 판정 실무 규칙
- 확인완료 후보: 대상·금액(또는 현물 내용)·신청 방법이 원문에 있고 종료 공지가 없는 **시·군 자체** 사업.
- 확인필요로 남기는 것: 금액·기한이 원문에 없는 금전 지원, 국가·도 사업인지 시 자체인지 원문에 구분이 없는 것, 36개월 초과 연령이 섞인 것, 자녀 연령 상한이 원문에 없는 것(육아휴직 장려금류).
- 제외(앱에 안 넣음): 주차장 감면·주차증(혜택형), 도서관 북스타트(시설 연계), 국가 보건소 사업, 교육 프로그램, 전국 공통, 종료 사업.
- 경기도 산후조리비(GG-001)·산모신생아 추가형(중위소득 150% 초과)은 **2026-10-01 종료**. 시·군 페이지에서 보이면 종료로 본다. 시 자체 산후조리비(예: 이천·양주·여주·동두천·포천·의왕)는 별개 사업.

### 2-6. 데이터 입력 규칙 (파일 구조)
- 경로: `data/subsidies/{시도}/{시군}/subsidies.json` (구조 `{ "_meta":..., "subsidies":[...] }`), 도 단위는 `gyeonggi/city.json`, 제외 항목은 `gyeonggi/pending.json`(앱이 읽지 않음).
- ID: `GGM-{시군영문대문자}-NN` (첫 항목은 번호 없이 `GGM-GOYANG` 같은 형태일 수 있음, 새 항목은 최대 번호+1).
- 필수 필드: id, name, scope("municipal"), applicableRegions(["경기도:시군명"]), target, minAgeMonths, maxAgeMonths, amountText, paymentMethod, deadlineType, deadlineValue, residencyRequirement, additionalConditions, officialUrl, sourceName, lastVerified(열람일), status, verified, notes.
- `deadlineType`: `ongoing` / `birth_relative_months`(정수) / `birth_relative_days`(정수) / `age_window`(값은 반드시 `{"minMonths":12,"maxMonths":18}` 정수 객체) / `unconfirmed`.
- 임신 중에만 신청 → `prenatalOnly: true`. 출산 후에도 신청 가능한 임산부 대상 → `postpartumOk: true`. 소득·장애·다자녀·서비스 이용 등 해당자만 → `conditionLabel`(짧게, 앱에서 접이식).
- `maxAgeMonths`는 신청기한에 맞춘다(고양·수원·남양주 등 12개월). 원문에 기한이 없으면 대상 시기(출생신고 시 1개월, 산후 대여 2~3개월 등)로 정하고 notes에 근거를 적는다.
- notes 맨 앞에 `[YYYY-MM-DD 재열람]` 또는 `[YYYY-MM-DD 신규]`와 원문 핵심 문장을 남긴다. 열람하지 못한 부분은 "본문 미열람"으로 쓴다.
- 파일 저장은 `json.dumps(..., ensure_ascii=False, indent=2) + "\n"` — 기존 서식과 diff가 줄 단위로만 나온다(왕복 변환이 정확함을 확인했다).

## 5. 주의사항

- **작업 폴더를 다른 세션과 공유한다.** `git stash`, `git checkout`, `git reset`, 브랜치 전환은 쓰지 않는다. 다른 세션의 미커밋 작업(`data/todos`, `ios/`, `docs/RSV-예방-조사.md`, `test/golden/` 등)은 건드리지 않는다.
- 커밋은 `git add data/subsidies/... docs/...`처럼 **경로를 명시**한다(`git add -A`·`.` 금지). 이 저장소는 `main`에 직접 커밋하는 관행이다.
- 앱 코드·버전 번호는 이 작업에서 수정하지 않는다.
- 열람하지 않은 페이지를 열람했다고 쓰지 않는다. 원문에 없는 금액·기한은 `원문에 없음`.
- `git add` 전에 `git status --short`로 다른 세션 변경이 섞이지 않았는지 확인한다.
- 미커밋으로 남아 있는 문서: 이 인수인계서, 옛 `경기-시군구-지원금-조사-인수인계.md`(대체됨).
