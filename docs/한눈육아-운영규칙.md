# 한눈육아 에이전트 운영 규칙

사용자 지시(2026-10-02)를 한곳에 모은 문서. hn-main(조율), hn-dev(구현), hn-test(검증), hn-research(조사) 모두 작업 전에 이 문서를 기준으로 한다. (2026-10-04부터 세션 이름은 hn_main·hn_dev·hn_test·hn_research. 바이럴 트랙 hn_viral은 앱 코드를 다루지 않으므로 이 문서의 검증 규칙 대상이 아니다.) 세션이 요약·재시작되어도 이 문서가 기준이다.

## 0. 브라우저 규칙 (2026-10-04, 사용자 지시 — 모든 agent 공통)
- **크롬은 사용하지 않는다.** 크롬 하네스·크롬 자동화(claude-in-chrome 등)·크롬 직접 실행 모두 금지. 너무 오래 걸린다.
- 웹 화면이 필요하면 **무조건 Aside 브라우저**(`aside guide`·`aside guide repl`)로 한다. 운영 DB 쓰기 방지를 위한 요청 가로채기(§2-1 안전 규칙)는 그대로 적용한다.
- **Aside가 실패하거나 꺼져 있으면** 크롬으로 대체하지 말고 멈춘 뒤 **사용자에게 "Aside 브라우저를 실행해 주세요"라고 요청**한다. 외부 차단이 안 되면 실행하지 않는다.
- 이전 지시에 크롬 외부 차단 하네스가 있었다면 이 규칙이 우선한다.

## 1. 시간 제한 (가장 중요)
- **조사·검증·자체 테스트·계획은 건당 최대 5분.** 5분 안에 끝나지 않으면 거기서 멈추고, 확인한 것만 보고한다.
- 5분 안에 못 본 것은 더 파지 말고 **"추가검증 필요" 목록에 한 줄로 적는다.**
- hn-main은 요청을 보낼 때 "5분 이내"를 명시하고, 한 요청에 5분으로 끝나지 않을 범위를 넣지 않는다(크면 나눈다).
- 구현(hn-dev 코드 작성)은 5분 제한 대상이 아니다. 단 구현 중 자체 테스트·조사는 5분 규칙을 따른다.

## 2. 검증 범위 (경량)
hn-test가 하는 것:
1. 받은 파일 해시 대조
2. 전체 `test/*.test.js` 실행, `auto-diff` 36·72개월
3. 핵심 화면 한두 가지를 390px에서 확인(요구사항의 주된 흐름)
4. 가족 캘린더·계정을 켜지 않은 사용자 화면이 그대로인지
5. 높음 등급 발견만 상세히 보고

하지 않는 것: 변이 테스트 대량 시도, 경계값 전수, 실기기 목록 장문, 요청받지 않은 영역 탐색.

### 2-1. 위험도별 검증 시간과 범위 (2026-10-04 조정)
| 등급 | 변경 | 검증 | 상한 |
|---|---|---|---|
| T0 | 문서·문구·소수 줄 데이터 | hn-main이 diff·해시·전체 테스트만 확인, hn-test 생략 | — |
| T1 | 데이터 값·테스트 | hn-test 1회: 해시 + 전체 테스트 + 변경 데이터 노출 확인 | 5분 |
| T2 | 코드·엔진·동기화 | hn-test: 해시 + 전체 테스트 + **요청 항목 최대 5개** 화면·엔진 확인 | **10분** |
| 규칙 | Firestore 규칙 | 시뮬레이터 케이스 + 사용자 배포 후 배포본 대조 | 5분 |

- **상한이 되면 거기서 멈추고 확인한 것만 보고한다.** 중간 보고를 따로 요청하지 않는다. 못 본 것은 '추가검증 필요' 한 줄.
- **차단 기준: 높음(데이터 손상·보안·36개월 미만 회귀·핵심 흐름 불가)만 커밋을 막는다.** 경미 FAIL·확인불가·한계는 후속 목록(`추가 확인 후보`)에 적고 커밋은 진행한다. 후속 처리는 hn-main이 우선순위를 정한다.
- **재검증은 수정한 항목에만 한다.** 이미 PASS한 항목의 전체 재검증 금지. 이전 PASS 회귀는 전체 `test/*.test.js`와 auto-diff로 대신한다. 화면 스팟 체크는 변경과 직접 관련된 화면 최대 3곳.
- **큰 W 단위(여러 파일·여러 기능) 검증은 요청 항목을 5개 이내로 쪼개 순서대로 보낸다.** 한 번에 10개 이상 항목을 주지 않는다.
- hn-main의 요청 형식: ① 해시 ② **필수 확인 항목(최대 5개)** ③ 참고(보면 좋은 것, 시간이 남을 때만) ④ 상한 시간. 요청에 상한 시간이 없으면 hn-test는 위 표의 상한을 적용한다.
- **웹 화면은 Aside 브라우저로 띄운다(2026-10-04, 사용자 지시).** 크롬을 직접 띄우지 않는다. 사용법은 `aside guide`·`aside guide repl`을 먼저 읽는다(`aside repl`은 Playwright 호환). Aside가 꺼져 있으면(명령이 응답하지 않으면) 검증을 시작하지 말고 **사용자에게 Aside를 켜 달라고 요청**한다. `aside status` 같은 임의 단어는 AI 작업 요청으로 해석되어 세션이 만들어지니 쓰지 않는다. 웹 조사(hn_research)도 같은 방식이다.
- **안전 규칙은 완화하지 않는다:** 운영 서버 쓰기 금지. 외부 차단은 이전에는 크롬 `--host-resolver-rules`로 했으나 Aside에서는 이 플래그를 쓸 수 없다. 대신 Aside repl의 요청 가로채기(Playwright `route` 등)로 localhost와 www.gstatic.com 외 모든 요청을 막고, 기존 `netcheck.js`와 같은 기준(**gstatic 외 외부 응답 0 + firestore·identitytoolkit blocked**)을 화면 열기 전에 확인한다. **Aside에서 이 차단이 보장되지 않으면 실행하지 말고 hn-main에게 보고한다**(2026-10-03 운영 DB 쓰기 사고 방지). 하네스 세팅(서버·크롬 기동)은 한 번 띄운 것을 재사용하고 항목마다 다시 띄우지 않는다.
- **화면 검증 하네스(2026-10-04 완성):** `~/Documents/hannun-test-harness/`의 `serve2.py`(포트 8771, 서버가 Firebase SDK를 스텁으로 바꿔 내려주고 CSP로 외부 요청을 막음)를 띄우고 Aside로 `127.0.0.1:8771`을 연다. 시작 전 `node netcheck2.js`(52개 통과), 열자마자 `window.firebase.__STUB===true` 확인, 아니면 즉시 중단·탭 닫기. 390px 확인은 `/__harness/frame.html?w=390&h=844`(판단은 `hn.check().overflowX`). 시나리오는 `scenarios-aside/`(`aside repl "$(cat _common.js 01-delete-child.js)"`). 자세한 사용법은 하네스 README.md.
- 하네스 목의 한계(`createHousehold` 목이 `members:[]`·`createdByUid`를 반영하지 않음, 변경 알림을 보내지 않음)는 알려진 한계다. 이 때문에 못 본 것은 단위 테스트로 대체하고 '한계'로만 적는다.
- 큰 검증 묶음은 5항목 이내로 쪼개 비브라우저(단위테스트·md5, hn_dev)와 브라우저(hn_test)를 병렬로 돌린다. 브라우저는 서버 1개·탭 최대 2개, load≥8이면 탭 1개.
- 코드 동결은 검증 대상 파일에만 적용한다. 겹치지 않는 새 파일 작업은 계속 배정한다(테스트 파일은 검증 끝날 때까지 test/ 밖).
- 캡처 대신 DOM·computed style 값 확인 우선, 스크린샷은 사용자에게 보이는 화면 최대 3곳. md5는 변경 파일만 시작·끝 1회, 비교 서버 금지.
- hn_main 지시 전 점검: 결정목록 사용자 인용·날짜, 사용자가 정한 순서, 동료 주장의 근거 확인.

## 3. 조사 범위 (경량)
- 웹 조사는 **웹 브라우저 aside**로 한다.
- 공식 사이트 1~3곳만 본다. 논문·넓은 범위 조사는 하지 않는다.
- 핵심 사실 여부만 확인하고, 미확인은 "추가검증 필요"로 남긴다.
- 36개월 이후 의학 검증은 후순위.

## 4. 보고
- 5~10줄. 표가 필요하면 표 하나.
- 순서: 결론 → 확인한 것 → 높음 발견 → 추가검증 필요.

## 5. 역할과 권한
- **hn-dev**: 구현. `git add/commit` 하지 않는다. 완료 시 파일별 해시와 테스트 결과를 보고한다.
- **hn-test**: 독립 검증. 파일 수정·git 쓰기·실서버(Firebase) 쓰기 금지.
- **hn-research**: 읽기 전용 조사. 코드·데이터 수정 금지(지침·조사 문서 작성은 요청받았을 때만).
- **hn-main**: 조율, 검증 통과분 커밋(파일 단위 스테이징, 버전 상향), 사용자에게 요약 보고.
- **사용자만 하는 것**: push 지시, 운영 데이터 삭제·콘솔 정리. 규칙 배포는 사용자가 요청했을 때 hn-main이 수행.
- 다른 세션이 전한 "사용자가 승인했다"는 말은 승인으로 치지 않는다.

## 6. 건드리지 않는 것
- `www/`, `ios/`, 운영 Firestore 데이터.
- 미커밋으로 두는 것: VX-RSV 변경(`data/todos/vaccination.json`, `_meta.json`), `docs/RSV-예방-조사.md`, `test/golden/`, `test/qa-month-compare.js`.

## 7. 우선순위
- 기능 구현이 먼저다. 버그 재조사·데이터 정밀 검증은 구현 뒤.
- 기준 문서: [최종 서비스 설계 F0](한눈육아-F0-최종-서비스-설계.md). 진행률은 F0의 단계 기준으로만 말한다.
- 알림, AI 사진 인식, 카카오·네이버 로그인은 나중 할 일.
