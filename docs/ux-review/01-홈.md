# 01. 홈 — 지금 우리 아이에게 필요한 것 (UX 검토)

> 읽기 전용 분석, 2026-10-05, 배포 v1.12.97 기준. 판단 기준은 `docs/한눈육아-서비스방향설계서.md`(§7-A·§12·§15)과 `docs/한눈육아-메뉴별UX지침.md`(§2·§10·§14). 코드 수정 없음. 화면을 띄워 보지 않았으므로 노출 개수는 코드와 데이터를 읽어 추정한 값이고, 기존 분석(scratchpad `홈-월령별-현황-분석.md`, 서울 구로구 기준 노출 후보 수)을 참고했다. 실제 화면에서 확인하지 않은 것은 **추가확인 필요**로 표시했다.

## (A) 공통 질문 6개

| # | 질문 | 답 |
|---|---|---|
| 1 | 왜 들어오나 | 앱을 열면 가장 먼저 보이는 화면이다. "우리 아이 지금 뭘 챙겨야 하지?", "이번 주 가족 일정이 뭐였지?"를 확인하려고 들어온다. 목적이 정해져 있지 않은 방문이 대부분이라, 홈이 먼저 답해 주지 않으면 부모가 탭을 하나씩 열어 보게 된다. |
| 2 | 가장 먼저 알고 싶은 것 | ① 지금(이번 달) 꼭 해야 하는 것(접종·검진·신청 마감) ② 곧(1~3개월 안) 다가오는 것 ③ 이번 주 가족 일정 ④ 이 시기에 무엇이 달라지는지(대표 고민 1~2개). 기능 목록이나 카테고리 이름은 궁금해하지 않는다. |
| 3 | 한눈이 대신할 수 있는 것 | 월령·학년·지역으로 해당 항목 고르기(구현됨), 이번 달·곧·지난 것 나누기(일부 구현), 마감 순 정렬, 완료·일정에 넣은 항목 숨기기, 다음 단계 미리 알림(구현됨, 구간 좁음), 지원금 대상 여부 판단(지역 데이터 범위 안에서만). |
| 4 | 사용자가 직접 할 행동 | 완료 체크, "일정으로 넣기" 확인, 신청 링크 누르기 정도로 줄여야 한다. 지금 36개월 이상 홈은 부모가 할 일을 직접 타이핑하는 메모장이 중심이라 입력이 오히려 늘었다. |
| 5 | 다음 행동 | 항목 → 상세(정보) → 예약·신청 링크 → 일정 넣기 → 가족 캘린더 → 가족이 함께 봄. 0~35개월은 카테고리 줄 → 팝업 → 상세까지 두 단계를 거쳐야 행동 버튼이 나온다. 다음 단계 배너는 "일정으로 넣기"까지 바로 이어진다(`next-stage.js:151-172`). |
| 6 | 재방문 시 달라질 것 | 완료하거나 일정에 넣은 항목은 빠지고, 날짜가 다가오면 다시 나와야 한다. 월이 바뀌면 이번 달 목록이 바뀌어야 하고, 단계 경계에 가까워지면 다음 단계 안내가 나와야 한다. 지금은 36개월 이상에만 "일정 넣으면 숨김, 7일 전에 다시 표시"가 있다(`app.js:1262-1265`, `home-reappear.json`). 36개월 미만 홈에는 완료 항목이 "모두 완료 ✓" 줄로 남는다(`home.js:90-91`). |

## (B) 단계별 현황 → 문제점 → 개선 UX → 필요 데이터/기능 → 메뉴 연결 → 우선순위

### 공통 구조 (모든 단계)

- 렌더 분기: `app.js:1337-1342` `renderHome` 래퍼. 지금 고른 아이가 36개월 이상(`acct36Child`, `app.js:1253-1256`)이면 `acct36RenderHome`(`app.js:1380-1389` → `over36-view.js:43-58`), 그렇지 않으면 `renderHomeBase`(`app.js:2383` → `home.js:57-195`). 그 다음 `nsSync()`가 다음 단계 배너를 홈 맨 아래에 붙인다(`app.js:2970-2978`).
- 맨 위: 프로필 카드는 아이가 아니라 '나(보호자)'를 보여 준다(`app.js:891-903`). 아이 이름·나이는 아래 '챙길 것' 머리 줄에만 나온다(`app.js:905-912`, `home.js:49-55`).
- 섹션 순서: 가구가 켜져 있으면 `HomeOrder.homeSectionOrder`(`home-order.js:28-36`)가 순서를 정하지만, 계정 모드에서는 나이와 관계없이 가족 일정 카드가 먼저 온다(`home.js:67-70`).
- 가족 일정 카드: 앞으로 7일, AUTO 제외, 최대 `UPCOMING_MAX`건(`app.js:4569-4579`, `user-schedule-view.js:1216-1235`).
- 다음 단계 배너: `next-stage.json`의 4개 단계뿐이다. TO_BORN(예정일 2개월 전), TO_3_5(33~35개월, windowMonths 3), TO_6_7(69~71개월), TO_SCHOOL(취학통지 무렵).

### B-1. 임신

| 항목 | 내용 |
|---|---|
| 현황 | 가족 일정 카드 → D-day 배너(긴 안내문, `home.js:40-46`) → "N월 챙길 것" → "신청 가능한 혜택"(최대 3건, `home.js:121-142`) → TO_BORN 배너(예정일 2개월 전부터). 머리 줄은 "이름 · 임신 N주"(`app.js:907-910`). |
| 문제점 | ① 설계서 §6의 "이번 주에 무엇을 검사·준비하지"(주차별)에 답하는 데이터가 없다. `data/todos/pregnancy.json`에는 PG-01 출생신고, PG-02 바우처 2건뿐이다. 산전검사 PREG-003은 `info-actions.json`에도 "현재 데이터에 없다"고 적혀 있다. ② PG·PREG 항목은 `행정·지원금` 분류라서 `classifyHomeItems`가 "챙길 것"에서 뺀다(`hn-logic.js:212`). 그래서 임신 중 "N월 챙길 것"은 출산 후 항목(예정일 기준) 중 이번 달에 걸린 것만 남고, 대부분 비어 있을 가능성이 높다(**추가확인 필요**: 실제 화면). ③ D-day 배너 문구가 3문장으로 길고, 해야 할 행동은 "아이가 태어나면 프로필에서…" 하나다. |
| 개선 UX | 머리 카드 "임신 N주 · D-xx" 아래에 **"이번 주 할 것" 1~3줄**(주차 기준: 보건소 등록, 바우처, 독감 접종 등 근거 있는 것만)을 둔다. 혜택은 별도 섹션 대신 같은 목록에서 마감 순으로 섞는다. 예정일 2개월 전부터 TO_BORN 배너("출생 후 1개월 안에 할 신고·신청")를 위쪽으로 올린다. |
| 필요 데이터/기능 | 임신 주차별 검사·준비 데이터(공식 근거 1~3곳, 미확인은 '추가검증 필요'), PREG 항목의 주차 창(`pregnancy-timing.json`에 일부 있음, 확인일 가정값 -252일은 근사), 주 단위 분류 함수. |
| 메뉴 연결 | 혜택 탭(PREG 지원금 상세·신청 링크), 캘린더(보건소·산부인과 일정, `info-actions.json` PREG-003 "산부인과 검진 일정"), 가족 공유(배우자에게 검진일 전달). |
| 우선순위 | **P1 / M**(데이터 조사가 먼저. 화면 변경은 S) |

### B-2. 0~12개월

| 항목 | 내용 |
|---|---|
| 현황 | 가족 일정 → "N월 챙길 것"(카테고리 6개 줄 요약: 발달·접종·검진·생활·안전, 줄마다 미완료 항목 제목을 쉼표로 이어 붙임, `home.js:76-101`) → "이 기간에 챙겨볼 것"(기간형 AUTO 묶음, `home.js:104-119`) → "신청 가능한 혜택"(최대 3) → 다음 단계 배너 없음(TO_3_5는 33개월부터). |
| 문제점 | ① 서울 구로구 기준 노출 후보가 141건(기존 분석)이다. 이번 달 창으로 줄여도 카테고리 줄이 4~5개, 줄마다 항목이 여러 개라서 **무엇이 가장 중요한지 판단을 부모에게 넘긴다.** 접종처럼 기한이 있는 것과 발달 관찰·생활 팁이 같은 무게로 보인다. ② 줄을 눌러도 팝업 목록이 한 번 더 나오고(`home.js:168-181`), 상세를 열어야 예약·일정 넣기에 닿는다(2~3번 탭). ③ `classifyHomeItems`가 `upcoming`(다음 달 이후)을 계산하지만 홈은 쓰지 않는다(`UPCOMING_MAX`·`PAST_MAX` 상수도 쓰이지 않음, `home.js:10-11`). 그래서 UX지침 §2의 "이번 달 할 것과 곧 할 것 구분"이 없다. ④ 완료한 카테고리도 "모두 완료 ✓" 줄로 남고, 일정에 넣은 항목은 "(예약됨…)" 꼬리표를 단 채 계속 보인다(`home.js:90`). 36개월 이상 홈은 이런 항목을 숨기므로 단계별로 규칙이 다르다. ⑤ 혜택이 없어도 빈 섹션과 버튼이 늘 남는다(`home.js:139`). |
| 개선 UX | **"지금 꼭 할 것" 최대 3줄**(기한·필수: 접종·검진·신청 마감 순)을 맨 위에 두고, 바로 행동 버튼(예약 링크·일정 넣기·완료)을 붙인다. 그 아래 **"곧(1~2개월 안)"** 1~2줄(`cls.upcoming` 재사용). 발달·생활·안전은 **"이 시기 살펴볼 것"** 접힘 1줄로 내린다(대표 1개만 보이기). 완료하거나 일정에 넣은 항목은 36+와 같은 재등장 규칙(`home-reappear.json`)으로 숨긴다. 혜택은 대상 항목이 있을 때만 보이고, 마감 30일 안이면 "지금 꼭 할 것"으로 올린다. |
| 필요 데이터/기능 | 항목별 '필수/기한' 등급(현재 `priorityOf`가 있는지 확인 필요, `hn-logic.js:246-247`), `cls.upcoming` 표시, 재등장 규칙을 36개월 미만에도 적용, 혜택 마감 임박 분류(`subsidyBuckets` 재사용). 새 데이터는 필요 없다. |
| 메뉴 연결 | 체크리스트(전체 목록), 혜택 탭, 캘린더(일정 넣기, AutoSteps 링크), 기록(접종 완료 기록). |
| 우선순위 | **P0 / M**(검색·판단 부담을 가장 크게 줄이는 지점. 데이터는 이미 있다) |

### B-3. 12~36개월

| 항목 | 내용 |
|---|---|
| 현황 | 0~12개월과 같은 `home.js` 경로. 33~35개월에만 TO_3_5 배너("3~5세 시작 전에 챙길 것 · 유아학비와 영유아검진 6차", 항목 NAT-020, HC-07). 어린이집 입소대기(CR-01)는 생활 분류 줄 안에 섞여 있다. |
| 문제점 | ① 설계서 §6의 "이 시기에 뭐가 달라지지(발달·생활·어린이집)"를 대표 고민으로 꺼내 주지 않는다. 카테고리 줄 요약만 있다. ② 다음 단계 안내가 33개월부터라 설계서 §12 예시("30개월→36개월 이후")보다 늦다. 그리고 36개월이 되는 순간 홈 전체가 바뀐다(탭 5→4개, 혜택 탭 숨김, 체크리스트→메모장). 무엇이 바뀌는지 미리 알려 주는 안내가 없다(**추가확인 필요**: TO_3_5 시트 문구에 그 내용이 있는지). ③ 12~32개월에는 "곧" 안내가 전혀 없다. ④ 어린이집 입소대기처럼 시기가 중요한 항목이 생활 줄에 묻힌다. |
| 개선 UX | B-2와 같은 3단 구조(지금 꼭/곧/살펴볼 것)에 **"이 시기 달라지는 것" 대표 1장**(예: 18개월 검진·어린이집 입소 대기·언어 발달 관찰)을 더한다. TO_3_5 창을 6개월(30개월부터)로 넓히고, 36개월이 되면 홈이 어떻게 바뀌는지 한 줄로 알린다. |
| 필요 데이터/기능 | 월령 구간별 대표 고민 매핑(정책 JSON 1개, 기존 todo id 참조). `next-stage.json`의 TO_3_5 `windowMonths` 값 조정(정책값만 바꾸면 됨. 단, 6개월 미리 보여 주는 것이 너무 이른지는 사용자 결정). |
| 메뉴 연결 | 어디갈까(아이 나이 기본값), 혜택(유아학비 NAT-020), 캘린더(어린이집 상담·입소 일정). |
| 우선순위 | **P1 / S~M** |

### B-4. 3~5세 (36~71개월)

| 항목 | 내용 |
|---|---|
| 현황 | `over36-view.js:43-58`: 아이 칩(2명 이상일 때만) → "오늘·이번 주 우리 가족" → **"놓치기 쉬운 것, 챙겨 드려요"**(허용 목록 `auto-after36.json` 34개 id 중 해당되는 것, 최대 3건, `app.js:1259-1267`) → **"[이름] 할 일"** 메모장(직접 입력, 3줄) → "자주 쓰는 일정" 칩(학원·숙제·준비물) → 69~71개월 TO_6_7 배너. 혜택 탭과 "N월 챙길 것"은 없다. 교육 트렌드 탭은 36개월부터 생기지만 초등 학년 범위가 아니라서 "초등 학년 범위를 벗어났어요"가 나온다(`edu-trend.js:17`, `over36-view.js:122`). |
| 문제점 | ① 설계서 §6의 "교육은 어떻게(기관·교육·건강·활동·지역)"에 답하는 영역이 없다. 홈의 개인화 내용은 허용 목록 최대 3건(HC-07~09 검진, 접종, NAT-020, 지역 지원금 일부)이 전부다. ② **아이 이름·나이 줄이 없다.** `kids[].ageText`를 계산해서 넘기지만 `renderHome`이 쓰지 않는다(`app.js:1383`, `over36-view.js:45-46`). 아이가 1명이면 칩도 없어서 홈만 보고는 누구의 몇 살 기준 화면인지 알 수 없다. ③ 메모장과 "학원·숙제·준비물" 칩은 부모 **입력을 늘리는** 구조다(UX지침 §13 "입력→사진/음성"과 반대 방향). ④ 지원금이 혜택 탭 없이 허용 목록에서만 나와서, 서울·경기 일부 시군이 아니면 지역 지원금이 거의 없다(기존 분석 G10). ⑤ 교육 트렌드 탭은 이 나이에서 열어 봐도 비어 있다. |

## (D) 설계서·UX지침과 어긋나는 현재 구현 (보고만, 수정하지 않음)

1. **36개월 이상 홈이 메모장·가족 캘린더 중심이다** (`over36-view.js:43-58`). 설계서 §6(3~5세 교육·기관, 6~7세 초등 준비, 초등 학년·지역 교육)과 §20 "체크리스트·가족 캘린더 앱이 아니다"와 어긋난다.
2. **36개월 이상 홈에 아이 이름·나이·학년 줄이 없다**. `ageText`를 계산하지만 렌더하지 않는다(`app.js:1383`, `over36-view.js:45-46`). 설계서 §4·§18 "아이가 다르면 홈이 달라야" 한다는 기준을 사용자가 확인할 수 없다.
3. **"이번 달 할 것 / 곧 할 것" 구분이 없다** (UX지침 §2). `classifyHomeItems`의 `upcoming`을 홈에서 쓰지 않는다(`home.js:72` 이후, `UPCOMING_MAX` 미사용).
4. **완료·확인한 것이 반복된다** (UX지침 §2). 36개월 미만은 "모두 완료 ✓" 줄과 "(예약됨)" 꼬리표 항목이 남는다(`home.js:90-91`). 36개월 이상만 숨김·재등장 규칙이 있어 단계마다 규칙이 다르다.
5. **대표 고민이 아니라 카테고리 나열**이다 (설계서 §7-A "단순 콘텐츠 목록 아님", UX지침 §2 "모든 콘텐츠 나열하지 않고 대표 고민 우선"). `home.js:82-93`.
6. **다음 단계 안내 범위가 좁다** (설계서 §12, UX지침 §10). TO_3_5는 33개월부터(예시는 30개월), 0~32개월에는 안내가 없고, 초등→다음 학년 단계가 없다(`next-stage.json`).
7. **임신 주차별 경험이 없다** (설계서 §6). 홈은 월 단위이고, 주차별 검사 데이터도 없다(`data/todos/pregnancy.json` 2건).
8. **36개월 이상에서 지원 탭이 숨겨진다** (`app.js:1290-1291`). 지원금은 허용 목록에 있는 것만 홈에 나온다. 설계서 §7-C "놓치기 전에 챙겨드립니다"는 36개월 이후 지역 지원(예: 서울·경기 외 지역)에서는 사실상 동작하지 않는다(데이터 범위 문제와 겹침).
9. **홈 탐색 영역(⑥ 어디갈까·교육) 진입이 없다** (설계서 §15 ⑥, UX지침 §12 메뉴 간 연결). 하단 탭으로만 갈 수 있다.
10. **교육 트렌드 탭이 36개월부터 생긴다** (`edu-trend.js:17`). 하지만 내용은 초등 학년 기준이라 3~5세에게는 "범위를 벗어났어요"가 보인다. 설계서 §14 "3~5세 이후 중요도 증가"를 따른 것이라면 3~5세용 내용이 필요하고, 아니라면 노출 시점이 이르다. **사용자 결정 필요**.
11. **판단 기준이 둘이다**. 홈은 지금 고른 아이 기준이고, 달력 토글은 가구 전체 기준이다(기존 분석 G9, `app.js:4783`). 홈 문제는 아니지만 혼합 가구에서 일관성에 영향을 준다.

## 6줄 요약

1. 0~35개월 홈은 데이터는 충분하지만, 카테고리 나열 구조라 우선순위를 부모가 판단해야 한다. "지금 꼭 할 것 3 / 곧 / 살펴볼 것" 3단 구조가 P0이다.
2. 36개월 이상 홈은 메모장·가족 일정이 중심이고 개인화된 것은 "놓치기 쉬운 것" 최대 3건뿐이다. 설계서 §6의 교육·취학·초등 고민에 답하지 못하고, 입력은 오히려 늘었다.
3. 36개월 이상 홈에는 아이 이름·나이 줄이 없다. `ageText`를 계산하지만 렌더하지 않으므로 S 규모로 바로 고칠 수 있다(P0).
4. `classifyHomeItems`의 `upcoming`을 홈에서 쓰지 않고, 완료·예약 숨김 규칙이 36개월 이상에만 있다. 전 단계로 통일해야 한다(P1/S).
5. 다음 단계 배너는 4종뿐이다. TO_3_5는 33개월부터, 0~32개월과 초등은 안내가 없다. 정책값과 항목 추가로 해결할 수 있다(P1/S).
6. 임신 주차별 검사, 유치원 입학, 돌봄·방과후, 초등 학교 일정 데이터는 저장소에 없다. 모두 추가확인(조사)이 먼저 필요하다.
