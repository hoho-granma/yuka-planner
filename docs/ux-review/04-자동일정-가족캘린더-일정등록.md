# 04. 자동 일정/할 일 · 가족 캘린더 · 일정 등록 (UX 검토)

> 읽기 전용 분석, 2026-10-05, 배포 v1.12.97(`js/version.js`) 기준. 판단 기준은 `docs/한눈육아-서비스방향설계서.md`(§7-D·§8·§9·§10·§11·§20)과 `docs/한눈육아-메뉴별UX지침.md`(§5·§6·§7·§13·§14), 참고 문서는 `docs/한눈육아-자동입력-사진음성-계획서.md`다. 코드는 고치지 않았고 브라우저도 띄우지 않았다. 개수와 탭 수는 코드와 데이터를 읽어 추정한 값이다. 실제 화면에서 확인하지 않은 것은 **추가확인 필요**로 표시했다.

## 0. 핵심 발견 7가지

1. **36개월 미만 달력에는 정보·관찰형 항목이 행동형 항목보다 많이 찍힌다.** 이유식·안전·발달·수면·생활 같은 항목도 "추천일" 칩으로 달력에 올라간다(`schedule.js:170`, `hn-logic.js:99-155`). 넓은 기간 항목은 기간 안의 모든 달에 반복된다(`app.js:2204-2237`). 추정하면 생후 6개월 달은 행동형 9건, 정보형 16건이고, 18개월 달은 행동형 4건, 정보형 16건이다. 설계서 §7-D "필수성+시기성+실제 행동 필요성이 있는 것만"과 어긋난다.
2. **AUTO와 일정을 잇는 기능이 접종·검진·치과(OR-03/04)에만 있다**(`calendar-model.js:76-83`). 지원금 신청, 취학통지서·예비소집처럼 날짜가 생기는 자동 항목은 "일정으로 넣기"가 없다. 부모가 같은 내용을 처음부터 다시 입력해야 하고, 그래도 AUTO 항목은 따로 남아 두 번 보인다.
3. **빠른 칩 '예방접종'과 G13 카테고리 '예방접종·병원·검진'으로 만든 일정은 AUTO와 연결되지 않는다**(`user-schedule-view.js:1161-1170`, `schedule-kinds.js:24-25`). 부모가 이미 자동으로 만들어진 접종을 손으로 다시 입력하게 되고, 그 결과 같은 날 항목이 두 번 보인다.
4. **담당자 지정이 화면에서 사라졌다.** 계정 모드 폼은 담당 선택을 지웠다(`user-schedule-view.js:931`). 카드와 상세 화면에도 담당 텍스트가 없다(`user-schedule-view.js:458-462`, `598-611`). 아이 일정의 담당은 작성자로 자동으로 들어간다(`user-schedule-view.js:853`). 그래서 "아빠가 데려갈 민준이 치과"를 표현할 수 없다. 설계서 §8 "담당자 지정"과 어긋난다.
5. **홈 '다가오는 우리 가족 일정'은 AUTO를 뺀다**(`app.js:4573` `showAuto:false`). "우리 가족에게 앞으로 무슨 일이 있는가"가 홈(USER만)과 캘린더(AUTO+USER)로 나뉜다.
6. **일정 등록은 직접 입력 하나뿐이다.** 사진·음성은 코드가 없다. `js/capture/` 폴더가 없고, `voiceInput`·`photoInput` 플래그도 없다. 받는 쪽(규칙의 `sourceType` VOICE/OCR, I8 확인 필수, `normalizeFromCandidate`)만 준비되어 있다(`firestore.rules:258,308-310`, `user-schedule.js:434-456`). 직접 입력은 대표 시나리오 기준 **탭 약 16회와 타이핑 1회**가 필요하다(§3-B).
7. **알림이 없다.** 코드에서 Notification·Push를 찾지 못했다. B7은 옵션 문서 단계다. 그래서 "기억"과 "가족에게 전달"의 부담은 아직 부모에게 남아 있다.

**문제점**

1. 정보·관찰형 항목(이유식 단계, 꿀 금지, 익수 예방 등)이 "일정"처럼 날짜 칸에 찍힌다. 매달 반복되는 항목은 한 번 완료하면 모든 달에 ✓가 남는다(`app.js:2208-2210`). 그래서 부모는 "이걸 이 날 하라는 건가?"를 판단해야 한다(지침 §14-②).
2. 지원금은 시작일에만 찍히고 마감은 칸에 없다. 마감을 기억하는 일이 부모에게 남는다.
3. 연결은 4종만 된다. 지원금·취학·생일·연례 접종은 부모가 처음부터 입력해야 한다(위 목록).
4. 예약 폼에서 날짜가 비어 있다(I9를 지키려는 의도). 그런데 한눈은 이미 추천일을 알고 있다. 후보 칩 하나로 입력을 줄일 수 있다.
5. 36개월 이상 할 일은 메모장(직접 타이핑)이라 "기억"을 부모가 직접 기록해야 한다(01-홈 검토와 같은 결론).

**개선 UX**

- AUTO를 두 층으로 나눈다. **일정형**(접종·검진·지원 신청/마감·취학·학교 검진)은 달력 칸에 찍는다. **알아둘 것**(이유식·안전·발달·수면·생활)은 달력 칸에서 빼고 '이번 달 챙길 것'과 월령 정보 화면에만 둔다. 데이터는 바꾸지 않고 표시 규칙만 바꾼다.
- '이번 달 챙길 것'의 행 버튼을 하나로 맞춘다. 행동형은 [예약/신청 링크] → [일정 넣기(후보 날짜 1탭)] → [완료]다. 지원금도 "신청 일정 넣기"를 단다.
- 일정을 넣으면 AUTO 행은 "예약됨 10/14 · 일정 보기"로 바뀐다(지금 동작). 날짜 7일 전에 다시 위로 올린다(36개월 이상 규칙을 전 단계로 확대).

**필요 데이터/기능**: `isLinkableAuto` 대상 확장(SB·지역 지원금·SC). 그에 따른 `autoRef` 형식 확인(지역 지원금은 `<id>__default`, `calendar-model.js:39-44`). 마감 칩 계산. 추천일을 폼 후보로 넘기는 인자. 정보형/일정형 구분 필드(카테고리 코드로 1차 구분 가능: VX·HC·SB·CR·PG·SC = 일정형). 생일 계산 일정. 독감·유치원 원서 데이터 조사.

**다른 메뉴와의 연결**: 홈(이번 달 챙길 것 = 같은 목록), 지원/혜택(신청 링크 → 신청 일정), 월령 정보(정보형 항목이 가는 곳), 가족 캘린더(연결 일정), 기록(완료 제안 → 접종 기록).

### (A) 공통 질문 6개

### (B) 현황 → 문제점 → 개선 UX → 필요 데이터/기능 → 다른 메뉴 연결 → 우선순위

**현황**

- 구성원 칩: 계정 모드는 구성원마다 칩 1개(나는 '나' 또는 표시 이름)와 아이 칩이 있고, '가족' 칩은 없다(`user-schedule-view.js:338-357`, `app.js:4416` `noFamily`). 칩을 하나도 고르지 않으면 '전체'다. 선택은 저장하지 않는다(`app.js:4417-4418`).
- 필터 의미: 구성원 칩은 그 사람이 담당인 일정, 아이 칩은 그 아이 일정과 그 아이의 AUTO를 보여 준다(`calendar-model.js:90-117`). 엄마·아빠만 고르면 AUTO는 사라진다.
- 담당: 데이터 필드 `assigneeMemberId`는 있다. 그런데 **계정 모드 폼에 담당 선택이 없다**(`user-schedule-view.js:931`). 비계정 폼에도 담당 마크업이 없다(`renderForm` 999-1045). 클릭 처리(`app.js:5410-5416`)와 강조(`app.js:4560-4567`)만 남아 있다. 카드·상세는 담당 이름을 보여 주지 않는다(`user-schedule-view.js:458` 주석 "담당은 화면에 표시하지 않는다", `renderDetail` 행 목록 601-608). 담당은 '전체' 보기의 칩 **색**으로만 드러난다(`occurrenceColor`, 291-295).
- 담당 자동값: G13에서 '나'로 시작한다. 아이로 바꾸면 담당은 나로 남고(`user-schedule-view.js:853`), '가족 전체'로 바꾸면 담당이 비워진다. 결과적으로 아이 일정에 배우자를 담당으로 둘 방법이 없다.
- 범례: 가구가 있으면 진행률 카드(카테고리 범례 포함)가 숨겨진다(`app.js:1743-1749`). 그 대신 문구 "꽉 찬 칩은 직접 등록한 일정, 테두리만 있는 칩은 자동 일정이에요"가 나온다(`user-schedule-view.js:76`, `app.js:4696`). 36개월 이상이면 이 문구도 숨긴다.
- 직접 입력만 보기: **아이 칩만 골랐을 때만** 토글이 보인다(`user-schedule-view.js:386`, `367-371`). '전체'에서는 AUTO를 숨길 방법이 없다. '카테고리별 색' 토글도 같은 조건이다.
- 칸 표시: 직접 등록이 먼저, 그다음 자동, 최대 2개 + N(`user-schedule-view.js:405-420`). 날짜 패널은 "추가한 일정 / 혜택 신청 시작 / 추천 항목(정해진 날이 아니에요)" 3구역에 '자동' 출처 라벨을 붙인다(`app.js:4702-4724`, `user-schedule-view.js:547-554`).
- 기간형: USER '날짜 미정(기간)'은 달력 아래 "이번 달 기간 일정"과 시작일 칸의 '기간' 칩으로 보인다(`user-schedule-view.js:562-565`, `calendar-model.js:164-167`). AUTO 기간형은 별도 카드 "이 기간에 챙겨볼 것"으로 보인다(`app.js:1856-1880`). 기간형 영역이 두 곳이다.
- 보기: 계정 모드는 월 보기만 있다(주 보기는 비계정에서만, `app.js:4600-4602`).
- 공유 범위: "지금은 모든 일정이 가족 캘린더에 공개로 저장돼요". 공개 범위 항목은 숨겨져 있다(`user-schedule-view.js:99`, `943`).
- 홈 연결: '다가오는 우리 가족 일정'은 7일 이내 최대 3건이고 AUTO를 뺀다(`app.js:4569-4579`).

**문제점**

1. 담당이 화면에 없다. 지침 §7 "필요 시 담당자 표시"와 설계서 §8을 충족하지 못한다. 색으로만 구분하면 칩 색이 아이색인지 담당색인지 헷갈린다(보기 모드에 따라 색 기준이 바뀐다, `cellChips` 411).
2. '전체' 보기에서 AUTO를 접을 수 없다. 정보형 칩까지 섞여서 가족 일정을 찾기 어렵다(메뉴 ①의 발견 1과 겹친다).
3. 기간형이 두 영역(AUTO/USER)으로 나뉘어 있고 문구도 다르다("이 기간에 챙겨볼 것" / "이번 달 기간 일정"). 부모가 둘을 모두 확인해야 한다.
4. 홈 가족 카드에 AUTO 일정형(예약된 접종, 지원금 마감)이 빠진다.
5. 알림이 없다. 배우자가 일정을 넣어도 다른 가족은 앱을 열기 전에는 모른다. 전달은 여전히 카톡으로 한다.

**개선 UX**

- 카드 메타 한 줄에 **담당 이름**을 붙인다(예: "오후 3:00 · 민준 · 아빠가 데려가요"). 상세에 '담당' 행을 둔다.
- 칩 필터의 의미를 한 문장으로 보여 준다(예: "아빠 칩 = 아빠가 맡은 일정").
- '전체' 보기에도 "자동 항목 접기" 스위치를 둔다(이 기기에 기억). 기본값은 사용자 결정이 필요하다. 일정형 AUTO는 접어도 보이게 하는 안을 권장한다.
- 기간형을 "이번 달 기간 일정" 한 영역으로 합친다. 행마다 '자동'/'직접' 출처 라벨을 붙인다.
- 홈 가족 카드 = 7일 안의 USER + **연결된 AUTO 예약 + 지원금 마감**. 출처 라벨을 붙인다.

**필요 데이터/기능**: 데이터 변경은 없다(`assigneeMemberId` 이미 있음). 표시 문구 승인(기존 운영 방식). 스위치 상태는 localStorage(기존 `CAL_CATCOLOR_KEY` 방식). 알림은 B7 서버 결정 이후다.

**다른 메뉴와의 연결**: 홈(가족 카드), 일정 등록(담당 선택), 자동 일정(일정형 AUTO), 계정·가족 초대(구성원 칩의 출처).

**우선순위**

| 개선 | 우선순위 | 크기 |
|---|---|---|
| 담당 표시(카드·상세) + 폼 담당 선택 복원(메뉴 ③과 같은 작업) | P0 | S |
| '전체' 보기 자동 항목 접기 스위치 | P1 | S |
| 홈 가족 카드에 AUTO 일정형 포함 | P1 | M |
| 기간형 두 영역 합치기 | P1 | M |
| 담당자·가족 알림(B7) | P2 | L(서버 결정) |

**문제점**

1. 입력이 타이핑과 탭 중심이다. 대표 일정 하나에 탭 약 16회가 든다. 지침 §6 "타이핑이 기본 UX가 아니다"와 어긋난다.
2. 담당을 입력할 수 없다(메뉴 ②의 문제 1). '등원·하원 픽업'·'학원 라이딩' 칩은 담당 강조(`needsAssignee`)를 하도록 되어 있지만, 강조할 담당 칸이 없어서 동작하지 않는다(`app.js:4560-4567`).
3. 계정 모드 폼에는 빠른 칩이 없다. 비계정 빠른 칩의 '예방접종'은 AUTO와 연결되지 않아 중복을 만든다.
4. 계정 모드에서는 2주 반복을 새로 만들 수 없다. 매월 반복은 규칙에서 지원하지 않는다(비활성 칩만 보인다).
5. 시간 휠이 '시' 1칸씩만 움직여서 오후 시각을 넣는 데 탭이 많이 든다.
6. 제목 자동값이 카테고리 이름이라 구체적인 제목(치과·소아과·피아노)을 쓰려면 결국 타이핑해야 한다.

**개선 UX**

- ＋ 시트 첫 화면을 **"말하기 / 사진 / 붙여넣기 / 직접 입력"** 4타일로 바꾼다. 음성과 사진은 P0 결과가 나올 때까지 '붙여넣기'(카톡·문자 문장)로 같은 파서와 확인 화면을 먼저 연다. 이 경로는 서버도 앱 재배포도 필요 없다.
- 확인 화면은 계획서 §5대로 한다. found는 읽기만, confirm과 missing만 강조, 저장은 1탭. 대상 아이는 등록 이름 사전으로 보정한다.
- 직접 입력 폼을 줄인다.
  - 카테고리를 누르면 **세부 제목 칩**(병원·검진 → 소아과·치과·안과·이비인후과)이 나와서 타이핑을 없앤다.
  - 시간은 **자주 쓰는 시각 칩**(오전 10시·오후 2시·오후 3시·오후 4시, 최근 사용 시각 우선)과 휠을 함께 둔다.
  - **담당 칩**("누가 데려가나요?" 나·배우자·조부모, 아이 일정에도)을 복원한다.
  - '예방접종'·'병원·검진'을 고르고 그 아이에게 미완료 AUTO가 있으면 "이 접종 말인가요?" 후보 1줄을 보여 준다(누르면 autoRef 연결 폼).
- 반복은 계정 모드에 '2주마다'를 노출한다(규칙은 이미 지원, interval 2). 매월 반복은 규칙 변경이 필요하므로 사용자 결정 사항이다.

**필요 데이터/기능**: `js/capture/*`(계획서 §3), `parseKoDateTime`, draft-view, 플래그 2개, 세부 제목 사전(정적 JSON, 카테고리별 4~6개), 최근 시각 기억(localStorage), 담당 칩 마크업(필드·규칙 변경 없음), AUTO 후보 조회(`CalendarModel.isLinkableAuto` 재사용).

**다른 메뉴와의 연결**: 자동 일정(후보 연결·추천일), 가족 캘린더(담당 표시), 홈(일정 추가하기), 어디갈까(장소 → 방문 일정, `places-view.js`에는 담당 칩이 이미 있다(369행). 같은 패턴을 재사용할 수 있다).

## 요약(6줄)

1. 36개월 미만 달력에는 정보·관찰형 AUTO(이유식·안전·발달 등)가 행동형보다 많이 찍힌다(6개월 9:16, 18개월 4:16 추정). 설계서 §7-D와 어긋난다.
2. AUTO와 일정 연결은 접종·검진·치과 4종뿐이다. 지원금 마감·예비소집·생일·연례 접종·'예방접종' 칩 일정은 자동으로 만들 수 있는데도 부모가 입력한다(목록 10건).
3. 담당 지정이 계정 모드 폼과 카드·상세에서 빠져 있다. 아이 일정에 배우자를 담당으로 둘 수 없어 가족 전달 부담이 남는다(P0/S).
4. 홈 가족 카드는 AUTO를 빼고, 기간형은 AUTO/USER 두 영역으로 나뉘며, '직접 입력만 보기'는 아이 칩을 골랐을 때만 쓸 수 있다.
5. 일정 등록은 직접 입력뿐이고 대표 일정 하나에 탭 약 16회가 든다. 사진·음성은 미구현이고 받는 쪽(VOICE/OCR 규칙, I8, normalizeFromCandidate)만 준비되어 있다.
6. 음성의 선행 조건은 iOS 홈 화면 웹앱(standalone)에서 Web Speech 동작을 실기기로 확인하는 것(P0)이고 Info.plist 권한 위치도 추가확인이 필요하다. 그 전에도 붙여넣기 → 공통 파서 → 확인 화면(P1)은 서버 없이 먼저 출시할 수 있다.
