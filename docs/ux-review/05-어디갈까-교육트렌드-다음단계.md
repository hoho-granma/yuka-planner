### (B) 현황
**노출 조건·기본값**
- 탭 노출: 가구 기능(`hhEnabled`)이 켜지면 '기록' 탭 자리에 노출 — `js/app.js:3084-3095`(applyTabLayout). 기능 플래그 기본값 ON(`js/feature-flags.js` household·accounts true) → 사실상 **모든 사용자에게 항상 노출, 나이 제한 없음**(임신 중 포함). 36개월 이상 4탭 구성에도 포함(`js/app.js:1286-1300`).
- 나이 기본값: **자동 적용됨**. `placesViewHtml`이 `ChildTimeline.completedMonths`로 월령을 넘겨 `Places.filterPlaces`의 `ageFits`로 거름 — `js/app.js:3158-3168`, `js/places.js:144-152`. 단 장소 `ageMonths`가 null이면 무조건 통과(`js/places.js:148`)라 **실질 효과는 6곳에만** 있음. 임신 중이면 나이 필터 없음.
- 지역 기본값: **필터로는 적용되지 않음**. `filterPlaces`는 province/district 필터를 지원하지만(`js/places.js:161-176`) 호출부가 province·district를 넘기지 않음(`js/app.js:3164`). 대신 시·군·구청 좌표(`data/district-offices.json`, 230곳 전국)를 기준점으로 **가까운순 정렬**만 기본(`js/app.js:3162-3166`, `js/places.js:242-248`). 즉 "우리 지역"이 아니라 "전체 77곳을 우리 구청에서 가까운 순".
- 화면 상단에 아이·지역 표시 없음(`index.html:228-231`의 제목 "어디갈까?"만). `TEXT.change`("바꾸기")는 정의만 있고 쓰이지 않음(`js/places-view.js:56`).

**필터 수**
- 분류 칩 8개(전체 + 7분류) — `js/places.js:17-25`, `js/places-view.js:144-154`. **키즈카페·실내 놀이 2분류는 데이터 0곳**(빈 칩).
- 필터 시트: 거리 4(전체/30/60/90분), 정렬 2(가까운순/인기순), 조건 3(실내/무료/예약 없이) — `js/places-view.js:157-184, 219-232`. 합계 기본 노출 8 + 시트 9.
- 지침 §8이 요구하는 "오늘/이번 주말" 조건 없음.

**인기순**: 장소별 [일정 등록] 완료 수(`placeStats`, 기기당 하루 1회)로 정렬 — `js/app.js:3123-3157`, `js/places.js:237-248`. Firestore 규칙은 주석상 "**P4 초안 — 배포 전**"(`firestore.rules:389-399`). 실제 배포 여부 **추가확인 필요**(미배포면 읽기 실패 → 빈 값 → 가까운순과 같음).

### 문제점
1. **[지역] "우리 지역" 기본값이 사실상 없음.** 데이터 범위(서울·경기 일부) 밖 사용자(예: 부산)도 77곳이 모두 보이고, 카드에 "차로 약 수백 분"이 표시될 수 있음(직선거리×1.3÷30km/h 추정, `js/places.js:203-217`). 데이터가 없는 지역이라는 안내도 없음. 설계서 §13("기본값 우리 지역 + 우리 아이 나이") 미충족.
2. **[나이] 나이 필터가 이름만 있음.** 92%가 나이 미확인이라 0개월 아기에게도 거의 전부가 "맞는 곳"으로 보이고, 카드마다 "권장 나이: 방문 전 확인"이 반복됨 → 판단 부담이 부모에게 그대로 넘어감.
3. **[분류] 빈 분류 칩 2개**(키즈카페·실내 놀이). 누르면 항상 "조건에 맞는 곳이 없어요"(`js/places-view.js:20`).
4. **[편집 추천 표기 누락]** F0 §7은 "편집 추천" 표기를 요구하나 화면에 표시되지 않음(데이터 `label`을 읽는 코드 없음). 정렬 이름은 "인기순"(`js/places-view.js:32`)인데 데이터 검증은 '인기' 단어를 금지(`js/places.js:34-36`) — 표기 원칙이 엇갈림.
5. **[인기순 표본]** 최소 표본 기준 없이 등록 수 1~2건으로 순서가 바뀜. 교육 트렌드의 "표본이 부족하면 보여주지 않는다" 원칙과 불일치. 조작 방지 불가는 규칙 주석이 이미 인정(`firestore.rules:391`).
6. **[아이·지역 표시 없음]** 무엇을 기준으로 추렸는지("은찬 3개월 · 구로구 기준") 보이지 않아 "왜 이게 보이지"를 알 수 없음(지침 §3 "왜 지금 보이는지").
7. **[시기 조건 없음]** "오늘/이번 주말 열린 곳" 판단 불가(휴관일 데이터 필드 없음 — notice 문자열에만 일부).
8. **[노출 시점]** 임신 중에도 탭이 보이지만 산전 교실 등 임신기 장소 데이터 없음(F0 §4 "산전 교실·출산 준비(후순위)").
9. **[재방문 변화 없음]** 다녀온 곳·일정 잡은 곳 표시 없음, 월령이 바뀌어도 나이 데이터가 없어 목록이 거의 같음.

### 개선 UX
- **상단 기준 줄**: "은찬(3개월) · 구로구 기준 · 편집 추천" + [바꾸기](다른 아이·다른 지역 임시 변경). F0 §7 화면 설계 그대로.
- **지역 기본값 = 같은 시·군·구 → 인접(차로 30분) 순 단계 노출**: 1구역 "구로구 안" → 2구역 "차로 30분 안" → 그 밖은 접힘. 데이터가 없는 지역은 빈 목록 대신 "○○구는 아직 준비 중이에요. 가장 가까운 곳은 차로 약 N분이에요" 한 줄(수백 분 카드 나열 금지).
- **나이 표기 3단계**: ① 공식 표기(현재 6곳) ② **유형 기준 안내**(조사 결과: 박물관 "36개월 이상 권장", 놀이시설 "36개월 미만 성인 동반", 도서관 "하한 없음") — 공식 값과 구분해 "시설 유형 기준" 라벨 ③ 둘 다 없으면 "방문 전 확인". 나이 필터는 ①은 제외 기준, ②는 정렬 감점·안내 문구로만(추측 값을 제외 기준으로 쓰지 않음).
- **빈 분류 칩 숨김**(데이터가 0곳인 분류는 칩을 그리지 않음 — '예약 없이' 칩과 같은 방식, `js/places.js:200`).
- **조건 단순화**: 기본 노출은 분류 칩 + "실내/무료" 2개, "이번 주말" 칩은 휴관 데이터가 생긴 뒤에만.
- **"인기순" → "가까운순" 단일 기본**, 등록 수 정렬은 최소 표본(예: 장소별 N가구 이상) 기준 확정 후에만 "가족들이 일정에 많이 넣은 곳" 같은 사실 표현으로.
- **재방문**: 일정에 넣은 장소에 "일정 있음 10/11(토)" 배지, 지난 일정 장소는 "다녀옴" 표시.

### 다른 메뉴와의 연결
- **홈 요약**: 설계서 §15 ⑥. 주말 전(목·금)에 "이번 주말 은찬과 갈 만한 곳 3곳" 한 줄 카드 → 어디갈까 필터된 목록. 비 오는 날 실내 우선은 날씨 데이터 필요(**추가확인 필요**, 현재 없음).
- **정보→행동→일정**: 장소 상세 → (예약 필요 시) 공식 예약 → 일정 등록(이미 구현) → 가족 캘린더 담당자 지정(구현) → 길찾기(구현). 빠진 고리는 "예약 필요" 장소에서 **예약 완료 확인 후 등록** 순서 안내.
- **월령 정보/검진**: 육아종합지원센터·장난감도서관(데이터 다수)은 "월령 정보 → 지역 기관" 연결 대상(지침 §12 "교육 지역 확인 → 기관/장소").
- **다음 단계 안내**: 36개월 전환 시 "이제 갈 수 있는 곳(박물관 어린이관 등)" 연결 가능.

### '데이터가 부족하면 억지로 통계를 만들지 않는다' 원칙 점검
| 점검 | 결과 |
|---|---|
| 평균·순위·비율 등 수치를 만들어 내는가 | **준수.** 수치 생성 코드 없음, 상태 배지만 '데이터 부족'(`js/edu-trend.js:2-7, 26-29`) |
| 표본 기준이 있는가 | 준수(30/100 초안). 단 사용자 승인 전 값(**추가확인 필요**: 승인 여부) |
| 화면이 통계가 있는 것처럼 보이는가 | **부분 위반 소지.** 회색 막대 자리표시(`.a36t-ghost`, `css/style.css:1586-1588`) 4칸이 "곧 그래프가 나온다"는 인상. 과목명(영어·수학)까지 미리 확정해 보임 |
| 안내가 사실과 맞는가 | **불일치.** "데이터가 모이면 여기에 나와요"·"표본이 일정 수 이상 모이면 '참고용'으로 바뀌어요"(`js/over36-view.js:99-102`)와 "지금은 통계용으로 수집하지 않아요"(`js/over36-view.js:107`)가 한 화면에 공존 → 수집 자체가 없으므로 **기다려도 채워지지 않음**. 기대만 만드는 문구 |
| 데이터 없는 메뉴를 고정 탭으로 노출하는가 | 원칙의 정신과 충돌. 3세 이상 모든 아이에게 하단 탭 한 칸을 주지만 정보 가치가 있는 영역은 '내가 입력한 학원 목록'뿐 |

**판정**: 숫자를 지어내지 않는다는 핵심은 지켰다. 그러나 "부족하면 만들지 않는다"를 화면 차원에서 보면, 채워질 계획이 없는 자리(막대·과목 칸·'모이면 나와요')를 만들어 둔 것은 **억지로 통계 틀을 보여주는 쪽**에 가깝다.

### 문제점
1. 공공 데이터(W6 후보 1·2: KESS·학교알리미 — 전수라 표본 문제 없음)조차 아직 없어 **보여줄 정보 0**.
2. 3세부터 탭 노출이지만 지역 교육 트렌드의 핵심 대상은 초등(설계서 §6·§14). 3~5세 "취학 전" 화면도 학원·영어·수학 칸이 동일.
3. 위 원칙 점검의 문구 불일치·자리표시 막대.
4. [학원 일정 추가]가 LESSON·아이 대상을 미리 고르지 않아 입력 부담 + 반영 실패 가능.
5. 지역·학년 바꾸기 없음(형제 비교는 아이 칩 전환으로만).
6. 다음 행동(지역 학원·기관 확인 → 상담 일정)이 없음 — 정보→행동 연결 끊김.

### 개선 UX
- **단계별 노출**: 초등(학년 1~6)은 탭 유지, 3~6세 취학 전은 탭 대신 홈/다음 단계 안내 안의 "교육 시작 고민" 카드로(데이터가 생기면 승격). 결정은 사용자에게.
- **빈 틀 제거**: 공공 데이터가 생기기 전까지 ③ 트렌드 4칸·막대 자리표시를 숨기고, ② 또래 범위는 "지금은 통계를 모으지 않아요. 동의 기능이 생기면 알려드릴게요"처럼 **현재 사실만** 한 줄.
- **1차 = 공공 기본 정보 카드**(W6 데이터구조 §1): "구로구 초3 학급당 학생수 N명 · 교육기본통계 2025 · 공공누리" + 출처 배지. 소규모 셀은 "표시하지 않아요".
- **우리 아이 현재 상태** 강화: 학원 일정 요약(요일·주 N회·총 시간)을 가족 캘린더에서 자동 집계, 입력 버튼은 LESSON·이 아이 대상으로 미리 채움.
- **행동 연결**: 공공 '지역 학원 수(분야별)' 카드 → (나중) 지역 학원 목록/상담 일정 추가.

- **행동 연결**: 시트에서 신청 링크 칩(`applyOf`), "이 시기 일정으로 넣기" → 항목별 체크 → 날짜 제안(FIXED/PERIOD/NONE, 지어내지 않음, `js/next-stage.js:66-86`) → 가족 캘린더 일괄 저장(`js/app.js:2990-3037`). 가족 캘린더 연결 없으면 안내 문구.
- 모든 창 길이는 "제품 제안값"(정책 파일 `_windowMonths`·`windowBasis`).

### 문제점
1. **초등 단계 없음** — 설계서 §12 "초등→다음 학년", 지침 §10 예시 4개 중 하나 미구현. 초등 아이에게는 배너가 영영 나오지 않음.
2. **'고민' 대신 '할 일'만**: 항목이 기존 todo/지원금 id로 한정돼 일정화 가능한 것만 다룸. 설계서 §12 예시 "5세→초등 준비", 지침 §10 "4~5세→교육 선택", "30개월→36개월 이후 변화"(예: 36개월 이후 자동 일정이 줄어든다는 변화 자체, 어린이집→유치원 선택)가 없음. TO_6_7은 이름은 "6~7세"지만 내용은 접종 3개뿐.
3. **노출 공백이 김**: 0~33개월 사이 대표 전환점(예: 돌 무렵) 없음, 36~69개월 33개월간 공백. 유치원 입학 모집 시기 등 3~5세 결정 이벤트 미포함(시기 근거 **추가확인 필요**).
4. **TO_SCHOOL 1월 공백**: 예비소집(12~1월)을 포함하지만 배너는 12/31에 꺼짐.
5. **홈 맨 아래 배치**: 설계서 §15 ⑤에 해당하나, 홈 내용이 길면 배너가 스크롤 끝에 묻힘. 노출 여부(본 적 있는지) 기록 없음.
6. **TO_3_5 시점**: 영유아검진 6차(42~48개월)는 33개월 시점에서 9~15개월 뒤 — "몇 개월 안" 기준에서 먼 항목이 같이 나옴(지침 §10 "너무 먼 미래를 모두 보여주지 않는다"와 경계).
7. 계정 모드에서만 동작(`js/app.js:2943`) — OFF 경로 사용자는 없음(현재 기본 ON이라 영향 작음).

### 개선 UX
- 배너를 "곧 바뀌는 것" + "지금 결정할 것" 2줄 구조로: "36개월부터 달라져요: 유아학비로 바뀌고, 자동 일정이 필수 항목만 남아요" + [미리 알아보기].
- **정보형 항목 허용**: 일정화 대상이 아닌 '변화 안내'(dateMode 없음, 일정 버튼 없음)를 항목 유형으로 추가 — 정보는 보여주되 자동 일정은 필수·시기성만(설계서 §7-D).
- **초등 단계 추가**: 학년 전환(2~3월: 새 학년 준비·방과후·돌봄 신청 시기 등, 근거 **추가확인 필요**), 5~6학년→중학교 배정.
- **3~5세 교육 선택 단계**: "유치원/어린이집 결정" — 모집 시기 공식 근거 확보 후.
- TO_SCHOOL 창을 SC-02 끝(1월)까지 연장하거나 1~2월 "입학 직전" 단계 분리.
- 홈 배치는 홈 전체 순서 결정(설계서 §15) 때 함께 — "이번 달 챙길 것" 아래, 가족 일정 위 후보.

## 4. 세 메뉴 공통 관찰
- **"표본·근거가 없으면 보여주지 않는다"의 적용이 메뉴마다 다름**: 교육 트렌드(엄격) / 어디갈까 인기순(기준 없음) / 다음 단계(근거 없는 값은 '확인 필요' — 양호). 하나의 표기 원칙으로 맞출 것을 제안.
- **노출 연령 기준이 제각각**: 어디갈까(항상) · 교육 트렌드(36개월~) · 다음 단계(단계별 창, 공백 큼). 설계서 §5 내부 단계(임신/0~12/12~36/3~5/6~7/초등)로 각 메뉴의 "단계별 역할"을 한 표로 정리하면 홈 순서 결정에도 쓸 수 있음.
- **지역**: 다음 단계는 지역 미사용, 어디갈까는 지역이 정렬에만, 교육 트렌드는 제목에만 — 설계서 §4 "지역" 개인화가 세 메뉴 모두 약함.
