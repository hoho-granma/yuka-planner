# F0 한눈육아 최종 서비스 설계 (시나리오 기준본)

작성: 2026-10-02 · 상태: **결정 3건 반영(§10), 구현 순서 사용자 확인 대기** — 이 문서의 시나리오(S1~S9)와 단계(§9)가 구현·테스트·진행률의 기준이다. 운영 규칙은 [운영규칙](한눈육아-운영규칙.md).
이전 문서와의 관계: [확장설계 v1](한눈육아-확장설계-v1.md)(데이터 구조) · [D0 회원가입 시나리오](한눈육아-D0-회원가입-사용시나리오.md)(구현 완료) · [E0 챙길 것/일정 분리](한눈육아-E0-챙길것-일정-분리.md)(계획, 이 문서 §9의 1단계로 흡수).

## 1. 한 줄 정의
**우리 가족 일정을 한눈에 보는 캘린더.** 예비·초보 부모에게는 챙겨야 할 것을 자동으로 알려 주고 신청까지 이어 주며, 아이가 크면 어린이집·학원·픽업·부모 약속을 가족이 함께 보는 캘린더가 된다. 일정은 손으로 적지 않아도 사진 한 장, 추천 장소 한 번 누르기로 들어간다.

## 2. 핵심 개념 — 세 가지가 하나의 캘린더로 모인다
| 개념 | 뜻 | 예 | 달력에서 |
|---|---|---|---|
| **챙길 것** | 기한 안에 하면 되는 일(앱이 자동으로 알려 줌) | 접종, 영유아검진, 지원금 신청 | 옅은 칩 + 달력 위 "이번 달 챙길 것 N개" |
| **일정** | 날짜·시간·담당이 정해진 일 | 소아과 예약, 학원, 픽업, 엄마 약속 | 구성원 색의 꽉 찬 칩 |
| **갈 곳** | 아직 일정이 아닌 후보 | 키즈카페, 공원, 체험 | 캘린더에 없음. "일정 추가"를 누르면 일정이 됨 |

일정이 만들어지는 길은 네 가지이고, 저장되는 모양은 하나다(기존 `schedules` 문서).
1. **자동**: 챙길 것에서 "예약 일정 만들기" → 일정 (구현됨, autoLink)
2. **직접 입력**: + 버튼 → 일정 추가 (구현됨)
3. **사진**: 가정통신문·학원 시간표를 찍으면 일정 후보가 나오고, 확인 후 저장 (신규)
4. **어디갈까**: 추천 장소의 "일정 추가" (신규)

## 3. 화면 구조
하단 탭 5개(개수 유지, 한 자리 교체):

| 탭 | 역할 | 변경 |
|---|---|---|
| 홈 | 오늘·이번 주 요약. 아이 나이에 따라 순서만 바뀜 | 순서 전환 |
| 캘린더 | 가족 일정 + 챙길 것 | 달성률 카드 제거, "이번 달 챙길 것" 줄 |
| 체크리스트 | 월령별 챙길 것 전체, 달성률은 여기에만 | 유지 |
| 육아 혜택 | 지역·나이 맞춤 지원금 | 유지 |
| **어디갈까** | 나이·지역 맞춤 갈 곳 큐레이션 | **신규(기록 탭 자리)** |

- **기록**은 프로필(내 정보) → "기록 보기"로 옮긴다. 기능은 그대로.
- **+ 버튼**: 일정 추가 / **사진으로 등록** / 아이 등록하기 / 가족 초대하기.
- **캘린더 위 구성원 줄**: 전체(기본) · 나 · 가족 구성원 · 아이들. 아이만 고르면 "직접 등록한 일정만 보기", "카테고리별 색깔 다르게 하기".

## 4. 사용자 단계별로 달라지는 것 (모드 설정 없음, 기본값만 자동 전환)
| 단계 | 홈 첫 화면 | 캘린더 | 어디갈까 |
|---|---|---|---|
| 예비 부모 | 출산 전 챙길 것, 출산 예정일 | 챙길 것 중심 | 산전 교실·출산 준비(후순위) |
| 0~36개월 | 이번 달 챙길 것(마감 임박, 신청 버튼) → 가족 일정 | 챙길 것 + 가족 일정 | 영아 동반 가능한 곳 |
| 36개월~초등 | 오늘·이번 주 우리 가족(누가 픽업) → 챙길 것 | 가족 일정 중심(구성원 색) | 체험·교육·키즈카페·공원 |

아이가 여럿이면 가장 어린 아이 기준. 전환 기준은 36개월.

## 5. 시나리오 (구현·진행률 기준)
- **S1 가입과 가족 만들기** — 회원가입(자녀 유무·역할·선택 주소) → 홈. 가족 코드로 합류. *(구현 완료, 실기기 확인 중)*
- **S2 아이 등록과 자동 챙길 것** — 아이(또는 출산 예정일)를 등록하면 월령에 맞는 챙길 것이 캘린더·체크리스트에 나온다. *(구현 완료)*
- **S3 챙길 것을 일정으로** — 캘린더 위 "이번 달 챙길 것"을 펼쳐 항목마다 [예약 일정 만들기]·[신청하러 가기]·[완료]. 예약하면 가족 일정이 되고 옅은 칩은 사라진다. *(연결 기능은 구현됨, 화면은 신규)*
- **S4 가족 일정 공유** — 각자 로그인해 일정을 등록하면 구성원 색으로 모두에게 보인다. 기본은 전체 보기. *(구현 완료, 기본값만 변경)*
- **S5 누가 픽업·라이딩** — 자주 쓰는 일정(등원·하원 픽업, 학원 라이딩)을 담당자와 함께 두 번 누르기로 등록, 반복 일정. *(반복·담당자는 구현됨, 빠른 입력 신규)*
- **S6 나이에 따라 바뀌는 홈** — §4의 순서 전환. *(신규)*
- **S7 사진으로 일정 등록** — + → 사진으로 등록 → 촬영 또는 앨범 → 일정 후보 목록(제목·날짜·시간·대상) → 고치고 선택 → 저장. 확인 없이 저장되지 않는다. *(신규, §6)*
- **S8 어디갈까** — 탭을 열면 아이 나이·사는 지역에 맞는 장소가 분류별로 나오고, 장소마다 [일정 추가]를 누르면 날짜만 고르면 되는 일정 폼이 열린다. *(신규, §7)*
- **S9 기록 보기** — 프로필 → 기록 보기에서 기존 성장·활동 기록을 본다. *(이동만)*

### S3 보충 — "신청하러 가기" 링크 현황 (조사 2026-10-02)
- 지원금 데이터의 공식 링크 172개 중 죽은 링크는 1개(제주 JJ-005)뿐이지만, **신청 화면으로 바로 가는 링크는 하나도 없다.** 모두 안내·보도·생활법령 페이지이고 실제 신청은 복지로·정부24 로그인 뒤에 한다.
- 접종·검진 같은 자동 항목(`data/todos`)에는 링크 필드가 아예 없다.
- 따라서 1단계에서 **신청용 링크 필드를 따로 두고**, 전국 공통 항목(부모급여·첫만남이용권·아동수당·양육수당·보육료)은 복지로 서비스 상세 페이지로, 접종은 예방접종도우미, 검진은 건강보험공단 안내 페이지로 채운다. 버튼 이름은 로그인 후 신청이 이어지는 항목은 "신청하러 가기", 안내만 있는 항목은 "안내 보기"로 구분한다.

## 6. 사진으로 일정 등록 (S7) 설계
**흐름**: 사진 선택 → 글자·일정 인식 → **확인 화면**(후보마다 체크, 제목·날짜·시간·대상 수정 가능, 원문에 없는 연도·요일은 비워 두고 사용자가 채움) → 저장.
**이미 준비된 것**: 일정 문서에 `sourceType: "OCR"`, `provenance.confirmedByUser`가 있고, 서버 규칙이 "확인 없는 OCR 저장"을 거부한다. 원본 사진은 저장하지 않는다(기존 원칙).

**인식 방식 — 결정 필요**
| 방식 | 품질 | 비용·준비 | 개인정보 |
|---|---|---|---|
| A. 기기 안에서 글자만 인식(오픈소스 OCR) + 규칙으로 날짜 찾기 | 한글 가정통신문에서 낮음. 표·손글씨에 약함 | 무료, 서버 없음 | 사진이 기기를 떠나지 않음 |
| B. AI 비전 모델로 사진에서 바로 일정 추출 | 높음(표·여러 일정·맥락 이해) | **서버(중계 함수)와 API 요금 필요.** 지금 앱은 정적 사이트라 Firebase Functions(유료 요금제) 또는 Cloudflare Workers 추가 | 사진이 외부 AI로 전송됨 → 동의 문구 필요, 저장 안 함 |
| C. 휴대폰 기본 기능으로 글자를 복사해 붙여넣으면 일정으로 풀어 줌 | 중간(사용자 손이 한 번 더 감) | 무료, 서버 없음 | 텍스트만 다룸 |

추천: **B를 목표로 하되 1차는 C로 확인 화면·저장 흐름을 먼저 만든다.** 확인 화면과 저장 구조는 A·B·C가 같아서 버리는 작업이 없다. B는 서버·요금 결정이 난 뒤 붙인다. 로그인한 사용자만 쓰게 해 남용을 막는다.

## 7. 어디갈까 (S8) 설계
**화면**: 상단에 아이·지역 표시(바꿀 수 있음) → 분류 칩(공원·키즈카페·체험·교육·도서관·박물관·실내 놀이) → 장소 카드(이름, 한 줄 설명, 권장 나이, 실내·실외, 예약 필요 여부, 공식 링크, **[일정 추가]**).
**일정 추가**: 제목=장소명, 장소 채움, 대상=가족 전체로 일정 폼이 열리고 날짜만 고르면 저장(기존 일정 구조 그대로, 규칙 변경 없음).

**장소 데이터 — 결정 필요**
| 출처 | 장점 | 한계 |
|---|---|---|
| A. 직접 큐레이션(앱 안 JSON, 지역×나이×분류) | 품질·톤 통제, 육아지기 콘텐츠(여행릴스 등)와 연결 가능 | 지역을 넓힐수록 관리 부담, 운영시간·폐업 변동 |
| B. 공공데이터(관광공사·지자체 공원·도서관·체험시설) | 전국 범위, 무료 | 키즈카페 등 민간 시설 없음, 품질 편차 |
| C. 지도 서비스 장소 검색(카카오·네이버) | 최신·방대 | API 키·호출 제한·약관(저장 금지 등), 서버 필요할 수 있음 |

추천: **1차는 A(직접 큐레이션)로 시작 지역 한두 곳**, B로 공원·도서관을 보강. "사람들이 자주 가는 곳"은 실제 이용 통계가 없으므로 처음에는 **"편집 추천"으로 표기**하고, 나중에 앱 안의 일정 추가 수로 바꾼다(가짜 인기 표시는 하지 않는다). 장소 항목마다 확인 날짜를 두고 오래된 것은 표시한다.
**장소 항목 필드(안)**: id, 이름, 분류, 시·도/시·군·구, 권장 나이(개월 범위), 실내·실외, 비용 구분, 예약 필요, 주소, 공식 링크, 한 줄 설명, 확인 날짜.

## 8. 데이터·서버 영향 요약
- 계정·가족·아이·일정 구조는 지금 그대로 쓴다. S3~S6, S8, S9는 **서버 규칙 변경 없음.**
- S7의 B 방식만 새 서버(중계 함수)와 비용이 생긴다.
- 어디갈까 장소는 Firestore가 아니라 앱에 포함된 데이터 파일로 둔다(지원금 데이터와 같은 방식).
- 가족 캘린더·계정 기능을 모든 사용자에게 켜는 시점은 별도 결정(지금은 켠 사람만 보임).

## 9. 구현 단계와 진행률 기준
| 단계 | 내용 | 시나리오 | 비중 |
|---|---|---|---|
| 0 | 계정·가족 합류·칩 달력 | S1, S2, S4 | 완료(실기기 확인 남음) |
| 1-1 | 캘린더 기본 선택을 전체로 | S4 | 5% |
| 1-2 | 캘린더 달성률 카드 → "이번 달 챙길 것" 줄(예약 일정 만들기·신청하러 가기·완료), 예약 연결 기본 켜기, 신청용 링크 채우기(전국 공통) | S3 | 30% |
| 1-3 | 홈 순서를 아이 나이에 따라 전환 | S6 | 20% |
| 1-4 | 픽업·라이딩 빠른 입력 | S5 | 10% |
| 2-1 | 기록 탭 → 프로필 "기록 보기" | S9 | 10% |
| 2-2 | 어디갈까 탭 껍데기: 화면·분류 칩·장소 카드·[일정 추가], "편집 추천" 표기, 예시 장소 몇 개(준비 중 안내) | S8 | 25% |
| 나중 | 사진·글자로 일정 만들기(S7, AI 인식 포함), 어디갈까 실제 장소 데이터(조사 지침 확정 후), 알림, 카카오·네이버 로그인, 구성원 전용 보안 강화, 계정 탈퇴 | — | 범위 밖 |

단계마다 개발 → 독립 검증(5분) → 커밋. push는 사용자가 지시할 때만.

## 10. 확정된 결정 (2026-10-02 사용자)
1. **사진 일정 등록(S7)**: 지금은 일정을 **직접 입력**으로만 받는다(붙여넣기 기능도 만들지 않음). 사진·AI 인식은 계획에 있으나 나중 일이라 3단계는 이번 범위에서 뺀다. + 메뉴에 '사진으로 등록'도 아직 넣지 않는다.
2. **어디갈까**: 처음에는 "편집 추천"으로 표기. 실제 장소 조사는 계획이 더 필요하므로 **화면 껍데기만** 먼저 만들고, 조사 에이전트는 장소를 조사하기 전에 **조사 지침부터** 세운다(`docs/한눈육아-어디갈까-조사지침.md`).
3. **단계 순서**: 1 → 2 (3단계는 나중).
4. (이전 확정) 알림은 나중. 캘린더 기본은 전체 보기, 36개월 이상도 월 보기 유지, 예약 연결은 가족 캘린더 사용자에게 기본 켬.

## 11. 하지 않는 것
- 가짜 인기 순위·후기 표시, 광고성 장소 추천.
- 확인 화면 없는 자동 일정 저장, 원본 사진 보관.
- 챙길 것 개수를 늘리기 위한 억지 항목 추가.
