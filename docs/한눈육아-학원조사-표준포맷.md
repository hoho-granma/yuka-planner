# 학원 조사 표준 포맷 (educationResearch `sections`)

학원 상세 창의 "학원 정보"에 보여줄 항목과 저장 형식을 정한다. 기존 `record`(마크다운 원문)는 DB에 그대로 두고, 화면은 `sections`만 읽는다.
운영 DB(`educationResearch`)에는 2026-10-12 사용자 승인으로 290개 문서에 `sections`·`phones`·`site`를 추가했다(아래 5절). 앱 화면은 클라이언트 배포 이후 보인다.

## 1. 화면 (사용자가 확인한 형태)

학원 이름 바로 아래에 "학원 정보"가 나온다(기관 종류·대상·과정·전화 줄은 없다. 기관 종류는 위 배지에 있다). 첫 줄은 위치(괄호 안 동·건물명은 아랫줄), 이어서 항목은 학부모가 가장 궁금해할 순서대로 7개다. 항목마다 한 줄 값 + 출처 성격 표시 + 근거 불릿(펼치지 않고 항상 보임). 자료가 없으면 "확인 안 됨" 한 단어만 쓰고, 7개 항목이 모두 없으면 7줄 대신 "조사 내용 | 확인 안 됨" 한 줄로 합친다.

| 키 | 화면 제목 | 담는 것 |
|---|---|---|
| `fees` | 수강료 | 월 수업료, 교재비·추가비·온라인비·셔틀비. 교육청 공개 교습비가 있으면 이 칸에 합친다(아래 참고) |
| `schedule` | 시간표 | 수업 요일·시작/종료·주 횟수·1회 분 (원문에 시간표가 없고 운영시간만 있으면 "운영 ○○"이라고 적는다) |
| `program` | 학년·과정 | 대상 학년, 레벨·반 체계, 개설 과정 |
| `levelTest` | 레벨테스트 | 필요 여부, 방식, 소요시간, 비용, 결과·유효기간, 예약 |
| `shuttle` | 차량 | 운행 여부, 요금, 노선·지역 |
| `method` | 수업방식 | 수업 진행 방식, 교재, 숙제·평가 방법 |
| `trial` | 체험·상담 | 체험수업 여부, 상담·예약 방법 (전화 응대 시간 포함) |

맨 아래에 "연락처" 줄이 붙는다: 라벨 옆에 전화번호가 한 줄로 나온다(교육청 등록 번호 + 조사 원문에서 이 학원 것으로 확인된 번호 `phones`, 합쳐 최대 2줄, 같은 번호는 한 번만. 눌러서 전화. 없으면 빈칸). 그 아래에 "공식 사이트 가기" 버튼(`site`: 공식 홈페이지 > 운영자 블로그 > 네이버 플레이스 순으로 이 학원 정보를 가장 잘 알 수 있는 한 곳, 새 탭으로 열림. 없으면 버튼 없음) + "조사한 내용은 ○○ 기준 공개 자료예요. 실제와 다를 수 있으니 자세한 내용은 학원에 직접 문의해서 확인해 주세요."
수강료 칸의 교육청 공개 교습비: 조사 수강료가 있으면 그 근거 첫 줄에 "교육청 공개 교습비: 고등영어A 300,000원 · …"로 붙이고, 조사 수강료가 없으면 이 값이 수강료 값(표시 `교육청 공개`)이 된다. 원본 `고등영어A:300000` 형태를 천 단위 쉼표와 "원"으로 바꿔 보여주며, 기간(월·회) 기준은 데이터에 없으므로 "월"을 붙이지 않는다. 별도 "공개 교습비" 섹션은 없다.
화면에서 뺀 것: 조사 원문·출처 보기 버튼, "과거 자료·기준일 불명…" 안내, "확인하지 못한 것" 문단, 별도 "공개 교습비" 섹션, 빈 후기 안내(후기가 있을 때만 표시), "상담에서 확인할 것" 목록, 위쪽 기본 정보(기관 종류·대상·과정·전화).

## 2. 문서 형식

```
educationResearch/{J10:기관ID}
  id, checkedAt, status, added, record, sources     ← 기존 필드 그대로
  sections: {
    fees|schedule|program|levelTest|shuttle|method|trial: {
      v:    string | null     // 한 줄 값. 확인된 내용이 없으면 null
      tag:  string            // 출처 성격. v가 null이면 ""
      more: string[]          // 근거 불릿 0~4개
    }
  }
  phones: [{ n: string, l: string }]   // 이 학원 것으로 확인된 별도 전화번호 0~2개(라벨 8자 안쪽). 없으면 []
  site: { u: string, l: string }       // 공식 사이트 한 곳(http/https만). 없으면 필드 없음
```

- `v`는 60자 안쪽(최대 80자), 핵심 사실을 " · "로 잇는다. 중요한 부분이 비면 끝에 "~는 확인 안 됨"을 한 번만 붙인다.
- `more`는 `v`에 없는 구체 사실만, 각 60자 안쪽.
- `tag`는 `지점 공식` / `본사 공통` / `운영자 블로그` / `네이버 플레이스` / `입학문의 폼` / `과거 글` / `지점 확인 필요` 중 하나. `지점 확인 필요`는 학원은 맞는데 그 값이 이 지점 몫인지 원문이 불확실하다고 한 경우이며 화면에서 값과 표시가 연하게(점선 표시) 나온다. 섞이면 가장 약한 쪽(지점 확인 필요 > 과거 > 본사 공통 > 블로그·플레이스·폼 > 지점 공식)으로 쓰고, 다른 성격의 값은 `more`에 "(본사 공통)"처럼 밝힌다.
- 값은 원문 그대로다. 외부 지식·추측·합산을 하지 않는다. 금액은 원문 표기 또는 정확히 나누어떨어지는 만원 단위만 쓴다.
- 원문이 "미확인·확인 못함·미판독"이라고 한 것은 사실로 쓰지 않는다. 항목 전체가 그러하면 `v: null`.
- 조사 과정 메모(탐색 시간, 판독 실패, 제외한 자료), 후기·성적 사례·합격률은 쓰지 않는다. URL·인용·출처 번호·전화번호도 쓰지 않는다.
- 학원 자체가 다른 곳일 수 있는 사실(동명이관 가능성, 출처와의 연결 보류, 다른 지점 값)은 쓰지 않는다. 학원은 맞지만 지점 몫이 불확실한 값은 쓰되 `지점 확인 필요`로 표시한다.
- 전화번호는 `v`·`more`에 쓰지 않고 `phones`에만 쓴다. 다른 캠퍼스·본사·앱 운영사·교사/기사 개인 번호와 연결이 불확실한 출처의 번호는 쓰지 않는다.
- 같은 사실을 두 항목에 중복하지 않는다. 레벨테스트 예약은 `levelTest`, 체험수업·일반 상담은 `trial`.

## 3. 만드는 법

원문 마크다운을 읽고 위 규칙대로 정리하는 일은 규칙·코드로 안 되고 모델이 읽어야 한다(규칙 기반 추출은 시안에서 시도했으나 읽기 불편한 결과가 나와 폐기했다). 정리 지시문은 `tools/education-sections-spec.md`. 10곳 안팎씩 나눠 서브에이전트가 정리하고, 결과를 자동 검증한다. 20곳 시험 결과는 `output/education-research-schema-dryrun/sample20.json`.

검증(전수): 항목 7개 모두 있음 / `tag` 값이 허용 목록 안 / `v` 길이 / `more` 개수 / URL·전화번호·"미확인" 표현이 없음 / 값에 나온 숫자가 원문에 실제로 있음.
검수(표본): 항목마다 원문과 대조. 특히 `null`이어야 할 곳에 값이 들어갔는지, 본사 공통·과거 글이 지점 값처럼 쓰이지 않았는지 본다.

## 4. 화면 코드 (`js/education-reference-view.js`)

- `sections`가 있는 문서만 이 화면을 쓴다. 없으면 기존 표시(요약 3줄 + 원문 접기)를 그대로 쓴다.
- 전화는 `directoryItems`의 `phone`(교육청 등록 번호)을 쓴다. 맨 아래 연락처에만 보이고, 위쪽 기본 정보 목록에서는 뺀다.
- 글자 크기: 값 15px, 항목 이름 13px, 근거 13px, 출처 성격 표시 11px. 홈·할일 메뉴의 14px/15px/10px 고정 규칙에는 영향이 없다.

## 5. DB 반영

- 저장 파일: 조사 폴더의 `education-sections.json`(정리 결과). `tools/build-education-research.py`가 기관 ID로 `sections`·`phones`·`site`를 합쳐 `firebase-import.json`을 만든다(정리 결과가 없는 기관은 필드를 붙이지 않고, 그 기관은 옛 표시로 나온다).
- `tools/import-education-research.py`는 문자열·참/거짓·목록에 더해 맵·null을 쓴다(`mapValue`/`nullValue`). 기존 동시변경 검사·백업(`.local-backups/`)은 그대로다. 사용: `--input <파일>`(이번 묶음만), `--new-only`, 쓰기 없이 변경 건수만 보려면 `--apply`를 빼고 실행.
- 2026-10-12 반영 완료: 입력 290곳(모두 기존 문서)에 새 필드 3개만 추가했다. 입력에는 `id`·`sections`·`phones`·`site`만 넣어 기존 필드(`record` 등)를 덮어쓰지 않았고, 재조회 290곳 일치, 같은 입력 재실행 시 변경 0, 쓰기 전후 기존 필드 변경 0을 확인했다. 쓰기 전 상태는 `.local-backups/firestore/education-research-20261012-191133/before.json`, 결과는 `output/education-research-schema-dryrun/sections-save-result.json`. 이후 새 기관의 정리 결과를 추가할 때도 같은 방식(`--input`에 새 필드만, 쓰기 없이 먼저 실행)으로 한다.
- `educationDirectory` 함수는 문서를 그대로 내려보내므로 함수·Firestore 규칙 배포는 필요 없다. 앱 화면은 클라이언트 배포(GitHub Pages, 커밋+push)가 필요하고, 배포할 때 `js/version.js`, `index.html`의 `education-reference-view.js?v=`·`education-research.css?v=`를 올려야 캐시된 옛 파일이 교체된다.
- 건수는 조사가 계속 진행 중이라 반영 직전에 다시 확인한다.
