# W6 교육 트렌드 데이터 구조 설계 (설계만 — 코드·데이터 구현 없음)

작성: hn_dev · 2026-10-04 · 근거: docs/한눈육아-W6-교육트렌드-공공데이터-후보.md, js/edu-trend.js, data/regions.json
방향(사용자 승인): ① 1차 = 공공 데이터로 지역×학년 기본 정보 카드 → ② 최종 = 지역+학년+교육영역+실제 사용자 집계 → ③ 지금은 구조만, 서버·집계 구현 없음.

## 1. 정적 공공 데이터 파일

**지역 키.** 앱은 지역을 한글 이름 쌍(`profile.province` = "서울특별시", `profile.district` = "구로구")으로만 안다(regions.json: 17 시도·230 시군구, 코드 없음). 그래서 파일 키도 `regionKey = "시도|시군구"`(앱 이름과 동일 문자열)로 두고, 공시 원본과 잇기 위한 `sigunguCode`(행정표준코드 5자리)는 **참고 필드**로만 둔다. 이름 불일치(통합 시·분구)는 빌드 단계의 매핑 표(`data/edu/region-map.json`)에서 흡수한다.

**파일 구성(시도 단위 분할 — 지원금 파일과 같은 방식).**
```
data/edu/_index.json            # 지표 정의·출처·기준연도·파일 목록(앱은 이것만 먼저 읽는다)
data/edu/region-map.json        # 앱 지역 이름 ↔ 공시 시군구 코드
data/edu/public/서울특별시.json  # 시도별 시군구×학년 값(약 20~60KB, 17개)
data/edu/public/_national.json  # 전국·시도 참고값(사교육비조사 등 시군구가 없는 지표)
```
sw 캐시: `data/*.json` 은 이미 sw 가 캐시하지 않는다(네트워크 우선) → 별도 sw 변경 없음. 앱은 지금 지역의 시도 파일 1개만 읽는다(지원금 `loadSubsidyDataForRegion` 패턴 재사용). 읽기 실패·파일 없음 = 카드 값 비움(현재의 "데이터 부족"과 같은 화면).

**값 스키마(시도 파일).**
```json
{ "schemaVersion": 1, "province": "서울특별시",
  "cells": [
    { "regionKey": "서울특별시|구로구", "grade": 3, "area": "SCHOOL",
      "metric": "classSize", "value": 22.4, "unit": "명/학급",
      "n": null, "suppressed": false,
      "source": "public", "sourceId": "KESS-2025", "baseYear": 2025, "baseDate": "2025-04-01" } ] }
```
- `grade`: 0(입학 전)·1~6(`ChildTimeline.gradeNumber` 와 같은 번호). 학년 구분이 없는 지표는 `null`.
- `area`(교육영역): `SCHOOL`(학교 현황) / `ACADEMY`(학원·교습소) 에서 시작, 사용자 집계 단계에서 `ENGLISH`·`MATH`·`SPORTS` 등 추가(§2).
- `metric` 은 `_index.json` 에 정의된 id 만(예: `studentCount`, `classSize`, `academyCount`). 정의에는 한글 라벨·단위·카드 문구 틀·`allowedGrades` 를 둔다.
- 값은 **원자료 그대로가 아니라 시군구로 집계한 숫자만**. 학교·개인 식별 정보 없음.
- **소규모 셀**: 집계 대상(학생 수·학원 수 등) 합이 기준(제안: 10 미만)이면 `value: null, suppressed: true` 로 쓰고 화면은 "표시하지 않아요"로 가린다. 합칠 수 있으면 상위(시도) 값으로 대체하지 않고 가림 처리(잘못된 지역 값을 보여 주지 않기 위해).
- **출처·라이선스**: `_index.json` 의 `sources[]` 에 `{sourceId, name, org, license("공공누리 제1유형" 등), url, baseDate, fetchedAt, note}`. 카드 하단에 `name · baseYear · license` 를 그대로 표시. **쓰지 않는 지표(사용 금지 목록)**: 학업성취·학교폭력·학교별 서열 가능 지표(근거 문서의 권고).
- 사교육비조사 등 시도 단위 표본조사 값은 `_national.json` 에만 두고 `scope: "province"|"national"` 로 구분한다(시군구 카드에 섞지 않는다).

## 2. 사용자 집계 확장 (같은 셀 스키마)

공공 셀과 사용자 집계 셀은 **같은 셀 구조**를 쓰고 출처 구분 필드만 다르다.
```json
{ "regionKey": "서울특별시|구로구", "grade": 3, "area": "ENGLISH",
  "metric": "participationRate", "value": 0.62, "n": 143, "distribution": {"1-2회": 0.4, "3회+": 0.22},
  "source": "user", "sourceId": "user-agg-2027Q1", "baseDate": "2027-03-31" }
```
- **`source`: `"public" | "user"`** 가 화면 구분 기준이다. 카드는 항상 출처 배지("공공 통계 · KESS 2025" / "한눈육아 가족 N가구")를 붙이고, 두 값을 한 숫자로 합치거나 같은 표에서 비교하지 않는다(공공=전수, 사용자=자발 응답 표본이라 성격이 다르다).
- **statusFor 와의 연결**: 지금 `statusFor(n)` 은 n<30 데이터 부족 / 30~99 참고용 / ≥100 충분. 이 규칙은 **`source:"user"` 셀에만** 적용한다(`n` 이 가구 수). `source:"public"` 셀은 전수 공시라 상태 배지 대신 "공시 기준 · baseYear" 를 보여 주고 statusFor 는 쓰지 않는다. 사용자 집계 셀은 n<30 이면 `value`·`distribution` 을 서버가 애초에 내보내지 않는다(앱 규칙이 아니라 집계 단계 규칙 — 앱 쪽 가림은 이중 안전장치).
- 화면 순서: ① 공공 기본 정보(항상) → ② 또래 범위(사용자 집계, 상태 배지) → 지금 `renderTrend` 의 카드 순서와 같은 틀에 값만 채운다.

## 3. 사용자 집계가 필요로 할 것 (지금 만들지 않음 — 목록만)
1. 동의 상태 저장 위치(제안: `accounts/{uid}.eduStatsConsent {v, at}` 또는 가구 단위 — 사용자 결정 필요)와 철회 시 이전 기여분 처리.
2. 집계 주체(제안: 클라이언트 직접 집계 금지 → 서버 함수가 동의한 가구의 학원 일정 `category=LESSON` 에서 영역·횟수만 뽑아 셀로 집계, 원본 일정은 읽기 전용).
3. Firestore 규칙 변경: 집계 결과 컬렉션(`eduStats/{regionKey}` 읽기 전용) 추가, 사용자 쓰기 불가. 동의 필드 쓰기 허용 규칙. → **규칙 배포 필요(사용자 배포)**.
4. 영역 분류 체계(학원 일정 제목 → 영역 매핑·자유 입력 처리), 최소 표본·소규모 셀 규칙(위 §2의 서버측), 개인 식별 방지(지역은 시군구까지만, 학년+지역+영역 조합에서 n<30 억제).
5. 개인정보 처리방침·동의 문구 갱신, 집계 데이터 보관 기간.

## 4. 지역 없는 계정·조기입학/유예
- **지역 없음**: 현재 제목이 `"{district||province} {grade} 교육 트렌드"` 라 지역이 비면 제목 앞이 비어 보인다. 구조상 `regionKey` 가 없으면 지역 카드는 만들지 않고 ① 제목은 학년만("초3 교육 트렌드"), ② 지역 필요 값 자리에 "지역을 설정하면 우리 동네 정보를 볼 수 있어요" + 프로필 지역 입력 진입 버튼, ③ 전국 참고값(`_national.json`, `scope:"national"`)만 "전국 기준"으로 표기해 보여 줄 수 있다.
- **조기입학·유예**: 카드의 학년은 `ChildTimeline.gradeNumber(birthDate, today, policy, {enrollmentYearOverride})`(W1 통일, 이미 반영)을 그대로 쓰므로 **아이가 실제로 다니는 학년**(예: 한 해 일찍이면 초2)의 셀을 가져온다. 공공 값은 "그 학년 전체"의 값이라 출생연도와 무관해 문제없다. 사용자 집계에서는 학년(재학 기준)으로 집계하므로 같은 규칙. 초등 밖(0·7)은 `inRange:false` 로 기존처럼 범위 밖 문구.

## 5. 구현 묶음 후보
| 묶음 | 내용 | 규모 |
|---|---|---|
| A. 스키마·로더 | `data/edu/_index.json`·`region-map`·셀 스키마 검증 테스트, `EduData`(순수 모듈: 파일 읽기 주입, regionKey·학년 조회, 소규모 셀 가림) | S |
| B. 공공 데이터 수집·빌드 | KESS/학교알리미 파일 → 시도 JSON 변환 스크립트(오프라인 실행), 지표 1~2개(학생수·학급당 학생수)부터, 출처 표기 | M(파일 컬럼·시군구 코드 확인 필요 — 조사 추가검증 항목) |
| C. 카드 화면 | `renderTrend` 에 공공 기본 정보 카드·출처 배지·지역 없음 처리, 사용자 카드의 `source` 배지 틀 | S~M |
| D. 사용자 집계(나중) | 동의·집계 함수·규칙 | L(규칙 배포·정책 결정 필요) |

**사용자 결정이 필요한 것(제안):**
1. 1차에 보여 줄 지표: 제안 = 학급당 학생수·학년별 학생수만(학교 서열화·성취 지표 제외). 학원 수(ACADEMY)는 B 이후 추가할지.
2. 소규모 셀 기준과 표시 방식: 제안 = 합 10 미만은 "표시하지 않아요"로 가림(상위 값으로 대체하지 않음).
3. 공공 값과 사용자 집계 값의 표시: 제안 = 항상 분리된 카드 + 출처 배지, 한 숫자로 합치지 않음. 사용자 집계가 쌓이기 전까지 "또래 범위" 카드는 지금처럼 '데이터 부족'.
