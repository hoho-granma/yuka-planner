# 역할별 DB 컬렉션 이전 — 2026-10-08

## 현재 기능에 맞춘 구조

| 경로 | 역할 | 저장 데이터 |
|---|---|---|
| children/{아이코드} | 아이 정보 | profile, completed, records 등 기존 필드 유지 |
| families/{가족ID} | 가족 공유 단위 | 가족 메타데이터 |
| families/{가족ID}/childLinks/{연결ID} | 가족과 아이 연결 | familyCode, displayName, order 등 |
| families/{가족ID}/members/{구성원ID} | 구성원·계정 연결 | 역할, 이름, uid |
| families/{가족ID}/schedules/{일정ID} | 가족 일정 | 기존 반복·예외·완료 데이터 유지 |
| families/{가족ID}/todos/{할일ID} | 가족 할일 | 기존 기한·카테고리·완료 데이터 유지 |
| familyInviteCodes/{코드} | 초대코드 조회 | 기존 householdId 필드 유지 |
| accounts/{UID} | 로그인 계정 | 기존 householdId/memberId 연결 유지 |
| placeUsageStats/{장소ID} | 어디갈까 이용 집계 | count, updatedAt |

컬렉션 이름만 변경하며 ID와 저장 필드 이름은 유지한다. 내부 HouseholdSync API·로컬 미러의 children 키·로컬 저장소 키도 유지한다. 오프라인 대기열의 구 경로는 읽을 때 새 경로로 변환한다. 계정의 householdId 필드까지 변경하는 것은 이번 이전 범위가 아니다.

## 기능별 별도 컬렉션 필요성

- 어디갈까 추천 원문: data/places.json을 계속 사용한다. 이용 집계만 placeUsageStats에 저장한다.
- 교육트렌드: 등록 학원은 schedules의 LESSON 일정을 읽는다. educationSchedules 같은 중복 컬렉션을 만들지 않는다. 지역 정보·콘텐츠는 기존 정적 데이터에서 읽는다.
- 성장기록: 현재 실제 성장기록은 기기의 IndexedDB hannun-growth-records에 있다. 서버 이전·가족 공유·첨부 이미지 저장은 별도 기능 설계가 필요하다. 이번 작업에서 기기 기록을 서버에 있는 것처럼 간주하거나 빈 컬렉션을 만들지 않는다. 향후 families/{가족ID}/growthRecords에서 대상 아이·활동·작성자·기록일을 명시하고, 첨부 이미지는 Storage에 저장하는 구조를 검토한다.
- 비활성 js/sync-v2.js: 앱이 로드하지 않는 이전 설계 모듈이다. 해당 설계로 전환하거나 새 DB 데이터를 만들지 않는다.

### 전환 순서

1. 전환 창을 잡고 구 경로 쓰기를 차단하는 rules-next 규칙을 배포한다. 구 앱에 저장 오류가 생길 수 있으므로 새로고침이 필요하다. 로컬 대기열은 지우지 않는다.
2. **차단 직후** 다시 백업·변경분 비교·갱신·전체 검증한다. 이 검증이 끝나기 전 전환 스위치를 켜지 않는다. 대상 충돌이 있으면 중단한다.
3. collectionV2를 ON으로 바꾼 앱을 commit/push하고 운영 버전을 확인한다. 현재 작업에 대해 새로운 push 요청은 아직 없다.
4. 로그인·회원가입·아이 프로필·초대·캘린더·할일·완료·반복 예외·오프라인 재접속을 새 경로로 검증한다. DB 전용 규칙의 허용/거부 40건은 로컬 에뮬레이터에서 검증했다. 신규 가입·초대 전체 흐름과 실제 계정 전환 검증은 남았다.
