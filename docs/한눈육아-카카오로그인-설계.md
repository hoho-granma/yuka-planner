# 한눈육아 카카오 로그인 — 설계서 (구현 완료·배포 대기)

기준: `한눈육아-D1-계정설계.md`(이메일/비밀번호 계정), `AGENTS.md`(기존 기능 유지, 큰 변경은 설계 보고, push는 지시 후에만).
목표: 이메일 가입 없이 카카오로 1초 가입·로그인. 기존 이메일 계정과 흐름은 그대로 둔다(추가만).

## 0. 구현 결과 (2026-10-16)
- 서버 `functions/kakao-login.js`·`index.js`의 `kakaoLogin`, 브라우저 `js/kakao-login.js`, `auth-service.js`(토큰 로그인), `account-view.js`(버튼 3곳), `app.js`(`acctKakaoComplete`·`kakao-login` 액션), `index.html`·`sw.js`·`firebase.json`(`/oauth` 재작성).
- **처음 온 카카오 사용자는 새 가입 시트가 아니라 기존 '연결 복구' 시트**(역할·이름 → 새 가족 또는 코드 합류)를 탄다. 이미 있는 화면이라 변경이 가장 작고, 이름은 카카오 닉네임으로 미리 채워진다(상황·지역은 가입 시트와 달리 묻지 않는다).
- 테스트: `test/kakao-login.test.js`(서버), `test/kakao-login-client.test.js`, `test/kakao-wiring.test.js`. `test/d1-accounts.test.js`의 "계정 SDK는 동적 로드" 항목은 이 작업 전부터 실패(HEAD `index.html`이 firebase-auth-compat를 정적으로 불러옴).
- 남은 일: 시크릿 `HANNUN_KAKAO` 입력(`tools/set-kakao-secret.sh`) → 함수 배포 → 카카오 개발자센터에 리다이렉트 URI 추가 → push(호스팅 배포) → 실제 로그인 확인.

## 1. 결정된 것
- 카카오 앱 하나를 쓴다(앱 이름 "한눈육아"). 리다이렉트 URI: `https://yuka-planner.web.app/oauth` (쓰앵님 `https://sseangnim.web.app/oauth`은 이미 등록됨, 쓰앵님 연결은 나중).
- 계정은 두 앱이 **따로**: 한눈육아 카카오 계정 uid = `hn_kakao_<카카오번호>`(쓰앵님은 `kakao_<번호>`).
- 카카오에서 받는 정보는 **번호와 닉네임뿐**(이메일 안 받음 → 검수·비즈앱 불필요). 카카오 계정은 Firebase 계정의 이메일로 쓰지 않는다(이메일 계정과 충돌 없음).

## 2. 동작 방식
1. 로그인/가입 시트의 [카카오로 1초 만에 시작하기] → 카카오 로그인 화면(`state` 난수는 sessionStorage에 저장).
2. 카카오가 `https://yuka-planner.web.app/oauth?code=…&state=…` 로 돌려보냄. 호스팅 규칙으로 `/oauth`를 `index.html`로 보내고(상대경로 자산은 그대로 동작), 앱이 시작할 때 경로가 `/oauth`면 로그인을 먼저 마무리한다.
3. 서버 함수 `kakaoLogin`(기본 코드베이스, 서울)이 코드를 카카오에 확인(토큰 → 사용자 정보) → 계정 생성/조회 → 커스텀 토큰(`sso: "kakao"`, `sname: 닉네임`) 반환. 비밀키는 Secret Manager `HANNUN_KAKAO`(JSON)에만 둔다.
4. 앱이 `signInWithCustomToken`으로 로그인 → 기존 `onChange` → `acctRestoreThenHide`가 가구를 복원한다(기존 로그인과 같은 경로).
5. **처음 온 카카오 사용자**(accounts 문서 없음): 가입 시트를 "카카오 모드"로 연다 — 이메일·비밀번호 단계는 숨기고 상황 → 역할 → (가족코드) → 지역만 받아 기존 `acctSignupTail`로 마무리한다. 가입 시 `acct.svc.signUp`은 건너뛴다.

## 4. 영향·주의
- 이메일 계정은 그대로. 카카오 계정은 이메일이 없으므로: 가족 구성원 표시는 "카카오 · 닉네임", 비밀번호 재설정/이메일 변경/이메일 인증 UI는 해당 없음(숨김), 계정 삭제는 방금 로그인한 상태라 재인증 없이 가능.
- 규칙(`firestore.rules`) 변경 없음: `accounts` 규칙은 `uid` 기준이라 그대로 동작, 이메일 필드는 없어도 통과(`!('email' in …) ||`).
- **배포 경로**: 화면은 main에 push하면 GitHub Actions가 호스팅(`--app hannun` 빌드)에 올린다 → **push는 지시하신 뒤에만**. 함수는 `firebase deploy --only functions:default:kakaoLogin`으로 따로 올리고, 시크릿 입력은 사용자가 직접(`tools/set-kakao-secret.sh`).
- **작업 트리 주의**: `js/app.js`·`index.html`에 다른 세션의 미커밋 변경이 이미 섞여 있다. 내 변경만 골라 커밋하려면 파일 단위로 나눌 수 없어, 커밋 전에 사용자가 어떤 변경을 같이 올릴지 정해야 한다.
- 승인된 구성원 모드(`acctApprovalEnabled`)에서는 카카오 가입도 기존처럼 PENDING 흐름을 탄다(가입 마무리 경로를 재사용).
- 카카오 앱이 "개발 중"이면 닉네임만 받는 기본 로그인은 일반 사용자도 가능하다고 알고 있다(등록 화면에서 확인 필요).

## 5. 사용자가 할 일
1. 카카오 개발자센터에 리다이렉트 URI `https://yuka-planner.web.app/oauth` 추가, 동의항목 "닉네임" 설정.
2. **REST API 키**를 알려 주기(공개값). **클라이언트 시크릿**은 `! bash tools/set-kakao-secret.sh`로 직접 입력.
3. 시크릿 입력 뒤 함수 배포 승인, 화면은 push 지시.

## 6. 검증 계획
- 단위: 서버(코드 교환·계정 생성·토큰), 클라이언트(state 불일치 거부·주소), 가입 카카오 모드(이메일 단계 없음, `signUp` 호출 안 함).
- 헤드리스 Chrome으로 첫 화면·가입 시트·로그인 시트에 카카오 버튼과 카카오 모드 화면을 확인(고정 테스트 계정 규칙은 이메일 가입용이라 카카오 모드는 가짜 로그인으로 확인).
- 실제 카카오 왕복은 키가 들어간 뒤 폰/브라우저에서 사용자가 1회 확인.
