# 한눈육아 서비스 방향설계서 (최상위 기준)

> 사용자가 2026-10-05에 확정. 특정 기능 구현 지시가 아니라 앞으로의 서비스 설계·UX·기능 판단의 최상위 기준이다. 기존 구현은 이 문서를 기준으로 검토하되 전체를 재구현하거나 기존 기능을 임의로 삭제하지 않는다.

## 1. 서비스 정의
한눈육아는 단순한 육아정보 앱이나 가족 캘린더가 아니다.

> 아이를 키우면서 생기는 부모의 고민을 아이의 성장단계·월령/학년·지역에 맞춰 먼저 찾아주고, 필요한 정보와 실제 행동·일정까지 연결해주는 가족 육아 서비스

경험 흐름: 아이 정보 → 현재 상황 판단 → 지금 부모가 고민할 가능성이 높은 것 선별 → 정보 → 행동 → 일정 → 가족 공유 → 다음 고민.

핵심 한 문장: **"우리 아이에게 지금 필요한 것을 먼저 찾아주고, 놓치지 않게 연결해주는 것."**

## 2. 해결하려는 문제
정보가 부족한 것이 아니라 너무 많고 흩어져 있다. 부모의 질문(지금 뭘 챙기지, 곧 뭐가 달라지지, 우리 지역은, 받을 지원은, 어디 가지, 다른 아이들은, 일정은 어떻게 공유하지)을 아이의 성장 흐름 안에서 연결한다.

## 3. 차별점
- 육아정보: 검색하면 알려줌 / 캘린더: 입력하면 관리 / 지역·교육 검색: 조건 입력하면 찾아줌
- 한눈육아: **먼저 찾아주고 정보→행동→일정→가족 공유까지 연결** (차별점은 기능 개수가 아니라 개인화된 선제적 경험)

## 4. 개인화 기준
생년월일, 거주 지역, 월령/연령, 학년, 기관(어린이집·유치원·학교), 가족 구성원, 필요 시 관심 영역 → 성장단계+월령/학년+지역+기관/가족 상황으로 판단해 노출 우선순위를 정한다. 같은 앱이라도 아이가 다르면 홈이 달라야 한다.

## 5. 성장단계(내부 로직, 메뉴로 노출 불필요)
임신 / 0~12개월 / 12~36개월 / 3~5세 / 6~7세 / 초등(학년+지역이 중요)

## 6. 단계별 경험
| 단계 | 부모 고민 | 먼저 제공 |
|---|---|---|
| 임신 | 이번 주에 무엇을 검사/준비하지 | 주차별 검사·준비·출산 준비 |
| 0~12개월 | 지금 아기에게 필요한 것 | 예방접종·검진·성장·수면·이유식·지원 |
| 12~36개월 | 이 시기에 뭐가 달라지지 | 발달·생활·건강·어린이집·지원 |
| 3~5세 | 교육은 어떻게 | 기관·교육·건강·활동·지역 정보 |
| 6~7세 | 초등 가기 전에 뭘 준비 | 취학·학교 준비·학습·교육·지역 정보 |
| 초등 | 우리 아이는 어느 정도, 다른 집은 | 학년별 학교생활·학습·학원·지역 교육 트렌드 |

역할 변화: 임신=준비 도우미 → 영아=놓침 방지 → 유아=성장·건강·교육 선택 → 취학 전=초등 준비 → 초등=교육·지역 정보+가족 생활 관리.

## 7. 핵심 기능 구조
- **A. 지금 우리 아이에게 필요한 것**: 현재 월령/연령/학년에서 부모가 고민할 대표 주제를 먼저 보여주는 개인화 영역(단순 콘텐츠 목록 아님). 예: 35개월(36개월 이후 변화·다음 검진·유치원 준비·지원), 5세(교육 시작·영어·지역 교육), 초3(우리 동네 학원·수준).
- **B. 월령·성장단계 정보**: 성장·발달·건강·접종·검진·구강·수면·식사·안전·생활습관·어린이집·유치원·학교·교육·영어·학원·지원제도·지역정책·체험·다음 단계 준비. 한꺼번에 보여주지 않고 관련성 높은 것부터.
- **C. 지원·행정**: 무엇을 받을 수 있나 → 대상인가 → 언제 → 어떻게 → 공식 페이지 → 캘린더. "지원금이 있습니다"가 아니라 "놓치기 전에 챙겨드립니다".
- **D. 자동 일정**: 성장단계·지역 기준으로 일정이 먼저 생김(접종·검진·지원 신청·취학·학교·지역 사업 등). 모든 콘텐츠를 자동 일정화하지 않고 **필수성+시기성+실제 행동 필요성**이 있는 것만. 36개월 이후는 놓치면 안 되는 필수·시기성 중심.

## 8. 가족 캘린더
개인 체크리스트가 아니라 가족 생활 허브. 병원·치과·어린이집·유치원·학교·학원·숙제·행사·생일·여행·가족 약속을 가족이 입력, 구성원이 함께 보고 담당자 지정.

## 9. 자동 일정 + 가족 일정
AUTO(한눈이 만든 일정)와 FAMILY/USER(가족이 등록한 일정)는 구분 가능하되 하나의 캘린더에서 본다. 사용자가 보는 것은 "우리 가족에게 앞으로 무슨 일이 있는가".

## 10. 일정 입력 UX
직접 / 사진 / 음성. AI·OCR·음성은 날짜를 임의로 확정하지 않는다: **해석 → 일정 후보 → 사용자 확인 → 등록**.

## 11. 정보 → 행동 → 일정
정보를 읽고 끝나면 안 된다. 검진 정보→예약/기관 확인→캘린더, 지원→신청 페이지→신청 일정, 교육→지역 정보→상담/방문 일정.

## 12. 다음 단계 안내
현재만 보여주지 않고 앞으로 고민할 것을 미리(30개월→36개월 이후, 5세→초등 준비, 6~7세→입학 전 준비, 초등→다음 학년). 부모가 검색하기 전에 준비하게 한다.

## 13. 어디갈까
기본값 **우리 지역 + 우리 아이 나이**. 단순 검색이 아니라 "우리 아이가 지금 갈 만한 곳".

## 14. 지역 교육 트렌드
3~5세 이후 중요도 증가, 초등에서 핵심. 초기엔 공개·공식 데이터, 장기적으로 익명·집계 사용자 데이터. 개인정보 보호와 충분한 표본이 우선.

## 15. 홈 UX
홈은 기능 메뉴판이 아니다. 답해야 할 질문: "그래서 지금 우리 아이에게 중요한 게 뭐지?" 구성 고려: ①지금 우리 아이에게 중요한 것 ②이번 달 챙길 것 ③가족 일정 ④곧 다가오는 일정/준비 ⑤다음 단계 안내 ⑥어디갈까/교육/탐색. 최종 위치·우선순위는 전체 UX 검토 후 결정.

## 16~19. 전체 흐름·사용자 느낌·개인화·핵심 경험
아이를 알려준다 → 이해한다 → 지금 필요한 것 → 궁금한 것 해결 → 행동 연결 → 일정 → 가족 공유 → 다음 고민 예고. "육아를 더 열심히 관리하는 앱"이 아니라 "육아에서 놓치는 것을 줄여주는 앱". 개인화는 나이(고민)·월령(건강·발달·생활)·학년(학교·학습·교육)·지역(지원·기관·교육·활동)·가족 상황(캘린더·담당)에 따라 홈과 추천의 내용과 우선순위가 바뀐다. 차별화는 개별 기능이 아니라 연결.

## 20. 최종 포지셔닝과 판단 기준
한눈육아는 육아정보 앱·체크리스트·가족 캘린더·지원금 앱·교육 검색 앱이 아니다. 새 기능과 UX는 아래로 판단한다.
1. 우리 아이에게 지금 필요한가
2. 부모의 실제 고민을 해결하는가
3. 정보에서 행동으로 연결되는가
4. 가족 생활과 연결되는가
5. 앞으로의 고민까지 이어지는가
