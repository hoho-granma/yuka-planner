# 4-1 재정의 시안 — 이전 홈 기반 + '지금 꼭 할 것' 가볍게

- 작성: hn_design, 2026-10-05 / 근거: D30(사용자 원문 "새홈 미리보기 해서 보는 화면보다, 이전 화면이 더 보기 편해." · 이유 "이전 홈의 가족 일정·카드가 더 익숙해요"+"한 화면에 정보가 너무 많아요" · 방향 "미리보기는 선택 사항으로 두고 개선") / 코드·문서 대조만(js/home.js, js/home-slots-view.js, data/policy/curation.json), 브라우저·캡처 없음
- 이전 4-1 메모(docs/한눈육아-4-1-허브홈-메모.md)의 "B 타임라인 마무리"는 **폐기**. 이 문서가 4-1의 새 기준이다.
- 고정 조건: 이전 홈의 '오늘·이번 주 우리 가족' 카드와 익숙한 배치는 유지 / 새 홈은 선택 사항(스위치) 유지 / 6기준 ①놓침 방지 ④가족 생활 ⑥수고 감소 지킴 / 새 색·새 변수 없음(`--nd-*`만)

## 1. 지금 두 홈의 정보량(숫자 기준)
**세는 법**: 눌러서 열리거나 이동하는 '줄·카드' 1개 = 1항목. 아이 칩 줄은 1항목, 안내 문구·제목은 세지 않음.
**예시 아이**: 생후 5개월, 아이 2명, 가족 일정 2건, 이번 달 카테고리 4개, 신청 가능 혜택 3개, 기간형 묶음 1개(계정 모드).

| 홈 | 구성 | 한 화면 항목 수 |
|---|---|---|
| 이전 홈(계정 모드) | 아이 칩 1 + 가족 일정 2 + 카테고리 줄 4 + 기간 묶음 1 + 혜택 3 + 혜택 전체 보기 1 | **12** |
| 새 홈 미리보기 | 머리 줄 0 + 지금 꼭 할 것 3 + 'N개 더' 1 + 가족 2 + 곧 2 + 알아두기 1 + 혜택 줄 1 + 다음 단계 1 + 탐색 2 (아이 칩 없음) | **13** (+ 접힘이 열리면 더 늘어남) |

→ 사용자가 "너무 많다"고 느낀 건 새 홈이 이전 홈보다 **항목이 많고 종류(곧·알아두기·다음 단계·탐색)가 더 많아서**다. 가족 일정은 두 홈이 같으므로, 줄이려면 '꼭 할 것 아래의 부가 섹션'을 접어야 한다.

## 2. 후보 3개
공통: 상단 **아이 칩 줄**을 이전 홈처럼 복원(아이 2명 이상일 때만, 1명이면 안 보임). 지금은 칩이 '이번 달 챙길 것' 섹션 안에 있어 접으면 같이 숨겨지므로 **맨 위로 올린다**. 아이 전환이 프로필 시트로만 되는 문제는 이로써 해결(`showChildSwitchSheet`는 그대로 둔다).

### 후보 A — 이전 홈 그대로 + 맨 위에 '지금 꼭 할 것' 2줄
순서: 아이 칩 → **지금 꼭 할 것(최대 2줄)** → 오늘·이번 주 우리 가족 → n월 챙길 것(카테고리 줄) → 이 기간에 챙겨볼 것 → 혜택 3줄.
- 한 화면 항목 수: 칩 1 + 꼭 할 것 2 + 가족 2 + 카테고리 4 + 기간 1 + 혜택 3 + 전체 1 = **14**
- 장점: 가장 익숙하다, 구현이 가장 작다. 단점: **이전 홈보다 2개 늘어** "정보가 많다"는 불만에 답하지 못한다.

### 후보 B ★ — A + 나머지는 접어서 한 줄로
순서: 아이 칩 → **지금 꼭 할 것(최대 2줄, 오른쪽 '외 N개 ›')** → 오늘·이번 주 우리 가족(이전 홈 카드 그대로) → **'이번 달 챙길 것 ›'(기본 접힘, 개수 없음)** → 혜택 한 줄 → 탐색 한 줄(어디갈까 · 교육).
- 접힘 안(펼치면): 카테고리 줄 4 + 기간 묶음 1 + 곧 다가오는 것(최대 2) + 이 시기 알아두기(1, 기본 접힘 유지) + 다음 단계 배너.
- 한 화면 항목 수: 칩 1 + 꼭 할 것 2 + 가족 2 + 접힘 머리 1 + 혜택 줄 1 + 탐색 1 = **8** (펼치면 최대 16)
- 장점: 이전 홈의 '가족 카드'가 그대로 2번째 자리에 있고, 눈에 항상 보이는 건 8개뿐이다. 놓치면 안 되는 것은 꼭 할 것 2줄이 맡는다.
- 단점: 카테고리 줄이 한 번 눌러야 보인다(익숙한 '카드'를 접는 셈 — 아래 §4 위험 참조).

### 후보 C — 홈 안에서 '오늘' / '전체' 둘로 나눔
상단 작은 두 칸 토글: **오늘**(아이 칩 → 꼭 할 것 2줄 → 가족 일정 → 탐색) / **전체**(이전 홈 그대로).
- 한 화면 항목 수: 오늘 = 칩 1 + 꼭 할 것 2 + 가족 3(이번 주 여유 있게) + 탐색 1 = **7**, 전체 = **12**
- 장점: 화면이 가장 가볍고 이전 홈이 통째로 살아 있다. 단점: **탭 안의 탭**이 하나 더 생겨 ⑥ 수고 감소에 어긋난다(하단 탭 4개 + 홈 토글 2개), 사용자가 어느 쪽을 기본으로 볼지 또 정해야 한다.

### 비교
| | A | **B ★** | C |
|---|---|---|---|
| 한 화면 항목 수 | 14 | **8** | 7(오늘)/12(전체) |
| 이전 홈과의 익숙함 | 최고 | 높음(가족 카드 그대로, 카테고리 접힘) | 높음(전체 탭이 이전 홈) |
| ① 놓침 방지 | 꼭 할 것 맨 위 | 꼭 할 것 맨 위 + 접힘 머리(개수 없음) | 오늘 탭에서만 보임(전체 탭에서 놓칠 수 있음) |
| ④ 가족 생활 | 가족 카드 2번째 | 가족 카드 2번째 | 가족 카드 3개까지 |
| ⑥ 수고 감소 | 정보 증가 | 정보 감소, 탭 추가 없음 | 토글 추가 |
| 구현 크기 | S | M | M~L |

## 3. ★ 추천: 후보 B — 이유
1. 사용자가 고른 이유 두 가지 모두에 답한다(가족 카드 그대로 + 정보량 13→8).
2. 새 슬롯 엔진(`cur.now`)을 그대로 쓰되 **'꼭 할 것'만 2줄**로 꺼내 쓰므로 D17 와인 D-N·D18 지난 기록 확인·D19~D20의 정책 파일을 바꾸지 않는다(슬롯 수 3→2는 홈 표시에서만 줄이고 '외 N개'로 전체 보기에 연결 — 엔진 수치는 그대로).
3. 접힘은 새 부품을 만들지 않고 이미 있는 `hs-fold`(details) 방식과 '이번 달 챙길 것' 카테고리 줄(`cat-line`)을 그대로 쓴다.

## 4. 후보 B 화면 규칙(디자인 값, 새 색 없음)
| 자리 | 모양 | 값 |
|---|---|---|
| 아이 칩 줄 | 이전 홈 `.home-child-chip` 그대로, 2명 이상일 때만, 가로 스크롤 | 기존 값 유지 |
| 지금 꼭 할 것 카드 | 흰 면 카드, 1px `--line`, r16, 제목 '지금 꼭 할 것' + 오른쪽 '외 N개 ›'(N=0이면 숨김) | #fff, #161618, 링크 #4a45c8 |
| 꼭 할 것 줄(최대 2) | 한 줄에 점(분류색) + 제목(한 줄 말줄임) + 오른쪽 날짜/D-N(D-14 이내는 와인 #8a1c3d 800, D17 유지) | 항목 눌러 상세 시트 |
| 꼭 할 것이 없을 때 | 카드 숨김(빈 상태 문구 없음) — 이전 홈 첫 화면과 같아져 정보가 늘지 않음 | 이전 새 홈의 "이번 달 꼭 할 것은 없어요"는 쓰지 않음 |
| 오늘·이번 주 우리 가족 | **이전 홈 카드 그대로**(`usUpcomingHtml`, 36개월 미만도 위에서 2번째) | 변경 없음 |
| 이번 달 챙길 것 › | 접힘 머리 1줄(details, 글자는 '이번 달 챙길 것 ›'만 — 개수 없음, D16·D31). 펼치면 카테고리 줄 + 기간 묶음 + 곧(2) + 알아두기(1) + 다음 단계 배너, 맨 아래 '전체보기 ›'(체크리스트) | 접힘 상태는 기기 저장 안 함(항상 접힘으로 시작, D6) |
| 혜택 한 줄 | '받을 수 있는 혜택 N개 · 확인할 것 M개 ›'(새 홈의 `hs-ben`) 1줄 | 이전 홈의 혜택 3줄 대신 |
| 탐색 한 줄 | 어디갈까 + 교육(3세 이상), 임신 중 어디갈까 숨김 | D2·D8 유지 |

- **개수 표기**: 접힘 머리에는 개수를 쓰지 않는다. hn_pm 판단: '이번 달 챙길 것 N개'는 D16(개수 요약 보류)과 충돌 → D31로 '이번 달 챙길 것 ›'만 둔다(2026-10-05).
- **위험**: 카테고리 줄은 사용자가 '익숙한 카드'라고 말한 부분일 수 있다. B로 가면 첫 화면에서 접힌다. 사용자 피드백이 "접지 마세요"면 접힘 기본값만 '펼침'으로 바꾸고 항목 수는 14로 돌아가므로(후보 A) **되돌림이 쉽다**.

## 5. 사용자에게 물을 것(하나만)
> "이전 홈 모양은 그대로 두고 '지금 꼭 할 것'만 맨 위에 두 줄로 올리려고 해요. 어떤 모양이 편하세요?"
> A. 이전 홈 그대로 + 맨 위 꼭 할 것 2줄(14개 보임) / **B. 꼭 할 것 2줄 + 가족 일정 + 나머지는 접어서 한 줄(8개 보임) ★** / C. 홈 안에서 '오늘'·'전체' 두 칸으로 나눔

## 7. 6기준 점검(후보 B)
- ① 놓침 방지: 꼭 할 것 2줄이 맨 위, 접힘 머리 '이번 달 챙길 것 ›'가 항상 보임(개수 없음), D-14 이내 와인 D-N 유지. 곧·알아두기는 접힘 안이지만 **D-14 이내 항목은 꼭 할 것 쪽으로 이미 올라온다**(L-규칙 그대로).
- ④ 가족 생활: 가족 카드가 이전 홈 모양·2번째 자리 그대로, 생일·100일·돌 연결은 별도(2-5 미연결 항목 그대로).
- ⑥ 수고 감소: 첫 화면 항목 13→8, 탭 추가 없음, 접힘은 한 번 눌러 펼침.

- 새 홈 미리보기 스위치를 켜면 B를 보이게 한다(D30 선택 사항 유지). 이전 홈이 기본(HOME_V2_STAGE=1 ①OFF)이라는 현재 설정은 그대로.
- 구현 규모 M: `js/home.js`(이전 홈)에 '꼭 할 것 카드'와 '접힘' 두 조각을 끼우는 방식이 `home-slots-view.js`를 줄이는 방식보다 이전 홈 DOM을 덜 건드린다. 어느 쪽으로 할지는 hn_dev·hn_pm 판단.
- 시안: 같은 이름의 아티팩트(후보 3개 + 후보 고르기)로 사용자 확인.
