# 교육 선택 — 맘카페·이용자 의견 수집 검토

확인일: 2026-10-08(KST). 세션 2 결과. 브라우저 조사: 사용자 지정 **Aside**. 앱 코드·공통 설계·운영 데이터·규칙은 변경하지 않았다. 연락·가입·후기 작성·신청·커밋·push는 수행하지 않았다.

## 1. 결론과 검증 수준

**공개 출처를 찾고 기관별 검색·상담 질문으로 연결하는 것은 가능하지만, 이번에 확인한 조건만으로 외부 후기의 자동 수집·보관·AI 요약·앱 재제공을 시작할 수는 없다.** 네이버 검색 API는 존재하지만 후기 분석용 원문 API가 아니다. 현재 개발자센터 약관은 검색 데이터의 AI 입력·활용을 금지하고 가공 없는 검색결과 표시를 요구한다. 당근과 강남엄마도 허가 없는 자동 수집에 제한을 명시한다. 플랫폼과 원저작자의 허락을 확보하는 경로 또는 한눈육아에 직접 제출하는 자발적 후기부터 검토하는 것이 현실적이다.

이번 검토에서 **허용조건·지점 귀속·원문 내용까지 검증하여 요약에 채택한 후기 원문은 0건**이다. 확인된 독립 작성자 수도 산출하지 않았다. 이는 해당 기관의 후기가 없다는 뜻이 아니라, 이번 조사에서 사용할 수 있는 근거가 확보되지 않았다는 뜻이다. 실제 후기 문장·닉네임·아동 개인정보·검색 패시지는 이 문서에 보관하지 않는다. 반복 언급·상반된 의견·실제 이용 여부도 아직 검증하지 못했다.

세션 1 결과 파일은 조사 시작과 중간 확인 때 없었다. 기다리지 않고 정책 검증을 진행했고, READ101 공식 지점 안내 2페이지를 독립 확인했다. 기존 시안의 가상 기관·후기는 근거로 쓰지 않았다. 검토 기준은 전달 프롬프트, 구현 가능 범위, 메뉴 시안, 서비스 방향설계서와 메뉴별 UX 지침이다. 아이의 생활권·주소·학교 위치를 추정하거나 수집하지 않았다.

### 공식 정책의 구체적 확인값

- 네이버 일반약관: 시행 2026-10-01, 공지 2026-09-23. 게시자의 지식재산권과 별도 이용 허락 필요성을 명시한다. 자동화 관련 조항을 확인했으나 긴 항목 일부가 접근성 출력에서 축약되어, 전체 문구를 읽었다고 전제해 원문 수집 허용을 판정하지 않았다.
- 네이버 수집 정책: 공개와 복제를 구분하며 robots.txt로 보호하는 데이터베이스 수집을 불허한다. 사용자 RSS 허용 설정은 RSS를 통한 수집·검색 예외다. **robots 허용만으로 저작권·요약 배포 허락이 생긴다고 판단하지 않는다.** 이번에는 출처별 실제 robots.txt를 확인하지 않았고 원문 크롤러도 실행하지 않았다.
- 네이버 API 약관: 페이지에 **2026-10-07 개정** 표시. 검색 특약의 AI 활용 금지와 보관 예외를 직접 확인했다. 기기 보관은 장애 대응/개인화 목적에 24시간 또는 새 질의까지 중 짧은 기간. 서버 이력 조회는 최대 21일, 개인화는 기기와 같은 기간이며 목적별 분리 보관. 이것은 후기 분석 DB 보관기간이 아니다.
- API 약관 부칙: 개발자센터 Search API 신규 신청은 2026-07-30 24시를 기점으로 중단. 그 시점까지 신청한 기존 이용자는 2027-06-30 24시까지 경과조치. 이후 NAVER API HUB 별도 절차·약관을 따른다. 기존 문서의 ‘앱 등록 후 키 발급’ 설명만으로 지금 신규 발급 가능이라고 판단하면 안 된다.
- NAVER API HUB 상품 소개: 네이버 사업 주관/네이버 클라우드 중개 운영, 키 하나로 검색 등을 선택하는 구조와 종량제를 확인했다. 신규 상품의 후기 요약 허용, AI 예외, 상세 요금·한도·캐시 조건은 미확인이다. 개발자센터 금지 조건이 HUB에서도 동일하다고 추정하거나 HUB가 이를 해제했다고 추정하지 않는다.
- 당근: 공고 2026-01-02, 시행 2026-01-09. 데이터베이스 보호·게시물 저작권·접근 방식 제한을 확인했다. 플랫폼이 갖는 게시물 이용권은 외부 앱의 권한을 뜻하지 않는다.
- 강남엄마: v2026.04.28, 시행 2026-05-28. 제11조 자동 수집 제한과 사전 승낙 없는 복제/제공 제한, 제15조 권리 귀속을 확인했다.

## 4. 카페글 API가 제공하는 것과 제공하지 않는 것

공식 문서 확인이며 **실제 운영 응답 검증은 아니다.** 키 발급·호출·계정 로그인은 수행하지 않았다.

| 항목 | 문서 확인값 | 후기 요약에 대한 한계 |
|---|---|---|
| 방식 | GET, HTTPS, JSON/XML. cafearticle.json / cafearticle.xml | 공개 게시판 검색 결과이며 원문 전체·댓글 수집 API가 아님 |
| 인증 | 클라이언트 ID·시크릿을 요청 헤더로 전송 | ‘비로그인’이 무인증이나 회원글 접근 허락을 의미하지 않음 |
| 검색 | query 필수, display 기본 10/최대 100, start 기본 1/최대 1000, sort sim/date | 전수 조회·전체 커뮤니티 대표성을 보장하지 않음 |
| 한도 | 개발자센터 문서상 검색 API 하루 25,000회 | 기존 서비스 문서 기준. HUB 한도는 미확인 |
| 결과 항목 | title, link, description(요약 패시지), cafename, cafeurl | description은 본문 전체가 아니며 경험·광고·반론을 판정할 충분한 근거가 아님 |
| 시점·작성자 | lastBuildDate는 검색결과 생성 시간. 문서의 개별 결과 항목에 게시일·작성자 없음 | 게시 시점·독립 작성자 수·실제 이용자 검증을 이 응답만으로 할 수 없음 |
| total | 총 검색결과 개수 | 검증 후기 수·독립 이용자 수·인기도로 바꾸면 안 됨 |

카페 가입/글쓰기 API도 공식 API 목록에 있으나 원문 읽기 권한이나 후기 다운로드 경로로 사용하지 않는다. 허용 여부 검토 없이 API description을 AI에 입력하거나 원문 보완 수집을 실행하지 않는다.

### 매핑 절차 제안

1. 교육청 관할+기관 고유 등록 식별자를 정본으로 확보하고, 공식 지점명·도로명주소·층/호·공식 URL·출처 확인일·이전 이름/운영기간을 연결한다. 자체 표기 등록번호와 교육청 확인값은 별도 필드로 둔다.
2. 후기에는 원문에 명시된 기관명·지점·주소/지역 맥락과 이용 시점을 기록한다. 이름 유사도는 후보 찾기에만 사용한다. ‘판교’, 브랜드 이름만 있거나 여러 지점이 가능한 글은 제외/미매핑한다.
3. 명칭·주소가 명확히 일치해도 이전·폐점·운영자/강사 변경·반/과정/이용기간을 확인한다. 한 반의 경험을 지점 전체로 확대하지 않는다. 주소의 단순 표기 정규화와 실제 이전을 구분한다.
4. 기관 ID 매핑 근거와 검토자를 남긴다. 미확정 상태에서는 해당 기관 카드에 연결하지 않는다. 사용자의 아이 주소나 국제초 진도를 보충 추정하지 않는다.

이번 표본은 **지점 혼합 위험을 실제 공식 원문으로 확인한 사례**다. 실제 부모 의견을 이 지점들에 매핑하는 검증은 완료하지 않았다.

## 6. 요약에 필요한 최소 근거와 건수 계약

허락을 확보한 뒤에만 다음 원문 검증을 진행한다. 정책 조사 메타데이터와 후기 콘텐츠 저장 권한을 분리한다.

| 검증 항목 | 필요한 근거·처리 | 화면 표시 |
|---|---|---|
| 이용 허락 | 출처·경로·권리자·허용 필드·AI 처리/보관/재제공 범위·기간·철회 조건·정책 버전 | 허락이 없으면 요약 미제공 |
| 원문과 시점 | canonical 원문 URL/글 ID, 게시일, 수정일(있는 경우), 열람일, 경험 기간 | 게시 기간과 확인일 분리. 게시일 불명이면 불명 표시 |
| 실제 이용 | 작성자의 직접 이용 주장/상담·체험/전언/기관 작성 구분. 검증 자료가 있으면 종류만 기록 | ‘이용 주장’과 ‘이용 확인’ 분리. 실명·아동 서류를 기본 요구하지 않음 |
| 지점·반 | 기관 정본과 명칭·지점·주소 근거, 과정/반/경험 시기 | 일치 불명 제외. 반 범위를 알 수 없으면 미확인 |
| 독립성·중복 | 같은 글 URL 변형, 재게시, 인용·스크랩, 동일 내용, 같은 작성자의 반복 경험 구분 | 글 수·중복 제거 원문 수·확인 가능한 독립 작성자 수 따로 표시 |
| 홍보 가능성 | 기관/관계자 표시, 협찬·체험단/보상/추천코드, 홍보 게시판·등업 동기 등 근거 | ‘홍보 가능성’으로 표시. 홍보 단서가 없다고 독립 경험 확정하지 않음 |
| 주장·반론 | 문장별 원문 근거, 주제, 긍정/부담/혼합 의견, 당시 조건 | 상반된 의견도 같은 화면에. 반론 없음은 탐색 범위 한계와 구분 |
| 삭제·변경 | 원문 삭제/비공개/정정·동의 철회에 따른 근거 무효화, 요약 버전과 재생성 | 오래된 근거를 최신 운영 사실로 유지하지 않음 |

익명 작성자·계정은 독립적인 사람임을 보장하지 않는다. 동일 닉네임/복수 계정의 관계를 추적해 신원을 추정하지 않는다. 권한 내 내부 식별 처리도 개인정보 검토가 필요하다. 댓글을 글과 합칠 때는 작성자·중복·전언 여부를 따로 검증하며, 한 스레드의 댓글 수를 독립 의견 수로 세지 않는다.

최소 집계 흐름은 **발견 링크 → 본문 열람 성공 → 허락 확인 → 지점 일치 → 중복/홍보/전언 구분 → 주제별 채택 원문**이다. 각 단계 수를 별도로 집계해야 한다. 이번에는 후기 채택 0건이며 열람 가능한 후기 전체 규모는 측정하지 않았다. 카페 회원 수·전체 게시글 수·조회/좋아요·검색 total·타 사이트 리뷰 수는 채택 건수를 대신하지 않는다.

### 주제별 상담·체험 질문

| 비교 주제 | 원문에서 확인해야 할 맥락 | 후기 없이도 부모가 확인할 질문 |
|---|---|---|
| 수업 방식 | 개별/그룹, 과정·반·이용 시기, 정규/체험 경험 | 어느 과정에서 몇 명이 함께 배우고 개별 지도는 어떻게 하나요? |
| 숙제 | 빈도·소요시간·미완료 대응, 당시 학년/과정 | 과제 빈도와 예상 시간, 미완료 시 지도 방식은 무엇인가요? |
| 진도 | 레벨·선행/복습·개별 조정 조건 | 진도를 어떤 기준으로 정하고 중간에 조정할 수 있나요? |
| 피드백 | 전달 주기·채널·누가 받는지·내용 | 부모 피드백 주기와 샘플, 질문에 답하는 담당자는 누구인가요? |
| 분위기 | 특정 강사/반/경험 당시 상황 | 체험에서 아이가 질문·도움 요청을 어떻게 하는지 볼 수 있나요? |
| 차량 | 경험 당시 노선·시간·인계·지연 처리 | 현재 이용 가능한 정류장·시간·인계 방식·추가 비용은 무엇인가요? |

### 요약 예시의 처리

**실제 학원별 요약 예시는 생성하지 않는다.** 허용 원문을 확보하지 못했기 때문이다. 현재 카드에 가능한 상태 문장은 ‘이용자 의견 근거를 아직 확보하지 못했습니다. 공식 안내와 상담 질문을 확인하세요.’이다. ‘후기 없음’이나 ‘검증된 이용자 0명’으로 표시하지 않는다.

향후 문장 형식만 제안하면: ‘[게시 기간]의 지점이 일치하는 [중복 제거 원문 수]건에서 [주제]에 관한 의견이 언급됨. [상반된 의견과 건수]. 독립 작성자 수는 [확인값/확인 불가].’ 이는 실제 후기 예시가 아닌 출력 계약이다. 한 글이면 ‘한 글에서 언급됨’이라고 한다. 여러 독립 근거를 실제 확인하기 전 ‘반복’, ‘많은 부모’, ‘꼼꼼한 학원’ 같은 표현을 쓰지 않는다. 건수·기간·근거 링크를 문장별로 되짚을 수 있어야 하며, 다수 의견도 사실·교육효과·아이 적합성의 증명으로 바꾸지 않는다.

## 7. 현재 불가능한 것과 부담이 적은 대안

| 대안 | 부모 부담·가능한 가치 | 선행조건·한계 | 우선순위 |
|---|---|---|---|
| 공식정보+기관/지점 검색 연결 | 이름·주소·과정 등을 나란히 비교하고 정확한 지점 검색어를 미리 준비 | 부모는 외부 사이트에서 로그인/원문 확인할 수 있음. 검색 미리보기 저장·요약을 하지 않고 일반 링크 조건 검토. 완전한 의견 통합은 아님 | 즉시 검토 |
| 비교표+기관 확인 질문 | 후보별 빈칸을 질문으로 바꾸어 한 번의 상담/체험에서 채울 수 있음 | 기관 답변은 공식 운영 안내/주장으로 표시. 부모 경험과 구분. 확인일·반/과정 필요 | 즉시 검토 |
| 한눈육아에 자발적 직접 후기 | 지점과 이용 기간을 먼저 고르고 숙제·진도·피드백 등 짧은 구조화 답변. 기존 성장기록 재사용은 별도 동의로 입력 감소 | 저장·AI 요약·공개 범위·철회·보상/관계자 표시 동의 설계. 다른 카페 캡처 제출은 원저작자 권한·아동/타인 정보 문제를 해결하지 못함 | 소규모 동의 기반 검증 |
| 플랫폼·카페·작성자 제휴 | 허락된 원문을 기관별 주제로 묶으면 여러 카페를 돌아다니는 부담을 직접 줄일 수 있음 | 플랫폼·카페 운영자·작성자의 각 권한 범위 확인, 데이터/AI/재제공·삭제 연동 계약. 광고 제휴는 수집 제휴가 아님. 이번에 연락하지 않음 | 통합 요약 전 필수 검토 |
| 작성자 허용 RSS | 작성자가 공개 배포한 범위의 수집·검색 예외 검토 | 실제 피드·설정·글별 권리 확인. 요약/보관/AI/재제공은 별도 허락 필요. 지점 의견의 충분한 확보 미검증 | 제한 후보 |
| 네이버 검색 API로 가공 없는 검색결과 제공 | 출처가 있는 탐색 경로를 한곳에 제공할 후보 | 현재 신규는 HUB 조건 검증 필요. 기존 특약에 따른 출처·BI·원본 링크·캐시 조건. AI 요약 기능과 연결하지 않음 | 조건부 후보 |

현재 허락 없이 할 수 있다고 확정할 수 없는 것은 외부 카페 원문/댓글의 정기 수집, 영구 후기 DB, 캡처 아카이브, API 패시지 AI 입력·후기 요약, 회원/등업 제한 글 수집, 작성자 실명·독립인원 추정, 지점 불명 글 합치기다. ‘스크래핑 대신 사람이 복사’, ‘학습 대신 추론’, ‘검색에 노출되니 공개’, ‘사용자가 링크를 줬으니 이용권 확보’로 조건을 대체하지 않는다.

이용자 의견 요약의 핵심 가치는 아직 **자료와 권한 확보 전**이다. 초기 제품 후보는 공식정보→비교 질문→상담/체험→부모가 선택한 가족 일정 연결이다. 의견을 확보하지 못해도 후보 비교·상담 진입을 막지 않는다. 자발적 후기/제휴 원문으로 실제 여러 독립 의견과 상반된 경험을 확보한 뒤, 부모가 추가 검색 없이 비교 가능한지 소규모 검증한다. 인기 순위·최고 학원·추가 교육 필요·국제초 진도는 생성하지 않는다.

## 8. 구현 전 정책·법적 검토와 운영 검증

1. **수집 계약:** 플랫폼/카페 운영자/저작자가 각자 허락할 수 있는 권한을 구분하고, 공식 접근 방식·필드·빈도·AI 입력/요약/배포·원문/파생물 보관·상업적 사용·삭제/철회 조건을 문서화한다. HUB 신규 약관과 상품별 조건을 직접 확인한다.
2. **개인정보:** 닉네임·계정 식별자·아이 사진·학교/반·시간표 등 최소화/비식별, 동의와 제3자 제공·처리위탁/국외 이전 적용 여부, 보관기간·접근권한을 법적 검토한다. 공개 글도 개인정보 문제가 사라지지 않는다.
3. **저작권·데이터베이스·인격권:** 요약·인용·링크·원문 스냅샷·파생물 사용 범위, 명예훼손/권리침해 대응을 검토한다. 공식 약관의 법률 언급은 플랫폼 입장이며 이 문서는 적법/위법을 확정하지 않는다.
4. **근거 운영:** URL/게시일/확인일/지점/과정/이용 주장/독립성/중복/홍보·반론과 요약 문장을 연결하고, 원문 비공개·삭제·정정·동의 철회 후 요약 무효화를 검증한다. 장기 보관을 감사 목적이라는 이유로 자동 허용하지 않는다.
