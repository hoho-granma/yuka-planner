# 한눈육아 0~36개월 Todo Master 설계

작성일: 2026-09-28
목적: UI/기능 작업 이전에 "0~36개월 동안 부모가 실제로 챙겨야 하는 것"의 지식 구조를 확정한다.
방법: 4개 영역 병렬 조사(이유식·구강·수면 / 안전·생활·보육 / 전국공통 지원제도 / 건강검진·예방접종·발달 재검증) + 기존 서비스 데이터(health_checkup.json, vaccination.json, development.json, subsidies.json)를 통합·중복 병합·등급 분류했다.

## 1. 데이터 카테고리 vs 화면 카테고리 (섹션 7 답변)

**결론: 유지하지 않는다.** 기존 4개 카테고리(건강검진/예방접종/성장발달/지원금)는 부모 화면에는 남겨두되, **내부 데이터는 10개 세부 카테고리로 나눈다.**

### 데이터 카테고리 (10개, DB/코드 상 실제 분류)
`HC`건강검진 · `VX`예방접종 · `DV`성장발달 · `FD`이유식·영양 · `OR`구강 · `SL`수면 · `SF`안전 · `LF`생활 · `SB`지원·제도 · `CR`보육

### 부모 화면 카테고리 (2단계로 분리)
1. **캘린더 필터**: 기존 4색을 유지하되 그룹을 재편 — 🩺건강(HC+VX) · 🌱발달·생활(DV+FD+OR+SL+SF+LF) · 🏫보육(CR) · 💰지원제도(SB). "안전/생활/구강/수면"을 발달과 합치는 이유는 개별 카테고리로 쪼개면 필터 칩이 8개가 되어 산만해지기 때문.
2. **홈 화면**: 카테고리가 아니라 **상태 기반**으로 보여준다 — 🔴지금 꼭 챙겨요 / 🟡이번 달 확인해요 / 🔵곧 다가와요 / ⚠️놓친 것 확인. (근거는 섹션 5, 6)

## 2. Todo 데이터 스키마 (DB로 옮기기 쉬운 구조)

각 Todo는 아래 19개 필드를 가진 하나의 레코드다. 실제로는 JSON 배열로 관리하고, `schedule.js`가 지금 하는 것처럼 프로필을 받아 이 배열을 필터링·상태계산해서 캘린더/홈/로드맵에 뿌린다.

```json
{
  "todo_id": "VX-ROTA-DEADLINE",
  "이름": "로타바이러스 접종 마감 확인",
  "상위카테고리": "예방접종",
  "세부카테고리": "국가필수접종",
  "시작월령": 2,
  "종료월령": 8,
  "발생조건": "절대월령(2~8개월). 1차는 생후14주6일 이내 시작 필수",
  "지역조건": "없음(전국 공통)",
  "성별조건": "없음",
  "반복여부": false,
  "우선순위": 1,
  "필수구분": "필수",
  "부모행동": "생후 8개월 0일 이전에 로타바이러스 접종을 모두 완료한다",
  "완료기준": "완료로 체크(접종 완료일 기록)",
  "놓쳤을때상태": "기간지남_영구불가 (캐치업 불가, 유일한 예외 항목)",
  "공식출처": "질병관리청 예방접종도우미(NIP)",
  "출처URL": "https://nip.kdca.go.kr",
  "확인일": "2026-09-28",
  "검증상태": "검증됨"

```

발생조건은 "절대월령형"(예: 9~12개월)과 "마일스톤 트리거형"(예: "뒤집기를 시작하면") 두 종류로 나뉘며, 아래 섹션 4에서 구조화한다.

## 3. Todo 후보 분류 원칙 (A/B/C/D)

- **A. 반드시 Todo** — 특정 시점에 실제 행동/확인이 필요하고, 캘린더·홈에 노출한다.
- **B. 조건부 Todo** — 특정 조건(소득, 상황, 지역, 증상)에서만 발생. 조건 충족 시에만 노출.
- **C. 참고 정보** — 캘린더/홈에 절대 Todo로 넣지 않는다. "월령별 육아" 정보 라이브러리에만 노출.
- **D. 제외** — 서비스 핵심 목적(0~36개월 육아)과 거리가 있거나 다른 콘텐츠로 다루는 게 나음.

예시 판정:
- 국가검진, 예방접종, 부모급여/아동수당 신청, 로타 마감 → **A**
- 기저귀바우처(저소득 조건), 미숙아 의료비(해당 시), 자기주도이유식 → **B**
- 목욕물 온도, 낮잠 전환 시기, 손가락빨기 습관, 카시트 좌석 전환 개월수(공식 단일기준 없음) → **C**
- 난임지원, 육아휴직급여 상세 금액표(부모의 노동 문제이지 "아이 Todo"가 아님), 국민연금 출산크레딧 → **D** (부모급여·아동수당만 A로 남기고 나머지 부모용 노동/세제 혜택은 "지원제도" 탭의 참고 링크로만 제공)

## 5. 상태 계산 구조 (섹션 5 답변)

각 Todo는 아래 8개 상태 중 하나로 계산된다. `오늘`, `시작월령/종료월령으로 계산한 startDate/endDate`, `완료기록`, `조건충족여부`, `검증상태`를 입력으로 받는 순수 함수로 구현 가능하다.

```
조건 불충족          — 지역/성별 조건 안 맞음 → 애초에 목록에서 제외(계산 불필요)
검증 필요           — todo.검증상태 == "미검증"/"상충" (다른 상태와 동시 표시되는 배지)
아직 시작 전         — 오늘 < startDate - 60일
곧 해야 함           — startDate - 60일 <= 오늘 < startDate  (신청기한 있는 지원금은 "곧 해야 함" 창을 더 넓게)
지금 해야 함         — startDate <= 오늘 <= endDate, 완료 안 됨
완료                — 완료 기록 있음
기간 지남(캐치업 가능) — 오늘 > endDate, 완료 안 됨, 캐치업 가능(대부분의 접종/검진)
기간 지남(영구 불가)   — 오늘 > endDate, 완료 안 됨, 캐치업 불가(로타바이러스, 신청기한형 지원금)
```

"놓친 Todo"는 `기간 지남(캐치업 가능/영구 불가)` 상태의 항목을 모아 별도로 보여주는 것이다 — 지금 서비스의 `subsidyIsActiveNow()`가 이미 지원금에 한해 하는 일을 **모든 카테고리로 일반화**하면 된다.

## 7. "Todo가 너무 많아지는 문제" 검토 (섹션 7 답변)

8개월 예시처럼, **홈 화면 노출 개수는 자연스럽게 5~8개로 수렴한다** — A등급(반드시 Todo)만 홈에 올리고, B등급(조건부)은 조건 충족 시에만 추가되기 때문이다. 다만 12개월처럼 접종이 몰리는 구간은 예외적으로 늘어나므로:

- **원칙 1**: 같은 카테고리(예방접종)의 여러 회차가 같은 달에 몰리면 개별 카드가 아니라 "○월 접종 패키지" 하나로 묶어 펼치면 상세가 보이는 구조로 설계한다.
- **원칙 2**: C등급(참고정보) 전부와, A/B등급이어도 "지금 당장 행동할 게 없는" 항목(예: 발달 관찰형 DV, 생활습관형 LF)은 홈 카드로 올리지 않고 **"월령별 육아" 탭**(로드맵)에서 언제든 펼쳐볼 수 있게 한다.
- **원칙 3**: 홈에는 카테고리당 최대 1~2개만 노출하고, "더보기"로 전체 이번 달 목록(기존 리스트 뷰)에 연결한다.

결론: 8개월 아이 기준 **홈 첫 화면 Todo는 4~6개가 적정**, 나머지는 "이번 달 챙길 일" 전체 리스트(기존 UI)와 "월령별 육아" 로드맵 두 군데로 분산한다.

|---|---|---|
| **홈** | 상태 기반 4구간(지금꼭/이번달/곧/놓친것) | 섹션 5·6·7의 상태 계산 구조를 그대로 화면에 매핑 |
| **전체 일정** | 기존 월간 캘린더 (필터는 4그룹) | 현재 구현 재사용 가능 |
| **월령별 육아** | 0~36개월 로드맵, C등급 참고정보 전부 여기 | Todo 과잉을 막는 배출구(섹션 7) |
| **기록** | 완료한 검진/접종/체크/신청 이력 | 지금은 없는 기능. "놓친 것" 계산의 근거 데이터이자, 이미 완료한 항목을 복기하는 화면 — 신규 추가 권장 |
| **지원제도** | 거주지역 기준 지원금 (SB + 지자체 verified) | 기존 지원금조회 서비스와 통합점 |

기존 통합 캘린더 UI 자체는 유지하되, **"기록" 탭 신설**이 가장 중요한 구조 변경이다 — 이게 있어야 "놓친 것 계산"이 실제로 의미를 갖는다(완료 여부를 사용자가 명시적으로 기록해야 놓친 것과 안 놓친 것을 구분 가능).

## 9. 최종 산출물

### ① 0~36개월 Todo Master

섹션 4의 표(HC 6개, VX 12개, DV 9개, FD 12개, OR 6개, SL 2개, SF 8개, LF 4개, SB 10개, CR 4개 = **총 73개 A/B등급 Todo**)가 결과물이다. JSON 스키마는 섹션 2 참고.

### ② 현재 서비스의 누락 목록

**반드시 추가**
- 구강검진 4회 반복 구조로 데이터 수정 (섹션 0)
- 로타바이러스 마감(생후 8개월0일) 강조 Todo — 유일한 "영구 불가" 항목
- 아동수당 2026년 연령·금액 확대분 반영
- "기록" 탭(완료 이력) — 놓친 것 계산의 전제조건
- 이유식·구강·수면·안전·생활·보육 6개 데이터 카테고리 신설(섹션 4-4~4-10)

**추가 권장**
- 발달 관찰을 8개 월령밴드로 세분화 + 상담신호는 평소엔 숨기고 조건부로만 노출(DV-09)
- 접종 밀집 월(12개월 등) "패키지형" UI
- 지원제도(SB)에 신청기한 60일 소급 규정을 놓치지 않도록 우선순위 1로 강조

**나중에**
- 불소치약 시작연령, 배변훈련 시점, 카시트 전환 기준 등 "미검증/상충" 항목 — 학회 원문 1차 대조 후 반영
- 2026~2030 건강검진 개편(75개월 연장 등) — 시행일 확정 후 반영
- 알림·PWA·가족코드 UX 개선(이전 리뷰에서 이미 지적) — 이번 지식구조 확정 이후 단계

**제외**
- 육아휴직급여, 6+6제도, 자녀세액공제, 국민연금 출산크레딧, 난임지원 — 아이 기준 Todo가 아니라 부모의 노동/세제 문제. "지원제도" 탭 하단 참고 링크로만.
- 낮잠 전환 시점, 통잠 시작, 목욕물 온도 수치, 카시트 전환 개월수, 완구 mm 기준 — 공식 단일 기준이 없어 Todo화하면 오히려 부정확한 확정 정보를 주는 셈. 원칙 중심 참고정보로만 제공.

### ③ 한눈육아의 핵심 데이터 구조

```
생년월일 + 성별 + 거주지역 (프로필)
  ↓
오늘 날짜 기준 현재 월령 계산 (ageInMonths)
  ↓
Todo Master(섹션 4, 총 73개)를 순회하며
  - 지역조건 만족? (없음 이거나 프로필 지역과 일치)
  - 성별조건 만족? (없음 이거나 프로필 성별과 일치)
  → 조건 불충족이면 이 아이의 목록에서 완전히 제외
  ↓
남은 Todo마다 startDate/endDate 계산 (시작월령/종료월령 → 생년월일 기준 실제 날짜)
  ↓
완료기록(로컬스토리지/가족코드 동기화) 대조
  ↓
섹션 5의 8개 상태 중 하나로 분류
  (아직시작전 / 곧해야함 / 지금해야함 / 완료 / 기간지남-캐치업가능 / 기간지남-영구불가 / 조건불충족(이미제외) / 검증필요 배지)
  ↓
같은 배열을 세 가지 방식으로만 다르게 렌더링
  - 홈: "지금해야함"+"곧해야함"(60일 이내)+"기간지남" 상태만, 카테고리당 1~2개로 압축
  - 캘린더: 전체를 startDate 기준 월별로 배치
  - 월령별 로드맵: 조건불충족만 빼고 전부, 월령 순서로 정적 나열(상태 무관)
```

기존 `js/schedule.js`가 이미 "프로필→통합 일정 배열"을 만드는 정확히 같은 패턴이므로, 새 카테고리(FD/OR/SL/SF/LF/CR)를 추가하고 상태 계산 함수를 8개 상태로 일반화하는 확장 작업이 된다 — 구조를 새로 짤 필요는 없다.

**공식 출처가 확인되지 않은 항목(불소치약 시작연령, 배변훈련 시점, 카시트 전환 기준, 목욕물 온도, 완구 mm 기준, 육아휴직급여 상세 금액, 미숙아 의료비 정확 상한액, 보육료/누리과정 정확 단가)은 이번 설계에서 확정 Todo로 넣지 않고 "검증 필요" 상태로만 표시했다.**

## 10. 최종 사실검증 결과

섹션 0~9 작성 이후, DB/UI 설계로 넘어가기 전 **실제 서비스 로직을 바꿀 수 있는 핵심 사실 4가지 + Todo 15~20개 샘플**만 좁게 재검증했다(새 영역 조사 없음, 검색 예산 12회 사용). 위 표에는 이미 결과를 반영했고, 아래는 그 근거와 남은 이슈를 정리한 것이다.

### 즉시 수정 (실제 데이터/스케줄 로직을 바꿔야 하는 오류)

- **`data/health_checkup.json` 구강검진 필드 오류(확정)** — H5·H6·H7의 `hasOralCheck`가 현재 `false`로 되어 있는데, 국민건강보험공단 공식 확인 결과 4차~7차(18~24/30~36/42~48/54~60개월) **전부 `true`가 맞다.** 단순 값 수정이 아니라, "이번 차수에 구강검진도 함께 안내됨"을 4개 차수 모두에서 반복 강조해야 하므로 UI/알림 로직도 같이 손봐야 한다.
- **아동수당 시행일 명시 필요** — "2026년부터"가 아니라 **2026년 4월부터** 연령확대·금액개편이 적용된다. 위 4-9 표(SB-04)에 반영 완료.

### 수정 권장 (표현/분류 수정)

- **아동수당 "지역별 차등"의 실체** — 기본금액 자체가 지역별로 다른 것은 사실이나(수도권10만/비수도권10.5만/인구감소지역11~12만), **지역사랑상품권으로 받을 때만 +1만원 가산**되는 조건이 섞여 있었다. 위 표(SB-04)에서 두 조건을 분리해 명시했다.
- **CR-02(만1세반 전환)를 AGE_WINDOW→CONDITION으로 재분류** — 반 편성은 기관별 재량(신학기 기준 등)이 커서 "만12개월"이라는 절대월령으로 확정하면 실제 어린이집 운영과 어긋날 수 있다. 위 4-10 표에 반영 완료.
- **OR-02 불소치약** — 국내 임상 실무는 최근 "첫니부터 1,000ppm 이상 소량 사용"이라는 국제기준 쪽으로 수렴하는 추세로 보이나, 대한소아치과학회 공식 원문(kapd.org)은 이번에도 접근 실패(404)로 대조하지 못했다. **"검증필요" 배지는 유지**하고, 서비스에는 "정확한 시작 시기는 소아치과 상담 권장"으로 안내하는 쪽을 채택한다.
- **DV-04/DV-06 표현 순화** — "자폐 조기신호/자폐 스크리닝 핵심연령"이라는 문구는 사실관계 자체는 틀리지 않지만, 확정적·자극적인 표현이 부모 불안을 유발할 수 있어([[cardnews-health-todolist-track]] 원칙과 충돌) 위 표에서 "포인팅 여부/퇴행 여부 관찰"로 순화했다. 상담 연결은 DV-09(조건부, 해당 시에만 노출)로 처리한다.

### 확인됨 (문서 내용과 공식자료 일치, 수정 불필요)

- 로타바이러스: 2023.3.6 국가예방접종 전환, 로타릭스 2회/로타텍 3회, 1차 생후14주6일 이내 시작, **최종 접종가능연령 생후 8개월 0일**(장중첩증 위험 증가가 근거), 캐치업 불가 — 전부 정확.
- 아동수당 연령 확대(만9세 미만, 2026.4~), 소득·재산 조건 없음(전국 공통) — 정확.
- 구강검진이 4회 반복된다는 핵심 사실 자체(기존 서비스 데이터가 오류였다는 판단) — 정확.
- FD-01 이유식 시작(4~6개월), SF-01 카시트 의무(도로교통법, 과태료 6만원) — 표본 검증 결과 정확.

### 추가 검증 필요 (공식기준이 불명확하거나 조건에 따라 다름)

- 구강검진의 **세부 월령창**이 신체계측 차수 창(18~24 등)과 완전히 같은지, 2차 자료에 나오는 더 넓은 창(18~29/30~41개월 등)이 맞는지는 NHIS 원문 표를 다시 대조해야 확정된다. 서비스 종료월령을 신체계측 기준과 동일시하면 구강검진을 조기 마감 처리할 위험이 있어 **"확인 필요" 배지 유지.**
- OR-02 불소치약 시작연령/농도 — 위와 동일, KAPD 공식 원문 미대조.
- OR-03(첫 치과방문), CR-04(어린이집 적응기간)는 이번 예산에서 다루지 않음 — 기존 "미검증" 표시 유지.

### Todo의 DATE / AGE_WINDOW / CONDITION / REFERENCE 재분류 점검

표본 검증 결과, 대부분의 AGE_WINDOW 항목(HC/VX/HC 연동 DV/FD)은 공식 출처가 실제 시기를 명확히 뒷받침해 그대로 유지해도 된다. 아래만 재분류/유지 확정한다.

| 분류 | 해당 항목 | 비고 |
|---|---|---|
| **DATE** | VX-ROTA(생후8개월0일 마감), SB-02/SB-03(출생후60일 신청기한) | 공식 근거로 날짜 단위 계산 확정 가능 |
| **AGE_WINDOW** | HC-01~06, VX-01~11, FD-01~12 대부분, OR-01/03/04/05, SL-01, SF-01~08, SB-01/04/05/06/08 | 월령 범위 계산에 공식 근거 있음 |
| **CONDITION** | OR-01(첫니가 나면 양치 시작), SF-02~05(발달 마일스톤 트리거형), CR-02(반편성 시점 확인, 재분류), DV-09(경고신호 발생 시에만) | "절대월령"이 아니라 "무언가 일어나면" 발생 |
| **REFERENCE로 유지/재확인** | SL-02·낮잠·통잠·수면교육, LF-01~04 중 목욕·낯가림·분리불안·신발시기, OR-02(불소치약 시작연령 자체는 REFERENCE, "양치 시작"만 CONDITION), 카시트 전환 개월수, 목욕물 온도, 완구 mm 기준 | 공식 단일 시점이 없어 Todo/캘린더에 자동 생성하지 않음 — 기존 분류가 이미 맞았고 이번 검증에서 뒤집힌 항목 없음 |

### 추가 조사 후보 (이번엔 조사하지 않음, 제목만 기록)

- SB-06 미숙아 의료비 지원 정확 상한액(매체 간 불일치: 1,000만~2,700만원)
- SB-07/08 보육료·누리과정 연령별 정확 단가(복지부 보육사업안내 고시 원문)
