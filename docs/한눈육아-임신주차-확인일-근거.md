# 임신 주차·확인일 입력 — 설계 결정과 근거 (2026-10-05)

사용자 승인(추천대로): (a) 확인일 앵커는 PREG-001·007 두 항목으로 시작 (b) 예정일과 주차가 충돌하면 마지막에 입력한 방식이 우선, 예정일로 되돌리기 가능 (c) 서버 공유는 후속(규칙 변경 없음, 기기 로컬 저장만).

## 동작
- 입력 방식 3가지: **예정일로 입력**(기존) / **지금 몇 주예요**(주+일, 4~42주) / **임신 확인일로 입력**(확인일 + 그날의 임신 주수).
- 출산 예정일(`profile.birthDate`)은 계속 **파생 값**이다. 예정일 = 기준일 + (280 − 임신일수). 기준일은 주수 방식=오늘, 확인일 방식=확인일. 그래서 `pregnancyInfo`(주·일 표시)·단계 판정·일정 엔진·W5 배너는 전부 그대로 예정일로 동작한다. 주수는 날짜가 지나면 저절로 늘어난다.
- 입력 방식은 `localStorage.hannun_preg_basis`(가족코드별)에만 저장한다. 서버(가족 프로필·가구 children 문서)로는 보내지 않는다 → Firestore 규칙 변경 없음. 다른 기기에는 예정일만 전달된다(후속 과제).
- 예정일로 입력하면 저장된 입력 방식을 지운다(마지막 입력 우선). 수정 시트에서 언제든 '예정일로 입력'으로 되돌릴 수 있다.
- 확인일 방식일 때만 일정 엔진이 `data/policy/pregnancy-timing.json`의 `startFrom: "confirmDate"` 항목(PREG-001·PREG-007)의 시작을 그 날짜로 쓴다. 없으면 기존 가정값(예정일 −252일 ≈ 임신 6주)을 그대로 쓴다. 끝(PREG-001의 −196일 = 임신 12주)은 예정일 기준 그대로.

## 근거 검증 (5분 상한 규칙 — 확인한 범위만 적는다)
- 앱 데이터(`data/subsidies/national.json`)의 두 항목은 신청 시작을 **'임신 확인 후'**(startText)로 적고 있다. PREG-001: 등록·수첩 발급 "임신 확인 후 ~ 분만 전까지", 엽산제 "임신 확인 후 ~ 임신 12주 이내(보건소별 상이)". PREG-007: "임신 확인 후" 신청, 선정 후 최대 12개월. 출처(앱 데이터에 기록된 것): 찾기쉬운 생활법령정보 + 중구보건소(PREG-001), 정부24 + 원주시보건소(PREG-007).
- 따라서 '확인일부터'로 시작을 잡는 것은 데이터 문구와 맞다. 다만 **확인일 자체의 정의(병원 진단일 vs 보건소 확인)와 보건소별 세부 시기는 이번에 다시 확인하지 못했다 → 추가검증 필요.** 화면은 지금처럼 '권장 시기' 표시이고 확정 기한으로 말하지 않는다.
- 임신 주수 계산(280일 = 40주, 4~42주 입력 범위)은 앱의 기존 `pregnancyInfo`(출산 예정일에서 280일 역산, 0~42주)와 같은 규칙이다. 확인일 입력 시 계산된 예정일이 오늘 기준 −14일(42주)~+280일을 벗어나면 입력을 거부한다.

## 한계·후속
- 옛 첫 화면 폼(계정 기능 OFF 경로)의 임신 등록에는 입력 방식 선택이 없다(예정일만). 계정 모드(기본 ON)의 아이 등록 시트와 임신 정보 수정 시트에서 쓴다.
- 서버 공유(가구 children 문서에 필드 추가)는 규칙 변경이 필요해 후속.
- 새 CSS 없이 기존 공통 클래스(rv-field·chip·ep-select)만 썼다. 디자인 입히기 때 정리 대상.
