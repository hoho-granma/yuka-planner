# 한눈육아 어디갈까 조사 지침 (초안)

작성: hn-research 초안(2026-10-02), hn-main 저장. 상태: **사용자 확정 대기** — §5 시작 지역·분류, §6 재확인 주기, 민간 시설(키즈카페) 포함 방식을 사용자가 정한 뒤 장소 조사를 시작한다.
기준: [운영규칙](한눈육아-운영규칙.md)(건당 5분, 초과는 "추가검증 필요"), [F0 최종 서비스 설계](한눈육아-F0-최종-서비스-설계.md) §7.

## 1. 장소 선정 기준
- 공식 출처로 이름·주소·이용 조건을 확인할 수 있는 곳만 넣는다. 확인이 안 되면 넣지 않는다.
- 광고·협찬·제휴 글, 블로그·SNS 후기, 앱 평점·순위 기반 선정은 하지 않는다.
- "인기", "많이 가는", "BEST" 같은 표시를 만들지 않는다(실제 이용 통계가 없다). 화면 표기는 "편집 추천"만 쓴다.
- 폐업·장기 휴관이 확인된 곳은 넣지 않는다.
- 아이 안전과 직결되는 사항(연령 제한, 보호자 동반 필요 등)은 공식 안내에 있을 때만 쓴다. 없으면 "미확인".

## 2. 허용 출처와 우선순위
1. 시설 공식 홈페이지, 지자체·공공기관(시·군·구청, 교육청, 문화체육관광부 소속·산하기관, 국립·공립 박물관·도서관·공원 관리 주체)의 공식 안내 페이지
2. 공공데이터(공공데이터포털, 한국관광공사 등 공공기관 제공 데이터). 이용 약관과 저장·재사용 조건을 먼저 확인
3. 지도 서비스는 "존재 확인"용 참고만. 저장·재사용은 약관 확인 후 사용자 결정 전까지 하지 않는다

- 금지: 블로그, 카페, 유튜브·SNS 후기, 광고성 큐레이션 사이트, 순위 사이트
- 시설 공식 SNS는 홈페이지가 없을 때만 보조로 쓰고, 이 경우 "공식 SNS 근거"로 표시한다
- 출처마다 URL과 확인한 날짜를 남긴다

## 3. 장소 1건당 확인 항목과 필드
F0 §7 필드 그대로: id, 이름, 분류, 시·도/시·군·구, 권장 나이(개월 범위), 실내·실외, 비용 구분, 예약 필요, 주소, 공식 링크, 한 줄 설명, 확인 날짜.

| 필드 | 규칙 |
|---|---|
| 분류 | 공원·키즈카페·체험·교육·도서관·박물관·실내 놀이 중 하나 |
| 권장 나이 | 시설 공식 표기(연령·월령)를 그대로 옮기고 개월 범위로 환산. 공식 표기가 없으면 비우고 "미확인" |
| 실내·실외 | 실내/실외/복합. 공식 안내로 판단 불가면 "미확인" |
| 비용 구분 | 무료/유료/일부 유료/미확인 (금액은 공식 표기가 있을 때만 참고로 적음) |
| 예약 필요 | 필요/불필요/일부 필요/미확인 |
| 한 줄 설명 | 공식 설명을 요약. 과장·평가 표현("최고", "인기") 금지 |
| 확인 날짜 | 공식 페이지를 본 날 |

- 미확인 표기: 값을 추측해 채우지 않고 비워 두거나 "미확인"으로 적고, 보고서 끝 "추가검증 필요"에 한 줄로 적는다. 앱에는 미확인 값을 표시하지 않거나 "방문 전 확인"으로 표시한다(표시 방식은 hn-main 설계).
- 한 필드라도 공식 근거 없이 쓴 값이 있으면 그 장소는 "검수 대기"로 둔다.

## 4. 시간 제한과 묶음 크기
- 장소 1곳: 공식 페이지 1곳 확인, 최대 1.5분. 못 채운 필드는 "미확인".
- 조사 요청 1건(5분): 장소 3~4곳. 한 요청에 지역과 분류를 하나씩만 둔다(예: "구로구 도서관 3곳").
- 5분이 지나면 멈추고 확인된 곳만 보고. 나머지는 다음 요청으로 넘긴다.
- 지역 1곳을 채우는 단위: 분류 7개 × 3~4곳. 요청 한 번에 한 분류를 끝내지 못해도 괜찮다.
- 보고 형식: 표 하나(위 12개 필드 + 출처 URL) + 맨 끝 "추가검증 필요: …" 한 줄.

## 5. 시작 지역·분류 고르기 (사용자가 정할 선택지)
지역(하나 이상 선택)
- 가. 테스트 계정 지역(서울 구로구)에서 시작 — 앱 확인이 쉬움
- 나. 사용자가 실제로 가는 지역 한두 곳
- 다. 광역 단위 1곳(예: 서울) 중 인구 많은 구 2~3곳

분류(처음엔 공공 중심 권장)
- A. 도서관·박물관·공원처럼 공식 출처가 확실한 공공 시설만
- B. A + 지자체 운영 체험·교육 시설
- C. B + 민간 키즈카페·실내 놀이(공식 사이트가 있는 곳만)

나이: 처음엔 0~36개월 먼저 / 0~72개월 전체 중 선택

추천(참고, 결정은 사용자): 지역 가 또는 나 1곳 × 분류 A로 시작해 검수 흐름을 확인한 뒤 넓힌다.

## 6. 변동 정보와 재확인 주기
- 운영시간·휴관일·요금은 바뀐다. 앱에는 "방문 전 공식 링크에서 운영 여부를 확인하세요" 안내를 둔다.
- 재확인 주기(제안, 사용자 결정): 공공 시설 6개월, 민간 시설 3개월. 기한이 지난 항목은 "확인 오래됨" 표시.
- 재확인 중 폐업·이전·장기 휴관이 확인되면 즉시 목록에서 뺀다(삭제 전 사용자 검수).
- 공식 링크가 404/만료이면 대체 공식 링크를 찾고, 못 찾으면 "링크 확인 필요"로 표시한다.
- 재확인은 같은 5분 규칙(장소당 1.5분, 요청당 3~4곳)으로 진행한다.

## 7. 사용자 검수 절차
1. 조사 요청 1건 결과를 표로 받는다(필드 + 출처 URL + 확인 날짜).
2. hn-main이 필드 누락·"인기/최고" 표현·출처 허용 여부를 먼저 점검한다.
3. 사용자가 장소 단위로 OK/보류/제외를 정한다(광고성 느낌, 아이에게 맞지 않음 등).
4. OK만 앱 데이터 파일에 반영하고 화면에는 "편집 추천"으로 표기한다.
5. 반영 후 재확인 기한을 장소별로 기록한다.
6. 사용자가 제외한 곳은 이유를 한 줄 남겨 같은 곳을 다시 제안하지 않는다.

## 8. 하지 않는 것
- 지침 확정 전 장소 조사, 순위·후기 기반 선정, 가짜 인기 표시, 근거 없는 값 채우기, 지도 서비스 데이터 임의 저장.
- 조사 결과의 앱 반영(데이터 파일 작성)은 hn-main/hn-dev가 사용자 검수 후 수행한다.

## 추가검증 필요
공공데이터 이용약관·API 저장 조건, 지도 서비스 약관(저장·재사용), 키즈카페 안전·위생 인증 기준 공식 근거.
