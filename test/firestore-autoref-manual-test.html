C2 autoRef 규칙 — Firestore 수동 서버 검증

⚠️ 이 페이지는 운영 Firestore(프로젝트 yuka-planner)에 일회용 가구 아래 일정 문서를 실제로 만들고 씁니다.
· 실제 가구 코드·가구 ID 를 쓰지 않습니다(페이지가 zz-autoref-… 형태의 무작위 일회용 가구 ID 를 새로 만듭니다).
· 이미 있는 문서에는 쓰지 않습니다(생성 전 get() 으로 확인하고, 있으면 중단).
· 보안 규칙상 문서 삭제는 불가(delete: false)하므로, 끝난 뒤 Firebase 콘솔에서 사용자가 직접 삭제해야 합니다.
· autoLink 플래그(hannun_feature_autolink)를 켜기 전에, 새 규칙(firestore.rules 의 autoRef 블록)을 배포한 뒤 이 페이지를 한 번 실행해 전부 PASS 인지 확인하세요.
· 페이지를 연다고 자동 실행되지 않습니다. 아래 확인란에 체크하고 [실행]을 눌러야 시작합니다.

실행 방법

1. 규칙 배포(firebase deploy --only firestore:rules 등 평소 방식)를 먼저 합니다.
2. 터미널에서 프로젝트 폴더(한눈육아/)로 이동해 python3 -m http.server 8765 를 실행합니다.
3. 브라우저로 http://127.0.0.1:8765/test/firestore-autoref-manual-test.html 을 엽니다(file:// 로 열면 스크립트 로드가 막힐 수 있어 로컬 서버로 여세요).
4. 확인란에 체크 → [실행]. 끝나면 표·요약·복사용 JSON 이 나옵니다. JSON 을 그대로 복사해 전달해 주세요.
5. 맨 아래에 표시되는 households/<일회용 ID>/schedules 아래 문서들을 Firebase 콘솔 → Firestore Database 에서 삭제합니다 (문서 삭제는 콘솔에서만 가능합니다. 부모 가구 문서는 만들어지지 않아 목록에 기울임체로 보일 수 있습니다). 다시 실행하려면 새로고침하세요(새 ID 가 만들어집니다).

시작

검증 대상

문서는 ../js/user-schedule.js 의 실제 buildCreateDoc() 로 만들고(재구현 없음), 거부 시나리오는 그 문서에서 autoRef 관련 필드만 바꿔 SDK 로 직접 씁니다. 거부 시나리오마다 같은 문서에서 autoRef 만 뺀 대조군이 먼저 허용돼야 합니다(그래야 거부 이유가 autoRef 규칙임이 확인됩니다). 기대: 허용 = 쓰기 성공, 거부 = permission-denied. 규칙 항목: 형식 ^[A-Za-z0-9-]+__[A-Za-z0-9-]+$ · 80자 이하 · scope=CHILD · childKeys 정확히 1개 · 반복 일정 아님 · 생성 후 불변.
