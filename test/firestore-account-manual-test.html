D2 계정 규칙 — Firestore·Auth 수동 서버 검증

⚠️ 이 페이지는 운영 Firebase(프로젝트 yuka-planner)에 일회용 계정 2개와 일회용 문서를 실제로 만듭니다.
· 사전 조건: ① Firebase 콘솔 Authentication 에서 이메일/비밀번호 사용 설정 ② 새 규칙(firestore.rules 의 [D2] accounts 블록·members uid)을 배포한 뒤 실행합니다.
· 일회용 값만 씁니다: 이메일 zz-hannun-test-…@example.com 2개(실행이 끝나면 페이지가 두 계정을 지웁니다), 문서는 accounts/<테스트 uid> 와 households/zz-acct-…/members/*. 실제 가구·가족 코드는 쓰지 않습니다.
· 보안 규칙상 문서 삭제는 불가(delete: false)하므로 끝난 뒤 아래에 표시되는 문서를 Firebase 콘솔에서 직접 삭제해야 합니다.
· 페이지를 연다고 자동 실행되지 않습니다. 아래 확인란에 체크하고 [실행]을 눌러야 시작합니다. 전부 PASS 여야 hannun_feature_accounts 플래그를 켤 수 있습니다.

실행 방법

1. 규칙 배포(firebase deploy --only firestore:rules) → 2. 프로젝트 폴더에서 python3 -m http.server 8765 → 3. http://127.0.0.1:8765/test/firestore-account-manual-test.html (localhost 는 Auth 승인된 도메인에 기본 포함) → 4. 체크 → [실행] → 5. 결과 JSON 복사 전달 → 6. 콘솔에서 표시된 문서 삭제.

시작

검증 대상

기대: 허용 = 쓰기 성공, 거부 = permission-denied. 항목: accounts 는 본인 uid 만 읽기·쓰기(목록·삭제 금지, 키·역할 제한, v·createdAt 불변) / members 의 uid 는 본인만 새로 달 수 있고 이미 달린 uid 는 가로채기·위조 불가 / 비인증 기존 쓰기(uid 없는 구성원 생성·수정)는 그대로 허용 / role CHILD 허용.
