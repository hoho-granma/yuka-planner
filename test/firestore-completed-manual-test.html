C1-a 완료 상태 필드 단위 갱신 — Firestore 수동 서버 검증

⚠️ 이 페이지는 운영 Firestore(프로젝트 yuka-planner)에 일회용 문서를 실제로 만들고 씁니다.
· 실제 가족 코드를 입력하거나 사용하지 않습니다(페이지가 무작위 일회용 ID를 새로 만듭니다).
· 이미 존재하는 문서에는 쓰지 않습니다(생성 전 get()으로 확인하고, 있으면 중단).
· 보안 규칙상 문서 삭제는 불가(delete: false)하므로, 끝난 뒤 Firebase 콘솔에서 사용자가 직접 삭제해야 합니다.
· 페이지를 연다고 자동 실행되지 않습니다. 아래 확인란에 체크하고 [실행]을 눌러야 시작합니다.

실행 방법

1. 터미널에서 프로젝트 폴더(한눈육아/)로 이동해 python3 -m http.server 8765 를 실행합니다.
2. 브라우저로 http://127.0.0.1:8765/test/firestore-completed-manual-test.html 을 엽니다. (file:// 로 열면 sync.js 를 불러오는 fetch 가 막혀 두 번째 기기(B) 시나리오가 실행되지 않습니다 — 반드시 로컬 서버로 여세요.)
3. 확인란에 체크 → [실행]. 끝나면 표·요약·복사용 JSON 이 나옵니다. JSON 을 그대로 복사해 전달해 주세요.
4. 맨 아래에 표시되는 families/<일회용 ID> 문서를 Firebase 콘솔 → Firestore Database → families → 해당 문서 → 삭제(⋮ → 문서 삭제)로 지웁니다. (이 문서에는 하위 컬렉션이 없습니다.) 다시 실행하려면 새로고침하세요(새 ID 가 만들어집니다).

시작

대상 코드

../js/sync.js 의 실제 함수 FamilySync.updateCompletedEntries / setCompletedEntry / removeCompletedEntry / updateCompleted 를 그대로 호출합니다(재구현 없음). 기기 A = 이 페이지가 불러온 sync.js(기본 Firebase 앱), 기기 B = 같은 sync.js 소스를 별도 Firebase 앱("device-B", 독립 Firestore 인스턴스)에 묶어 다시 실행한 사본입니다. 문서 생성(시나리오 a)과 검증용 재조회는 SDK 를 직접 씁니다(테스트 장치이며 검증 대상 코드가 아님).
